# 工作流执行界面使用指南

## 1. 安装与入口

安装 `@levin/bpm-runtime-ui`，从包根入口导入 `WorkflowRuntimeWorkbench`、
`WorkflowTaskPanel` 或 `WorkflowRuntimeService`。运行时依赖 Vue 3、Ant Design Vue 及
`@levin/admin-framework`，版本要求以包的 `peerDependencies` 为准。

```vue
<WorkflowRuntimeWorkbench
  :load-copied="loadCopiedTasks"
  @completed="refreshBusinessDetail"
  @error="showWorkflowError"
/>
```

## 2. 前置条件与服务端契约

宿主必须配置工作流运行时后端，并以当前认证会话调用待办、已办、我发起、完成任务和二次验证
挑战接口。待办列表、可执行动作、必填字段和验证类型均以服务端响应为准；前端不得传递或相信
可伪造的用户 ID、候选资格、角色、组织或动作许可。

当节点要求二次验证时，先请求服务端挑战，再将用户完成的验证结果随同完成动作提交。验证码、
MFA 秘钥和表单敏感原文不得写入持久化存储、浏览器日志或分析事件。验证码仅在当前表单短暂持有，切换任务、动作、意见或动作参数后清除。流程图只能展示服务端节点状态，
不渲染服务端下发的任意 HTML 或 SVG。

## 3. 结果与错误语义

完成操作成功后触发 `completed`，宿主应刷新业务详情和待办。鉴权、候选资格、动作、必填字段或
二次验证失败时触发 `error`；宿主应展示服务端通用错误，并且不应把失败请求自动换用户、换动作
或重放。可选的 `loadCopied` 仅用于已由服务端单独授权的抄送数据。

## 4. 最小验证

1. 以候选用户登录，确认仅显示其服务端授权待办。
2. 以非候选用户尝试完成同一任务，确认服务端拒绝且任务未推进。
3. 缺少节点必填字段或提交失效/跨任务验证码时，确认服务端拒绝且没有业务副作用。
4. 完成允许动作后，确认待办刷新、时间线状态更新且未泄露验证码或表单敏感值。

扩展、测试、升级和兼容性要求见[模块开发规范](MODULE-DEVELOPMENT-STANDARD.md)。

## 5. 业务页面接入

```vue
<script setup lang="ts">
import { WorkflowBusinessPanel } from '@levin/bpm-runtime-ui';

defineProps<{ businessId: string }>();
</script>

<template>
  <WorkflowBusinessPanel
    :business-reference="{ businessType: 'your-business-type', businessId }"
    @started="refreshBusinessDetail"
    @error="showWorkflowError"
  />
</template>
```

`businessType` 必须是业务模块已注册的稳定类型；`businessId` 是当前对象主键。引用可包含宿主从已授权选项中明确选择的 `tenantId`、`orgId`，经 GET 查询参数或 POST 正文传入，不写自定义 Header。它们只是候选作用域，服务端必须校验对象实际归属和当前用户范围。普通发起不传入用户身份、办理轮次或定义版本；独立换轮和重提携带只读接口返回的预期轮次用于并发核验。资格列表展示各用途的 `eligible` 及 `reasons`，加载失败时禁用发起，不把查询当成自动启动。`started` 只在服务端明确返回创建结果且仍处于同一引用作用域时触发；暴露的 `refresh()` 可以在业务内容变化后刷新资格与历史。

默认服务基路径为 `/com.levin.oak.base/V1/api`，对应 `BizWorkflowRuntimeController`，实际方法路径如下：

| 服务方法 | HTTP 与相对路径 | 参数 |
| --- | --- | --- |
| `todo()` / `done()` / `started()` | GET `workflow-runtime/todo` / `done` / `started` | 当前认证会话 |
| `eligibility(reference)` | GET `workflow-runtime/business/eligibility` | `businessType`、`businessId` |
| `history(reference)` | GET `workflow-runtime/business/history` | `businessType`、`businessId` |
| `start(command)` | POST `workflow-runtime/business/start` | 业务引用、`purposeKey`、`idempotencyKey` |
| `roundState(reference)` | GET `workflow-runtime/business/roundState` | 业务引用、显式 `contractVersion` |
| `newRound(command)` | POST `workflow-runtime/business/newRound` | 业务引用、`contractVersion`、`expectedRevision`、`expectedRoundId`、`idempotencyKey` |
| `resubmit(command)` | POST `workflow-runtime/business/resubmit` | 新轮次命令的全部字段，加 `purposeKey` 与 `sourceRunId` |
| `complete(command)` | POST `workflow-runtime/complete` | 任务、动作、表单、意见、动作参数、二次验证 |
| `retry(command)` | POST `workflow-runtime/business/retry` | `businessType`、`businessId`、`dispatchId` |
| `prepareStepUpAuth(command)` | POST `workflow-runtime/step-up-auth/prepare` | 与实际动作相同的表单、意见及动作参数，加验证类型 |

一次发起网络失败后再次点击会复用同一幂等键；明确成功后才释放此键。最终幂等、条件重验和活动实例互斥由服务端保证。当前组件生命周期结束后不保留请求键，后端仍须阻止已有活动实例重复创建。

## 6. 授权详情和动作表单

工作台 `detailComponents` 属性为本地组件注册表，例如 `{ 'contract.detail': ContractDetail }`。任务 DTO 返回 `detailComponentKey`、业务引用及允许展示的 `businessFields`；组件只通过注册表解析键，不加载任意 URL、HTML、脚本或动态组件源码。宿主详情收到 `businessReference` 和 `readonly: true`，仍必须通过自己的后端接口执行对象和字段授权。未注册对应组件时保留授权摘要并明确提示，不能把空插槽当成详情功能。

任务表单 `formItems` 显式声明 `key`、`label`、`type`、`required`、`readOnly`、`value` 及 `options`。支持文本、多行、数字、布尔、日期和枚举选择；必填校验保留合法的零与 false，只提交当前节点公开的可写字段。专用 `form` 插槽获得 `task`、`formData`、`readOnly`，插槽写入也不能扩大允许提交的字段范围。

动作 `actions` 必须由服务端按当前权限返回；本地不构造默认动作。`requiresComment` 控制意见必填。退回使用 `returnTargets`；转办、委派、加签使用 `candidateUsers`；加签同时使用 `addSignPositions`。这些选项采用 `{ label, value }`，加签顺序为 `before` 或 `after`。缺失能力的动作不显示为可执行按钮。`resolve` 表示受托人归还，是否可见由服务端明确授权。

## 7. 设计与实现边界

业务对象只提供身份与授权数据，不要求固定状态字段或 FSM。业务面板管理当前对象的资格、手动命令与历史；任务面板处理节点输入；工作台负责加载任务、调用命令与刷新；所有网络调用集中于可替换的 `WorkflowRuntimeService`。业务类型、主键、租户、组织任一变化立即清空旧历史与资格；旧查询、发起和重试响应不能更新、触发事件或刷新新的作用域。幂等键同时隔离业务引用和租户组织，提交中阻止重复点击，失败保留当前作用域的请求键。宿主详情接收包含可选租户、组织的完整引用。

运行记录分别展示 `executionStatus`、`outcome`、`effectStatus`。例如 `PendingEffects / Approved / Failed` 显示“等待业务处理 / 通过 / 处理失败”，不把引擎结束或单节点通过当成业务写入完成，也不在浏览器解锁下一阶段。

`lastError` 展示服务端已脱敏的交付失败原因。业务面板与工作台仅在宿主明确传入 `canRetry=true`，并且该记录携带服务端按对象授权返回的 `pendingDispatchId` 时显示“重试业务处理”。宿主必须根据实际 `retry` API 方法及 `workflow.runtime.retry` 权限计算该属性，不得统一设为 true。重试只恢复原交付，成功触发 `retried(instanceId)` 并刷新列表，失败保留原记录；服务端仍重新校验权限与对象范围。

响应中的 `businessContractVersion` 标识历史运行记录绑定的业务契约版本，不能代替宿主声明。需要轮次动作时，宿主必须显式传入 `contractVersion`，并分别以实际 `roundState`、`newRound`、`resubmit` API 权限计算 `canNewRound`、`canResubmit`；缺失契约或权限不会开放对应动作。

“开启新办理轮次”与“重新提交”都会先只读查询当前真实修订与轮次，再展示二次确认。“重新提交”只展示 `roundState.resubmittableRunIds` 许可的同轮已结束、效果已应用的拒绝/撤回/终止来源，命令使用历史记录的 `runId` 作为 `sourceRunId`；不按引擎实例 ID 或历史数组顺序猜测来源。新轮次保留历史且旧前置结果不再适用；服务端返回阻断原因时显示原因并禁止确认。其他用途活动不能被前端一律解释为禁止重提，最终仍由服务端按用途检查。

确认命令后若响应失败，保留原请求的完整参数和幂等键。再次确认，或取消后点击“重试原提交”，都重放原命令，不读取新修订后另建尝试。切换对象、契约或服务立即清空当前确认与忙碌状态；取消准备、切换对象与卸载后的迟到响应不能恢复确认或触发当前对象事件。请求键仅在组件生命周期内保存，页面刷新后须先查看当前办理结果再决定后续操作。新轮次成功触发 `roundChanged(roundId)`；重提成功触发 `started(instance)`，宿主应刷新业务结果。`startMode=event` 的用途显示“由事件触发”，普通发起入口禁用，失败后可使用独立重提操作。

最小验证还应覆盖：无独立权限不可执行；换轮有活动/待交付时展示阻断原因；重提请求携带实际 `runId` 与当前修订；响应丢失重试两次载荷完全一致；取消或切换业务对象后旧请求不能打开确认或刷新新对象。组件不提供任意业务字段赋值和越权人员选择能力。

## 8. 开发与回归检查

`WorkflowProcessDiagram` 读取任务响应的 `processDiagramNodes` 和 `processDiagramEdges`。节点包含 `id/name/status` 与可选 `type`，连线包含 `id/source/target`；它们必须来自该实例固定定义版本。节点数组不必按拓扑排序，组件依据真实边分层展示分支及汇聚，跨层连线从节点区域外侧经过。未提供边时仅展示节点并提示不表示执行顺序，不添加串行箭头；缺失端点的连线不会绘制，并提示图示不完整。节点状态区分进行中、已完成、待执行、已取消、已跳过，使用中文与主题语义色。多分支图保持可读尺寸并允许横向滚动。

任务响应 `timeline` 用于展示已授权的真实记录，`timelineTruncated=true` 时提示仅展示最近1000条；不会删除原始历史或把截断内容宣称完整历史。待办、已办、抄送列表以业务标题区分同名节点，同时显示节点和实例标识，支持鼠标、Enter与空格打开详情。

宿主注入的服务与详情组件必须保持上述请求和授权边界。新增动作需先补服务端 DTO、执行语义和候选参数，再扩展动作表单及测试；未知动作只提示尚不支持。新增表单控件需要保持原值类型、字段过滤、空值语义以及二次验证失效规则。

回归至少覆盖：无动作不显示默认通过、零与 false 必填、只读/残留字段排除、非法目标不能提交、失败重试复用幂等键、对象切换丢弃旧响应、前置未满足不可发起、等待业务处理不伪装成功。组件单测和包构建不能替代宿主浏览器与真实后端端到端验收。
