# 工作流设计器使用指南

## 第五版任务流程：从开始到结束设计

入口为“流程设计”列表→新建流程，先选择当前账号可访问的业务对象、状态字段和状态映射，再进入大弹窗。新流程默认显示“开始→结束”。已有绑定定义可点“新建任务流程版本”，明确创建空白任务图草稿；原版本不转换、不修改。公共宿主使用 `createTaskGraph` 与 `WorkflowDefinitionWorkbench`，所有保存、模拟、发布继续调用同一连接器，定义的 `schemaVersion` 为5。

### 最短操作步骤

1. 点击节点旁“＋”或选中路线，选择“添加下一步”。人工办理用于审批/填写，自动处理用于显式更新业务状态；按条件分路、同时办理自动生成完整结构。
2. 点击人工办理节点，设置名称、人员或角色、审批方式和字段。“会签”是本任务所有人办理通过，“或签”任一人通过，“顺签”按人员顺序逐人办理。角色仅解析候选人，不授予业务访问权。
3. 每个操作分别设置可填写字段与必填字段，例如通过选填意见、驳回必须补充说明。操作字段只能缩小节点允许编辑的范围。普通表单不得填写绑定状态字段。
4. “按条件分路”自动生成两个出口。点击路线填写中文名称和结构化条件，一条路线标为“其他情况”；条件按明确顺序选择，默认出口只在其它路线都不满足时使用。
5. “同时办理”生成拆分、两条办理分支和“全部完成后继续”。点“增加一路”自动连接新增分支与同一汇合点；分支内仍可插入任务。选中拆分或汇合会高亮整组。会签属于分支内某个任务，不能代替多个独立分支。
6. 从节点的连接点拖到另一个节点，松开创建流转路线并打开路线配置；放到空白处、按Esc或取消不创建。服务端仍拒绝不合法的跨并行连接、遗漏汇合或不完整条件。
7. 点击“更新业务状态”步骤，从已知映射中选择目标值。其它任务不隐含改状态。并行分支中禁止更新同一绑定状态，应放在拆分前或汇合后。
8. 保存草稿，配置结构化检查用例的变量、办理节点、办理人、通过/驳回及表单数据，执行检查并查看覆盖结果，成功后发布。修改后必须重新保存和检查，不能沿用旧模拟证明。

保存草稿允许尚未配置完的节点；执行检查及发布必须通过完整校验。操作失败时保留当前输入并显示原因，不自动关闭窗口。实际办理的“保存”只保存许可数据并保留任务；“通过/驳回”提交对应操作表单并推进本任务。审批进度和并行汇合等待情况来自服务端实际任务，不由前端推算。

### 退回修改与启动条件

选择人工办理的“退回修改”操作，再从“允许退回到”选择必经的前置办理步骤。当前受控退回要求源与目标都是单人办理，之间没有并行区域；没有合法目标时会说明限制。退回保留原路线供重新办理，不画一条可任意跨并行的循环边，也不隐含变更业务状态；需要改变状态时通过原路线中的显式状态更新步骤执行。会签中的驳回是该任务的拒绝结果，仍由结果分路决定后续，不能混同“退回修改”。

点击开始节点可以配置业务启动条件，仅使用当前账号允许参与判断的业务字段；未配置表示沿用现有发起权限与业务适用校验。启动前由服务端读取当前业务数据判断，前端隐藏入口不能替代该校验。

### 最小验证

建立“开始→更新为审核中→财务/法务同时办理→全部完成→更新为已通过→结束”。财务配置两人会签，检查首人通过后任务未结束、法务完成后仍等待剩余会签、全部完成后才更新业务状态；驳回缺少必填数据必须失败。没有业务对象/字段可选时检查当前账号的真实CRUD权限和字段占用，不通过角色选择器扩大权限。


## 第四版固定状态图：原有版本用法

新版新增流程先填写名称，选择当前账号可访问的业务对象和必选状态字段。对象显示中文名称、完整类名及说明；枚举、字典或固定选项使用既有值和标签，普通字符串、整数须填写状态值与名称。整数与字符串不混用。对象和字段全局只能绑定一个流程定义，同一定义的不同版本共用绑定；创建成功后才进入图形设计。

画布初始只有开始状态，其余状态从已知状态列表添加。点击节点设置单人/全部会签/任一或签/顺签、人员和角色、表单字段、进入/离开通知及抄送；终态还须选择审批结果。点击路线配置触发事件、条件和目标。连接已有节点可以实现多条路线进入同一状态或回退，不需要复制同名节点。开始条件在开始节点；具体进入路线条件在连线上。

保存草稿后，通过结构化模拟用例录入变量、事件/审批步骤及期望状态，检查覆盖报告，通过后发布。流程图、状态映射或元数据变化后须重新模拟。角色是选人规则，最终任务属于解析出的实际人员；配置角色或抄送不会自动授予业务权限。个人会签完成不等于业务状态已改变。

第三版既有固定版本继续使用其原树编辑与执行路径；本指南后续第三版章节不用于描述第四版状态图。动态表定义由独立模块负责，设计器使用同一业务对象元数据接口接入已注册来源，无需工作流全局开通设置。

Oak 宿主从列表“打开设计”或新建绑定后，进入独立接近全屏的设计窗口，版本、候选人员、画布、属性、检查与发布都在窗口内。关闭回到列表，同一流程重开保留当前未保存草稿；切换流程仍沿用宿主的未保存修改保护。自建宿主也应使用一个大 Modal 承载同一工作台实例，关闭时保留挂载状态，不另建第二套编辑模型。

## 第四版新增流程：安装与真实接口入口

新增流程使用公开导出的 `createStateGraph`、`WorkflowDefinitionWorkbench`、`WorkflowDesignerService` 及 `WorkflowBusinessObject` 等类型。`WorkflowGraphDesigner` 是单独的第四版设计组件；通常使用工作台，由工作台连接真实保存、模拟与发布。安装依赖以包 `peerDependencies` 为准，宿主应先配置 `@levin/admin-framework` 请求运行环境和当前登录身份。

以下示例使用本模块现有真实接口。先从 `WorkflowDefinition/businessObjects` 选择有权访问的实体、未占用状态字段，并根据字段选项或手动映射填写表单；`createDraft` 接收该表单结果。绑定以 `createBound` 返回的权威快照为准，不能从字段名猜测状态类型，也不能绕过全局占用校验。

```vue
<script setup lang="ts">
import { onMounted, ref } from 'vue';
import { RequestService } from '@levin/admin-framework';
import {
  createStateGraph,
  WorkflowDefinitionWorkbench,
  WorkflowDesignerService,
} from '@levin/bpm-designer';
import type {
  WorkflowBusinessObject,
  WorkflowCandidate,
  WorkflowDefinitionVersion,
  WorkflowStateBinding,
  WorkflowStateOption,
} from '@levin/bpm-designer';

// 人员、角色及按钮权限来自宿主当前主体的授权目录与真实 API 权限。
const props = defineProps<{
  users: WorkflowCandidate[];
  groups: WorkflowCandidate[];
  permissions: { save: boolean; simulate: boolean; publish: boolean };
}>();
// RequestService 的 get/post 为受保护方法，宿主通过明确服务方法包装真实接口。
class WorkflowBindingApi extends RequestService {
  constructor() {
    super('/com.levin.oak.base/V1/api');
  }

  businessObjects() {
    return this.get<WorkflowBusinessObject[]>(
      'WorkflowDefinition/businessObjects',
    );
  }

  async createBoundDraft(form: {
    name: string;
    businessEntityKey: string;
    stateField: string;
    stateMapping: WorkflowStateOption[];
  }) {
    const bound = await this.post<{
      id: string;
      name: string;
      processKey: string;
      genericBusinessContract: { bindingSnapshot: WorkflowStateBinding };
    }>('WorkflowDefinition/createBound', {
      data: { ...form, processKey: `workflow-${crypto.randomUUID()}` },
    });
    const graph = createStateGraph(
      bound.genericBusinessContract.bindingSnapshot,
      bound.processKey,
      bound.name,
    );
    const id = await this.post<string>('WorkflowDefinitionVersion/create', {
      data: {
        workflowDefinitionId: bound.id,
        versionNo: 1,
        lowflowDefinition: graph,
      },
    });
    return this.get<WorkflowDefinitionVersion>(
      'WorkflowDefinitionVersion/retrieve',
      { params: { id } },
    );
  }
}
const api = new WorkflowBindingApi();
const designerService = new WorkflowDesignerService();
const objects = ref<WorkflowBusinessObject[]>([]);
const version = ref<WorkflowDefinitionVersion>();
const definition = ref<WorkflowDefinitionVersion['lowflowDefinition']>();

onMounted(async () => {
  objects.value = await api.businessObjects();
});

async function createDraft(form: {
  name: string;
  businessEntityKey: string;
  stateField: string;
  stateMapping: WorkflowStateOption[];
}) {
  const saved = await api.createBoundDraft(form);
  if (saved.lowflowDefinition?.schemaVersion !== 4) {
    throw new Error('服务端未返回已保存的第四版状态图');
  }
  version.value = saved;
  definition.value = saved.lowflowDefinition;
}
// 宿主通过组件 ref 调用 createDraft；错误时保留输入并展示服务端原因。
defineExpose({ createDraft });
</script>

<template>
  <WorkflowDefinitionWorkbench
    v-if="version && definition"
    v-model:definition="definition"
    :version="version"
    :options="{
      stateBusinessObjects: objects,
      users: props.users,
      groups: props.groups,
    }"
    :permissions="props.permissions"
    :service="designerService"
    @refreshed="version = $event"
  />
</template>
```

已有第四版直接用 `WorkflowDefinitionVersion/retrieve` 返回的 `lowflowDefinition` 和完整版本进入工作台，不重新执行绑定或创建。修改后的模型仍须通过工作台保存，不能直接发布本地临时图。Oak 宿主的完整页面位于 `@levin/oak-base-admin`，该包的 `docs/workflow-pages.md` 提供接入说明；使用其它后端时通过公开服务连接器适配真实受控接口。

第四版业务字段不会因为名称接近引擎变量而被排除。条件变量别名禁止使用 `workflow*`、`execution`、`task`、`loopCounter`、`nrOfInstances`、`nrOfActiveInstances`、`nrOfCompletedInstances`、`authenticatedUserId` 等运行时保留名；设计器为这些字段分配稳定的 `business_*` 别名，处理与其它字段的碰撞，真实数据来源仍是 `business.原字段`。正常已保存别名保持，草稿编辑时会同步不安全旧别名的条件引用和模拟变量键。

第四版最小验证：创建绑定 → 添加已知状态和事件 → 连接审批、完成及取消路线 → 保存 → 录入模拟用例并检查 → 发布 → 从真实业务记录发起办理。人工模拟步骤没有表单数据时可以省略 `nodeId`，由服务端按实际活动状态办理；需要填写表单时选择该步办理节点并填写许可字段，服务端再次校验节点、类型和必填。已发布设计仍可点击状态和路线查看人员、表单、通知等只读配置；人员名称仅从当前授权目录回显，目录未知的 ID 保留原值，不虚构姓名。运行图默认不开放设计选择或编辑。

## 第三版既有定义：安装与入口

从 `@levin/bpm-designer` 根入口导入 `WorkflowDesigner`、`WorkflowDefinitionWorkbench`、`WorkflowDesignerService` 和 `createTreeDefinition`。运行时依赖 Vue 3、Ant Design Vue 与 `@levin/admin-framework`，以包 `peerDependencies` 为准。

```vue
<WorkflowDefinitionWorkbench
  v-model:definition="definition"
  :options="{ users, groups, businessTypes, purposeOptions }"
  :version="version"
  :permissions="{ save: canSave, simulate: canSimulate, publish: canPublish }"
  :service="designerService"
  @refreshed="onVersionRefreshed"
/>
```

本段只维护已有第三版流程定义的草稿版本，再把服务端版本对象传入；新增绑定流程应使用前面的第四版入口。第三版既有定义的兼容宿主使用 `createTreeDefinition(processKey, name)`，其 `schemaVersion=3` 且只含 `flowTree`，不提交根级 `nodes/edges`。已有配置来自 `version.lowflowDefinition`；v2 响应会明确拒绝，迁移必须在受控独立流程完成。`onVersionRefreshed` 必须更新完整 `version`，特别是 `optimisticLock`、生命周期和模拟报告；不要只更新状态。

## 第三版既有定义：宿主契约

`options.users/groups` 是当前主体已授权的候选，形状为 `{id,label,value?,kind?}`，存储值取 `value ?? id`。候选组值必须沿用服务端身份桥接的实际格式，不能根据标签猜测角色或组织键。

`options.businessTypes` 来自 `workflow-runtime/business-types`，每项为 `{businessType,contractVersion,title,fields,actions,validators,eventTypes,approverResolvers}`；后四类能力按公开标识组织为映射，`approverResolvers` 可为空。字段至少包含 `title/type`，并声明 `display/condition/editable/sensitivity`。结果动作、只读校验器和动态审批人解析器须由能力目录明确标记 `simulation: true` 才能选择、模拟及发布。没有传入目录时工作台自行请求；切换目录来源会立即清除旧候选，失败保留草稿并提供重试，模拟和发布被阻止。稳定流程定义创建页按 `businessType` 去重，全新草稿或明确选择另一个业务对象时，默认采用该对象目录中的最新 `contractVersion`（按版本标识的数字段自然顺序比较）。已保存设计保留原绑定，不随目录刷新或新版本出现而升级；需要切换时明确选择。

`permissions` 由宿主实际 API 方法权限派生，显式 `false` 隐藏对应操作并阻止调用；设计权限不等于对象数据权限。服务端始终重新鉴权。`purposeOptions` 可传可见业务用途提示。

## 第三版既有定义：可选业务对象与加载提示

可选业务对象由宿主提供的工作流业务目录决定。目录成功加载但没有可用对象时，页面提示检查业务目录及当前账号访问权限；未选中有效业务方案前，条件字段区不显示。宿主须区分加载中、请求失败和成功空目录，失败时提供重试，不应将网络错误或已发布版本列表加载失败解释为没有业务对象。

## 第三版既有定义：配置一个流程

1. 填写流程名称并选择业务对象。Oak 宿主生成稳定流程标识及内部用途；复用组件的宿主也必须准备这些标识。业务设计者无需录入技术标识。
2. 在“选择业务对象”选择中文业务名称。同一对象有多套受控方案时，新建默认最新方案，仍可明确改选其它可用方案；历史设计不静默换版。记录编号、名称及可选申请人、摘要仅依据能力目录的 `defaultBinding` 预填；缺少明确语义角色时提示管理员补齐，不按字段名猜测。字段对应关系与技术标识留在按需展开的实施者设置中。
3. 选中业务对象后，在“审批条件使用哪些业务字段？”中选择中文字段名称。例如“申请金额大于 1 万元时由部门负责人审批”，先添加“申请金额”，再到“发起规则”或审批分支配置金额条件。不按业务数据分流可跳过。可选择发起时的值或进入步骤时的值；秘密字段不进入候选，同一字段不重复登记。
4. 在“启动与依赖”选择手动或事件自动模式。自动模式需选择受控事件和受限执行主体；执行账户必须为 `User.type='workflow-service'` 的非管理员账户并有明确受限数据范围，发布者需 `workflow.runtime.delegate` 权限。不会隐式选用当前登录账户。普通字段变化没有事件接入时不会自动触发。
5. 用中文条件编辑器选择“同时满足”“满足任一”“不成立”、类型比较及前置流程结果。前置用途默认固定同对象当前轮次、最新有效且业务结果已应用的实例；被拒绝而结束的实例不满足“通过”。
6. 在“节点与流转”先选择画布或树内连线列表中的目标边，再插入审批节点或条件/并行网关；原边的 ID、排他条件与默认标记保留。网关原子建立两个出口与汇聚。排他第二出口可先留空作为草稿，需配置条件后才能模拟。节点属性及排他边条件按稳定 ID 写回树。
7. “新增不同结果出口”要求先选中通向唯一入边结束节点的连线：树会原子生成排他双终局，原结束点留在默认支，新建“拒绝结束”支；非默认出口条件仍需设计者配置，未配齐不得模拟。普通单入单出审批任务可删除，原入边身份保留并接回后继。自由连线、任意游离结束、网关或结束节点删除仍未开放；不符合安全拓扑的操作会给出明确原因，不允许手改 JSON 绕过门禁。审批节点默认一入一出，多路汇聚用网关表达。

画布使用已适配的 lowflow-design `FlowDesign`，节点和连线属性栏位于同一画布的宿主属性插槽；画布容器空间不足时属性栏排到下方，长图在画布列内滚动。草稿由受限树投影显示，业务属性始终写回原树；`toLowflowCanvasTree` 和 `fromLowflowCanvasTree` 仅供显式 v2 迁移/转换工具使用，不应作为 v3 页面回写入口。草稿允许部分配置未完成，但能力目录未加载、目录中不存在或未声明隔离模拟的结果动作、校验器和动态审批人等配置不能通过模拟或发布门禁。BPMN 转换及最终发布仍由后端从冻结 v3 树投影完成。

已发布版本画布使用上游只读模式，节点清单仍允许选择节点查看不可编辑的属性；清单选择不更改树或提交请求。8. 设置固定候选人员，或在“动态审批人”中选择当前业务契约公开且已授权的解析器，再配置其声明式参数；节点只保存 `approverResolver: {key,parameters}`，不能输入任意表达式。可将固定用户与动态结果合并。单人、ALL 会签、ANY 或签均在进入节点时按完整有效人员集合分配；静态会签/或签须至少两名明确用户且不混用候选组，动态会签/或签解析后也至少需要两名实际有权用户。默认禁止申请人自审，允许时需显式开启；例如 `workflow-request@2` 提供申请人解析器，而旧 `@1` 不会自动获得该能力。9. 选择允许动作。退回须配置前置目标；转办、委派、加签可配置目标用户或角色/组织资格。加签前后顺序由执行动作填写。空候选按实际有效成员判断，默认阻断；选择“升级到指定人员或组”后，可分别从授权目录选择升级处理人、升级候选角色/组织，至少填写其中一项。仅在主候选不可用时启用升级，不能降低 ALL 会签要求；发布后的只读面板保留已配置的组标识与中文名称。10. 选择可读字段、表单保存业务操作 `formAction`、可编辑和必填字段及二次验证。二次验证显示图片验证码、人机交互验证、短信验证码、邮箱验证码、多因子验证码；定义 JSON 仍保存对应的 `Captcha`、`Hmi`、`Sms`、`Email`、`Mfa` 枚举值。可编辑字段必须同时可读、目录允许编辑、位于业务操作 `writableFields`，并有同名同类型操作参数；必填字段必须可编辑。服务端再与当前业务授权求交集。未选择保存操作时不能配置可编辑业务字段。11. 在“完成后处理”选择通过、拒绝、撤回、终止对应的业务操作及参数。参数选择填写固定值或使用同类型业务字段，也可以不配置任何回写操作。操作失败时后续依赖不会提前解锁。12. 保存草稿，完善检查提示，再点击“执行检查”。主界面分别显示已检查审批步骤、已检查路线及待检查路线数量；缺失覆盖字段显示“未记录”，不会冒充无分支。具体节点键、连线键和纯数据轨迹在“实施者查看原始执行轨迹”按需展开。服务端仍按实际覆盖及冻结定义裁决发布，修改设置后必须重新保存和检查。业务字段和动态审批样例均来自契约冻结的纯数据，不调用真实业务解析器；样例缺失或无法证明全部分支时检查失败。

## 第三版既有定义：设计与发起前的就绪检查

1. 业务对象应已在当前授权目录中公开字段与允许操作。通用只读方案只能记录审批过程和结果，不会自动修改任意业务状态；需要状态回写时，业务模块必须先公开受控结果动作，再在“完成后处理”选择。
2. 选择审批人只设置办理资格，不授予目标记录查看权。应先确认普通审批人在业务对象对应租户、组织及个人数据范围内拥有查看权限，不能用设计权限或消息接收资格替代业务授权。系统不会自动扩权。
3. 条件分支走一条满足条件的路线，同时办理展开全部支路并等待汇聚；设计器按树形结构成组创建分支与汇聚，不支持任意交叉连线。退回仅能指向服务端允许的前置步骤，不能任意跨越并行支路。
4. 保存后完成模拟及发布，再从业务页面或统一发起入口选择符合启动条件的记录。定义可以是全局模板，实例归属仍跟随业务记录；模拟通过不证明普通审批人已具备真实业务访问权限，应使用实际普通角色验证待办和目标数据访问。

## 第三版既有定义：步骤通知与模板

在“审批步骤”选择开始、条件/并行网关、结束或人工审批节点，在“步骤通知”点击“添加步骤通知”。自动步骤可选择进入/完成；人工步骤可选择产生待办/完成办理/提醒/超时。每种时机一条，单步骤最多四条。选择业务申请人、发起人，或待办事件的当前候选人，再多选站内、短信、邮件、企业微信/钉钉/飞书机器人渠道。

标题与正文支持固定变量 `{{process.name}}`、`{{node.name}}`、`{{event.name}}`、`{{action.name}}`、`{{business.id}}`；也可点击变量按钮插入正文。正文使用 Markdown，允许标题、段落、列表、加粗与作者填写的静态 HTTPS 链接；链接目标不能使用模板变量。变量按纯文本显示并保留原字符，不能产生新链接或格式。不允许 HTML、图片、脚本、任意表达式或业务隐藏字段。标题最多 120 字，正文最多 4000 字；渲染后限制由服务端再次检查。

“内容预览”使用示例变量，短信另外展示纯文本示意（链接保留文字及地址），最终投递以服务端转换为准。宿主可通过 `notification-preview` 插槽接收 `{content}` 并使用自身安全 Markdown 阅读器；未提供插槽时组件只展示字面文本。Oak 宿主已接入与个人消息相同的安全阅读器，原始 HTML 被转义且不自动加载图片等远程资源。

接收人的手机、邮箱及机器人目标只能由服务端授权配置解析，设计页面不接收临时号码、邮箱或 Webhook。供应商缺失会导致投递明确失败，不能把模拟通过视为实际发送成功。保存、更改通知后必须重新检查再发布；已发布版本只读。流程模拟只检查通知配置，不发送外部消息。最小验证应包含一条自动通知和一条人工通知、实际站内消息、短信纯文本载荷和失败重试。

## 共用版本接口与失败语义

默认 API 基路径 `/com.levin.oak.base/V1/api`，可由服务构造参数或宿主子类替换。

- `GET WorkflowDefinition/businessObjects`：第四版当前主体可访问的实体、状态字段及完整选项目录。
- `POST WorkflowDefinition/createBound`：第四版新增定义与全局唯一状态绑定，返回含 `genericBusinessContract.bindingSnapshot` 的完整定义。
- `POST WorkflowDefinitionVersion/create` 与 `GET WorkflowDefinitionVersion/retrieve`：创建并读取固定草稿版本。
- `GET workflow-runtime/business-types`：第三版授权能力目录，不用于第四版新增实体选择，不返回真实业务记录。
- `POST WorkflowDefinitionVersion/save-design`：JSON `{id,optimisticLock,lowflowDefinition}`，返回完整版本。
- `POST WorkflowDefinitionVersion/start-simulation`：JSON `{id}`，返回版本及模拟报告。
- `GET WorkflowDefinitionVersion/simulation-runs`：参数 `{versionId,pageIndex,pageSize}`，按固定版本权限分页返回模拟历史摘要（`items/totals`，不含完整轨迹）。
- `GET WorkflowDefinitionVersion/simulation-run`：参数 `{versionId,runId}`，在已授权版本下读取单次覆盖报告与有界虚拟执行轨迹。
- `POST WorkflowDefinitionVersion/delete-simulation-run`：JSON `{versionId,runId}`，按设计权限软删除单次报告；删除当前通过证明后须重新模拟，不能依赖旧通过记录发布。
- `POST WorkflowDefinitionVersion/publish-after-simulation`：JSON `{id}`，服务端复核测试、唯一发布版本及依赖条件。

保存冲突需刷新并核对其他修改，不能覆盖最新乐观锁后盲目重试。接口失败不会关闭工作台或清空配置。Published、Retiring、Retired、Archived 均只读；生命周期只经语义化 API 迁移。

## 第三版既有定义：最小验证与扩展

使用无状态字段对象配置一条审批流程，完成字段映射、保存、模拟、发布和真实待办执行。再验证错误字段/条件拒绝、拒绝结果不解锁下一用途、结果操作失败不放行、低权限目录和对象访问被阻止。组件测试不能替代浏览器与服务端数据库端到端验收。

本模块不提供任意脚本、服务任务、自由跨并行退回或任意数据库属性赋值。新增能力先通过业务目录和服务端支持矩阵，再扩展界面。设计原理见[设计与实现](流程设计器设计与实现.md)，下游使用要求见[模块开发规范](MODULE-DEVELOPMENT-STANDARD.md)。

第三版扩展模拟须使用业务目录中明确公开的纯数据 fixture、声明式校验器和资源边界。模拟报告不替代真实业务适配器写入、权限或外部发送验收；未知或未覆盖能力应由服务端明确拒绝，不能以页面存在配置项推断已经支持。
