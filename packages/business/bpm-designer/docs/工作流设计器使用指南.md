# 工作流设计器使用指南

## 1. 安装与入口

安装 `@levin/bpm-designer`，并从包根入口导入 `WorkflowDesigner` 或
`WorkflowDefinitionWorkbench`。运行时依赖 Vue 3、Ant Design Vue 及
`@levin/admin-framework`，版本要求以包的 `peerDependencies` 为准。

```vue
<WorkflowDefinitionWorkbench
  v-model:definition="definition"
  :options="{ users, groups, fields }"
  :version="version"
  @refreshed="reloadVersion"
/>
```

## 2. 前置条件与配置

宿主必须先从自身已授权的服务端 API 加载 `users`、`groups` 与 `fields`；不得把未过滤的
全租户用户、角色、组织或表单字段直接传给浏览器。`version` 是服务端返回的版本状态，已发布、
下线中、已下线和归档版本必须以只读方式传入。

第一期仅支持顺序的 `start`、`userTask`、`end` 节点。每个用户任务必须具有候选用户或候选组；
空审批人只可采用服务端验证的升级候选人策略。组件可编辑动作、必填字段和二次验证类型，但
是否允许保存、模拟或发布始终由后端定义版本接口决定。

高级表达式、脚本任务、服务任务和任意外部副作用节点不受支持。不得在 JSON 中写入 `${`、`#{`、
Groovy、SpEL 或 JavaScript；服务端转换器会拒绝它们。

## 3. 权限与结果语义

本包不保存 BPMN XML，也不在浏览器中判定发布资格。宿主应将保存、模拟和发布操作委托给服务端；
服务端仅允许模拟通过的 Testing 版本发布，并负责唯一 Published 版本和生命周期约束。收到
服务端拒绝时，保留编辑状态并展示错误，不得尝试绕过模拟或直接调用 Flowable。

## 4. 最小验证

1. 使用低权限账号确认候选数据不包含无权主体和字段。
2. 保存一个 `start → userTask → end` 草稿，确认用户任务无候选人时服务端拒绝。
3. 提交含脚本或表达式的 JSON，确认服务端拒绝且不产生部署。
4. 对模拟通过的版本执行发布，并确认已发布版本不能继续编辑。

扩展、测试、升级和兼容性要求见[模块开发规范](MODULE-DEVELOPMENT-STANDARD.md)。
