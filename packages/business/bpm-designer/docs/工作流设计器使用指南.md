# 工作流设计器使用指南

## 安装与入口

从 `@levin/bpm-designer` 根入口导入 `WorkflowDesigner`、`WorkflowDefinitionWorkbench`、`WorkflowDesignerService` 和 `createTreeDefinition`。运行时依赖 Vue 3、Ant Design Vue 与 `@levin/admin-framework`，以包 `peerDependencies` 为准。

```vue
<WorkflowDefinitionWorkbench
  v-model:definition="definition"
  :options="{ users, groups, businessTypes, purposeOptions }"
  :version="version"
  :permissions="{ save: canSave, simulate: canSimulate, publish: canPublish }"
  :service="designerService"
  @refreshed="onVersionRefreshed"
/>
```

先创建业务流程定义及草稿版本，再把服务端版本对象传入。新配置使用 `createTreeDefinition(processKey, name)`，其 `schemaVersion=3` 且只含 `flowTree`，不提交根级 `nodes/edges`。已有配置来自 `version.lowflowDefinition`；v2 响应会明确拒绝，迁移必须在受控独立流程完成。`onVersionRefreshed` 必须更新完整 `version`，特别是 `optimisticLock`、生命周期和模拟报告；不要只更新状态。

## 宿主契约

`options.users/groups` 是当前主体已授权的候选，形状为 `{id,label,value?,kind?}`，存储值取 `value ?? id`。候选组值必须沿用服务端身份桥接的实际格式，不能根据标签猜测角色或组织键。

`options.businessTypes` 来自 `workflow-runtime/business-types`，每项为 `{businessType,contractVersion,title,fields,actions,validators,eventTypes,approverResolvers}`；后四类能力按公开标识组织为映射，`approverResolvers` 可为空。字段至少包含 `title/type`，并声明 `display/condition/editable/sensitivity`。没有传入目录时工作台自行请求；失败保留草稿并提供重试，模拟和发布被阻止。稳定流程定义创建页按 `businessType` 去重，具体 `contractVersion` 仍在草稿内明确选择，不能默认取最新版本。

`permissions` 由宿主实际 API 方法权限派生，显式 `false` 隐藏对应操作并阻止调用；设计权限不等于对象数据权限。服务端始终重新鉴权。`purposeOptions` 可传可见业务用途提示。

## 配置一个流程

1. 填写名称、稳定流程标识和业务用途标识。用途由设计者定义，不对应固定状态字段。
2. 在“业务适配”选择业务类型及契约版本，映射业务主键、标题、可选申请人和摘要。不会自动猜测字段。租户、组织从服务端业务适配器取得。
3. 添加所需流程变量，选择目录公开的判断字段、变量名及读取时点。默认使用提交快照；节点进入时重读应与业务变更保护配套。
4. 在“启动与依赖”选择手动或事件自动模式。自动模式需选择受控事件和受限执行主体；执行账户必须为 `User.type='workflow-service'` 的非管理员账户并有明确受限数据范围，发布者需 `workflow.runtime.delegate` 权限。不会隐式选用当前登录账户。普通字段变化没有事件接入时不会自动触发。
5. 用条件编辑器构造 AND、OR、NOT、类型比较及前置用途结果。前置用途默认固定同对象当前轮次、最新有效且业务结果已应用的实例；被拒绝而结束的实例不满足“通过”。
6. 在“节点与流转”先选择画布或树内连线列表中的目标边，再插入审批节点或条件/并行网关；原边的 ID、排他条件与默认标记保留。网关原子建立两个出口与汇聚。排他第二出口可先留空作为草稿，需配置条件后才能模拟。节点属性及排他边条件按稳定 ID 写回树。
7. “新增不同结果出口”要求先选中通向唯一入边结束节点的连线：树会原子生成排他双终局，原结束点留在默认支，新建“拒绝结束”支；非默认出口条件仍需设计者配置，未配齐不得模拟。普通单入单出审批任务可删除，原入边身份保留并接回后继。自由连线、任意游离结束、网关或结束节点删除仍未开放；不符合安全拓扑的操作会给出明确原因，不允许手改 JSON 绕过门禁。审批节点默认一入一出，多路汇聚用网关表达。

画布使用已适配的 lowflow-design `FlowDesign`。草稿由受限树投影显示，业务属性始终写回原树；`toLowflowCanvasTree` 和 `fromLowflowCanvasTree` 仅供显式 v2 迁移/转换工具使用，不应作为 v3 页面回写入口。草稿允许部分配置未完成，但模拟、发布使用严格门禁。BPMN 转换及最终发布仍由后端从冻结 v3 树投影完成。

已发布版本画布使用上游只读模式，节点清单仍允许选择节点查看不可编辑的属性；清单选择不更改树或提交请求。
8. 设置固定候选人员，或在“动态审批人”中选择当前业务契约公开且已授权的解析器，再配置其声明式参数；节点只保存 `approverResolver: {key,parameters}`，不能输入任意表达式。可将固定用户与动态结果合并。单人、ALL 会签、ANY 或签均在进入节点时按完整有效人员集合分配；静态会签/或签须至少两名明确用户且不混用候选组，动态会签/或签解析后也至少需要两名实际有权用户。默认禁止申请人自审，允许时需显式开启；例如 `workflow-request@2` 提供申请人解析器，而旧 `@1` 不会自动获得该能力。
9. 选择允许动作。退回须配置前置目标；转办、委派、加签可配置目标用户或角色/组织资格。加签前后顺序由执行动作填写。空候选按实际有效成员判断，默认阻断；选择“升级到指定人员或组”后，可分别从授权目录选择升级处理人、升级候选角色/组织，至少填写其中一项。仅在主候选不可用时启用升级，不能降低 ALL 会签要求；发布后的只读面板保留已配置的组标识与中文名称。
10. 选择可读字段、表单保存业务操作 `formAction`、可编辑和必填字段及二次验证。二次验证显示图片验证码、人机交互验证、短信验证码、邮箱验证码、多因子验证码；定义 JSON 仍保存对应的 `Captcha`、`Hmi`、`Sms`、`Email`、`Mfa` 枚举值。可编辑字段必须同时可读、目录允许编辑、位于业务操作 `writableFields`，并有同名同类型操作参数；必填字段必须可编辑。服务端再与当前业务授权求交集。未选择保存操作时不能配置可编辑业务字段。
11. 在“结果处理”选择通过、拒绝、撤回、终止对应的业务操作及参数。参数选择固定值或同类型流程变量，也可以不配置任何回写操作。操作失败时后续依赖不会提前解锁。
12. 保存草稿，处理校验问题，开始自动模拟并检查服务端覆盖报告。“覆盖分支”列出实际走到的分叉出口连线 ID，不是审批任务节点；“未覆盖分支”列出未走到的出口，非空时模拟失败且不能发布。没有分叉的串行图两栏均显示“无”，旧报告缺少覆盖字段时显示“未记录”，不能把缺失证据解释成无分支。业务字段和动态审批样例均来自契约冻结的纯数据，不能单独证明真假两路均覆盖，也不调用真实业务解析器；样例缺失或只剩禁止自审候选且没有可验证的显式升级用户时模拟失败。通过后才发布；修改 Testing 配置会回到草稿并使旧报告失效。

## 接口与失败语义

默认 API 基路径 `/com.levin.oak.base/V1/api`，可由服务构造参数或宿主子类替换。

- `GET workflow-runtime/business-types`：授权能力目录，不返回真实业务记录。
- `POST WorkflowDefinitionVersion/save-design`：JSON `{id,optimisticLock,lowflowDefinition}`，返回完整版本。
- `POST WorkflowDefinitionVersion/start-simulation`：JSON `{id}`，返回版本及模拟报告。
- `POST WorkflowDefinitionVersion/publish-after-simulation`：JSON `{id}`，服务端复核测试、唯一发布版本及依赖条件。

保存冲突需刷新并核对其他修改，不能覆盖最新乐观锁后盲目重试。接口失败不会关闭工作台或清空配置。Published、Retiring、Retired、Archived 均只读；生命周期只经语义化 API 迁移。

## 最小验证与扩展

使用无状态字段对象配置一条审批流程，完成字段映射、保存、模拟、发布和真实待办执行。再验证错误字段/条件拒绝、拒绝结果不解锁下一用途、结果操作失败不放行、低权限目录和对象访问被阻止。组件测试不能替代浏览器与服务端数据库端到端验收。

本模块不提供任意脚本、服务任务、自由跨并行退回或任意数据库属性赋值。新增能力先通过业务目录和服务端支持矩阵，再扩展界面。设计原理见[设计与实现](流程设计器设计与实现.md)，下游使用要求见[模块开发规范](MODULE-DEVELOPMENT-STANDARD.md)。

在线模拟的纯数据 fixture、声明式校验器和资源边界正在本批集成；模拟报告不构成真实业务适配器写入或外部发送验收。未知或未覆盖能力应由服务端明确拒绝，不能以页面存在配置项推断已经支持。多业务、失败恢复及并发场景仍需按交付批次独立验证。
