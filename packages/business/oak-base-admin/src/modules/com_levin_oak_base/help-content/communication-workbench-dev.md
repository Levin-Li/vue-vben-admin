# 邮件、个人消息与工单工作台使用指南

## 邮件中转的投递目标

在邮件中转的标准新增表单填写域名、邮箱别名和提供商后，必须至少添加一个“投递目标”。投递目标在独立子列表中一条占一行；点击“新增目标”弹出表单，选择“邮箱”“完整邮件 Webhook”或“通知 Webhook”并填写邮箱或 HTTPS 地址。已有目标可在所在行点击“编辑”，删除须二次确认；列表超过五条时内部滚动。父表单保存时仍提交 `type:endpoint` 字符串数组，类型和地址均须合法。

编辑时会回显已有目标，修改一项不会清空其它目标；空目标列表不能保存，必填帮助会保留在表单内。保存只创建或更新本地配置，不等于已经同步至提供商；同步和DNS操作仍通过各自明确动作执行。

## 安装与入口

通过 `@levin/oak-base-admin` 公开入口启用 `createOakBaseAdminModule()`，并使用当前后端授权菜单及页面路由映射。宿主在 `configureAdminApplication` 中注入本包 API 入口导出的 `userMessageService`；框架接入方式见 `@levin/admin-framework` 包内 `docs/personal-message-integration.md`。独立页面不会注册私有邮件文件、通知事件、投递尝试或工单消息的通用 CRUD。

| 页面             | 地址                                 | 业务分组  |
| ---------------- | ------------------------------------ | --------- |
| 我的消息         | `/clob/V1/MyMessages`                | 个人&中心 |
| 我提交的工单     | `/clob/V1/MyTickets`                 | 个人&中心 |
| 待我处理的工单   | `/clob/V1/MyHandlingTickets`         | 个人&中心 |
| 收件箱           | `/clob/V1/Inbox`                     | 应用&接入 |
| 客服邮箱设置 | `/clob/V1/SupportMailboxSetting`        | 应用&接入 |
| 工单受理小组     | `/clob/V1/TicketQueue`               | 客户&伙伴 |
| 客服工单         | `/clob/V1/Ticket`                    | 客户&伙伴 |
| 通知投递记录     | `/clob/V1/NotificationAudit`         | 运维&审计 |
| 工作流通知渠道   | `/clob/V1/WorkflowNotificationRoute` | 基础框架 → 工作流 |

菜单、方法权限和服务端支持事件共同决定操作。消息摘要不授予来源访问权；服务端每次读取、下载或写入均重新检查当前身份、租户、组织及业务范围。前端地址或隐藏按钮不能替代这些校验。

## 个人消息与公告来源

消息页使用当前登录身份的服务端分页、未读筛选及未读总数。打开列表、详情或来源不自动标记已读；使用单条或当前页批量已读按钮提交 `{ids:[...]}`，每次最多100条。已读时间由服务器返回，工单、邮件和公告业务状态保持独立。

公告提醒进入 `/clob/V1/MyMessages?noticeId=<公告标识>`，调用 `Notice/myDetail` 读取本人受众快照及当前资格允许的最小展示内容；普通用户不通过管理公告列表或通用详情读取正文。来源失效、无权访问或身份范围变化时，页面清空旧正文并显示不可访问状态。HTML隔离在没有脚本及同源权限的 iframe；文本、Markdown和配置JSON只读展示。

工作流来源使用服务端持久化的 `{kind,id}` 目标，固定进入 `/clob/V1/MyWorkflow?taskId=...` 或 `?instanceId=...`，普通登录保留定位参数。邮件与工单分别进入固定页面的 `?id=...`；不使用摘要中的任意URL，不从业务实例标识猜测工作流任务。

## 工单受理小组与客服邮箱设置

先在工单受理小组页选择已授权受理组织，填写同范围唯一的小组编码和名称，选择有效用户或角色作为处理范围，并按需选择小组支持的工单分类。保存和启停使用独立业务命令；编辑或启停必须回传读取时的版本。没有对应操作权限时不显示按钮。

平台用户查询队列时可只选择一个有权访问的租户，查看该租户内自己有权访问组织的队列；也可继续选定具体受理组织。新增仍必须选定具体授权组织。详情、编辑和启停以所选记录自己的租户、组织及版本为准，不以较宽的列表筛选范围执行行操作。

客服邮箱列表的“处理组织”只用于查询筛选；有创建权限时无需先筛选列表。点击“新增客服邮箱”，在弹窗内选择有权管理的处理组织，再填写完整邮箱地址、收件方式和来源。列表已选组织会预填到弹窗，但可改选；切换弹窗组织会清空旧来源、队列、处理人及邮箱输入，提交前必须重新选择。本地SMTP引用已开启收件的域名；Forward Email引用已同步并匹配邮箱的路由。选择已启用工单受理小组、可选默认处理人、优先级以及可选回复邮件设置。回复邮件设置只引用服务端已授权的发信配置，不能填写SMTP主机、口令或任意收件地址。小组按编码搜索，收件来源选项由弹窗所选组织的服务端接口提供。

平台用户在队列或邮箱的新增弹窗中可先选择归属租户，再从该租户的授权组织中选择受理组织；切换租户或组织会清空不再适用的处理人、角色及邮箱来源等关联选择。编辑时租户与组织固定为原归属；需要其他归属时应新建对应记录。队列保存后刷新当前列表筛选范围，若新增记录属于其他租户或组织，需切换列表的受理组织后查看。所有选择及保存仍由服务端复核权限与归属。

新邮箱规则默认停用。修改规则须先停用；启用动作重新核验来源、队列和处理人。停用后邮件仍可进入授权收件箱，但不自动建单。版本冲突、来源无效或范围不符时，刷新后重新核对配置，不通过普通更新覆盖状态或版本。

## 工作流通知渠道与群目标

工作流通知渠道使用实际业务资源的查询、新增、更新、删除权限，更新绑定读取时的版本。事件仅为“任务创建、任务提醒、任务到期、任务完成”；通知方式来自服务端枚举：站内、邮件、飞书、企微、钉钉机器人。接口仍使用稳定事件键 `TaskCreated`、`TaskReminder`、`TaskDeadline`、`TaskProcessed` 和既有渠道编码。

初次配置时，进入“基础框架 → 工作流 → 工作流通知渠道”，按需要选归属租户和组织，点击“新增通知渠道”，选择发生事件和通知方式即可。适用流程定义不选时，对当前业务范围内全部流程生效；要限定某个流程，就从有权查看的定义中搜索并选择。展开“更多匹配设置”后可继续从该定义的版本和节点中搜索选择；三者按所选值**精确相等**匹配，留空分别表示全部。无定义或版本查看权限时不显示未经授权的候选。优先级默认100，数值越小越先；“强制覆盖”替代较低匹配层级的通知渠道。附加 JSON 条件仅支持字段值精确相等或值数组，`{}` 表示不限，不支持大于、包含或表达式。编辑已有高级规则时页面自动展开该区域。

站内与邮件的接收人由工作流引擎和服务端精确受众决定。三家群机器人应先在“机器人通知群”中配置；租户流程从本租户及对应组织可访问的群中选择，平台流程选择租户和组织均为空的平台群。页面只保存群标识，不输入 Webhook URL、token 或密钥。发送前系统再次核对通知群范围、渠道和启用状态，平台群不能作为租户流程的回退目标；历史逻辑引用不自动转换为通知群。

群地址或密钥变更后，先前排队的消息不会发送到新群。停用发生在发送预检之后时，已经在途的请求可能仍然送达；对结果不确定的投递，先核对群消息再决定后续处理。

群目标的HTTPS地址与可选加签秘密由服务端部署秘密引用解析；服务插件配置表单消费后端JSON Schema，不能把实际秘密值放进路由、浏览器或消息摘要。路由页面显示固定安全通知模板，不接受自定义HTML或未声明templateCode。匹配条件只保存有限的精确值JSON，不在浏览器执行表达式或脚本。

切换个人渠道与机器人渠道时目标必须明确替换；邮箱/站内目标不能保留旧群引用。服务端拒绝跨作用域配置或未知字段时重新授权读取事实，不能通过请求迁移路由的租户和组织归属。入队、渠道受理及结果不明通过统一投递审计追溯，修改路由不改写已产生的事件或尝试历史。

“运维&审计 → 通知投递记录”用于查看已产生通知的渠道受理记录，不在此页创建通知。先选业务范围，再按投递状态筛选；“查看详情”展示渠道尝试和人工处理日志。渠道受理不等于用户已阅读。失败记录只在原因修复后由有权主体重试；结果未知时必须从供应商记录核实**未受理**并提供无机密核验标识，不能直接重发。没有记录时，页面显示当前范围和筛选条件下的空态。

## 邮件详情与转工单

收件箱复用标准只读 CRUD 的查询、服务端分页、详情、刷新、全屏、列设置和字段导出；通用新增、编辑、删除始终关闭。选择受理组织后保留可见的选择并从第一页重新查询；固定 `?id=...` 只定位待授权的来源。标准详情展示正文与会话头，“原文与受理”扩展入口再按当前权限读取邮件并提供私有文件操作。HTML只显示源文本，不作为网页执行。原始MIME预览最多128KB，完整内容及关联附件通过携带正常登录鉴权的私有下载请求取得。下载绑定来源收件标识和文件标识，不使用公开上传地址或URL。

转工单前选择授权受理组织以及匹配实际收件地址的启用规则；规则选择支持分页。提交只包含来源邮件和规则标识，负责人、状态、身份和附件关系由服务端决定。成功后进入既有或新建工单详情；失败保持邮件事实，并提示核对范围与受理规则。

## 系统内工单工作台

标准 CRUD 页面的帮助图标（悬停显示“我要帮助”）会尝试截取当前可见区域，并打开“个人&中心 → 我提交的工单”。选择有权访问的发起组织、分类和启用的受理小组，填写标题、问题描述及可选标签；发起组织和受理组织可以不同。自动截图和手动选择或粘贴的图片以小卡片展示，点击查看大图，可逐张移除，最多 5 张；本地 PNG、JPG 或 WebP 原图最大 10 MB，转换后的每张 PNG 不超过 2 MB，尺寸不超过 4096×4096。图片随工单私有提交，截图失败时仍可提交；查询参数不写入来源页面路径，密码和标记为私密的区域会遮盖，但用户仍应检查截图中其他业务信息。

“待我处理的工单”供具备受理小组处理资格的人员查看；两个工作台左侧为工单列表，右侧为聊天气泡；当前用户消息靠右、对方消息靠左，每条内部消息显示发送人名称、用户 ID 和时间，内部备注单独标识。页面每7秒刷新，未读红点和站内铃铛按个人记录；查看已加载消息只确认本人的对应提醒，其他人的未读不会变化。内部备注仅当前合资格受理人员可见。页面按钮和接口还要求对应操作权限；菜单须由管理员同步并授权后使用。

每张工单的红色数字表示当前用户可见的未读消息数；超过 99 条时显示 `99+`，打开后只确认已加载消息。鼠标悬停内部发送人可查看当前租户及授权可见的组织名称；此信息受工单消息接口的“发送人组织归属”数据属性权限和组织范围约束，无权或信息不可用时显示提示。“我来处理”会将未分派或已分派给自己的工单领取给当前用户并进入处理中；已分派给其他人时需先重新分派。

打开工单或自己发送消息时，会话滚动到最新内容；停留在底部附近时，新消息也会自动跟随。向上查看历史消息时，自动刷新保留当前阅读位置。

管理员在数据字典中维护编码为 `ticket-category` 的工单分类，字典项的编码作为保存值、名称作为页面显示。发起工单时可选择一个分类，也可留空；选择后仅显示支持该分类的受理小组，唯一匹配时自动选中，多个匹配由发起人选择。小组未配置分类时不会匹配已选分类，未选择分类仍按原流程选择小组。工作台可查看、修改和按分类筛选，修改时当前小组必须支持目标分类。已有处理人时分配入口显示“转派”，没有处理人时显示“分派”。历史工单默认未分类，分类停用后历史编码仍保留；修改时只能选择当前启用的分类。

邮件来源的历史会话附件在具有“下载工单附件”权限时可从消息气泡下载；服务端仍核验工单及原收件关联。页面截图使用独立的私有截图接口，不能作为邮件附件来源。切换工单后，尚未返回的旧附件不会自动下载。

系统标签由管理员在现有字典中维护，字典编码为 `ticket-tags`，启用字典项的名称显示为候选；未配置时仍可输入自定义标签，自定义值只保存在当前工单。每张工单最多10个标签、每个最多32字符；标签筛选在服务端执行。

自动流程通过应用配置控制：`oak.base.ticket.auto-close-days` 默认3，表示已解决后等待的自然日数；`oak.base.ticket.overdue-hours` 默认24，表示未解决工单自最近活动起的提醒小时数；`oak.base.ticket.lifecycle-poll-ms` 默认60000毫秒；`oak.base.ticket.lifecycle-enabled=false` 可停用自动调度。超时提醒不改变工单状态，同一活动周期只提醒一次；自动关闭前会锁定并复核当前状态，用户回复已使工单重开时不会覆盖回复。关闭天数允许1至3650，提醒小时数允许1至87600；超出范围时调度拒绝处理并记录错误，非整数配置会使应用启动失败。

部署前须由后端部署人员按受控迁移流程执行后端项目提供的工单组织字段及分类字段迁移脚本，并同步授权菜单和操作；迁移脚本不会由页面调用。

## 工单会话、状态动作与邮件回复

工单页只提供授权查询及专用动作，不提供通用新增或任意状态编辑。分派、开始处理、解决、重开、关闭仅在服务端返回相应支持事件且当前方法权限满足时展示。提交回传当前工单版本，服务端完成状态迁移和追加日志。流程日志按时间排序，展示实际操作人、状态迁移与非空说明。

会话按服务端稳定分页显示，截断正文可通过当前工单的专用消息详情读取。来源邮件和私有附件仍独立授权。附件下载绑定工单与不可变来源关系；回复附件只能选择该工单已关联的私有入站附件，本入口不上传任意新附件。

外发前核验现有固定联系人，提供无机密核验记录标识；浏览器不能修改该邮箱。回复只提交纯文本、关联附件及一次明确回复的稳定键，不提交From、To、抄送、SMTP或会话头。首次请求固定回复键和内容，技术重试复用原请求。正文最多十万字符，附件最多二十件。

外发结果区分等待发送、发送中、SMTP已受理、发送前确定失败和结果不明。SMTP受理不证明对方邮箱最终送达。结果不明时不能直接重发；有独立“核验工单邮件未受理”权限且仍符合当前队列处理资格的人员，可明确确认供应商未受理并提供安全证据引用。邮箱未收到不足以证明未受理，确认框不得预先勾选；证据是1至128字符的非秘密记录标识，不是URL、token或原始响应，原因固定为VerifiedUnsent。核验回传当前意图版本，仅把Unknown改为Failed并追加审计，不发送邮件，也不自动重试。页面须刷新外发结果取得新的状态与意图版本；确定发送前失败且总尝试次数未达五次时，才显示另一个显式重试入口。工单版本与外发意图版本不可混用。

## 投递审计与人工核验

通知投递页仅展示安全投递元数据、历史尝试和追加式人工日志，不展示正文、目标凭据或供应商原始错误。平台用户可以按有权访问的租户查询，也可以进一步选择该租户内的授权组织收缩范围；租户用户使用服务端会话租户。详情、核验和重试沿用记录的受控范围，服务端再次授权。

工作流通知路由同样允许平台用户按有权访问的租户查询，新增时需要明确选择授权组织。租户级查询不会给行操作赋予更宽范围；详情、编辑和启停继续使用记录自身的租户与组织。

未知结果先核验渠道确实未受理，明确勾选确认并填写无机密记录标识；核验本身不会发送通知。之后符合确定失败状态、权限和总次数限制时，才可独立重试。重试原因使用配置已修复或服务已恢复等受控原因，必须回传当前投递版本，不清零历史次数。

## 最小验证与错误处理

使用有效普通用户确认消息与未读数只属于本人，读取公告来源不调用管理正文接口、不自动已读。撤销来源资格后重新打开，必须显示不可访问且不保留旧正文。使用授权处理账号验证队列与邮箱配置、私有邮件下载、重复转工单、状态版本冲突以及回复技术重试。

测试未知投递和未知外发没有直接重发按钮；验证合法动作后列表、详情和日志刷新。接口拒绝范围、状态、身份或版本时保持数据不变，并让用户重新授权读取当前事实。页面可见、构建成功或本地模拟不能证明公共DNS、真实邮箱最终送达与部署现场网络已开通；上线时须按后端模块手册完成对应环境验证。

## 范围选择与二次开发

组织选择器先展示租户分组；点击左侧箭头展开，再选择有权访问的组织。分组本身不可选，初始折叠不表示组织目录加载失败。已有子组织的展开保留服务端组装的树，不额外增加目录权限。

工作流通知路由、工单受理小组、客服邮箱设置、工单和收件箱的通用 GET 查询及主键请求由 API facade 统一处理范围。非平台主体省略 `tenantId`，由服务端从当前身份注入；平台主体保留明确租户筛选。非空 `orgId` 继续作为标量发送，在调用方没有明确 `orgIdList` 时同时补充单元素 `orgIdList:[orgId]`，沿用现有模型的列表及公共组织查询语义；调用方已有的列表不被覆盖，界面选择记录也不被修改。通用 DELETE 使用相同范围封装。

独立通知审计接口使用自己的 DTO，不追加未知组织字段。Create、Save 和其它 POST 业务命令继续遵循各自 DTO 合同，不能照搬 GET 的字段省略规则；例如队列保存需要明确的租户和组织。通知群目标保存和发送均由服务端重验范围；二次开发应通过服务方法调用，避免直接拼接 API 请求绕开范围封装。

队列处理用户候选沿用上述通用组织查询范围。处理角色使用角色接口正式租户 DTO，不传组织字段，并关闭 `containsPublicData`：队列处理角色必须属于队列租户，平台公共角色不是有效处理角色。候选查询的租户字段省略规则不用于保存、编辑或启停命令；这些命令仍按其 DTO 提交明确归属和读取版本。

客服邮箱默认处理人与工单分派候选也通过统一组织范围查询加载。邮件来源目录使用正式租户 DTO，不发送组织字段：本地 SMTP 只查询已启用、生命周期为 Active 且已开启接收的域名；Forward Email 只查询已启用并已同步的路由。来源可见字段用于排除已知无效记录；私有投递目标被屏蔽时不要求额外读取权限，保存和启用仍由服务端校验真实来源、到期状态、邮箱匹配及 Webhook 目标。当前租户没有满足条件的来源时，候选为空是正常结果，应先按邮件与域名指南配置来源。

平台管理员的通用角色查询可能仍返回平台公共并集。队列角色候选逐项核对正式返回的 `tenantId` 与 `publicRole`：明确公共角色被排除，平台主体还必须精确匹配所选租户；租户主体遇字段被屏蔽时继续依赖正式目录授权与保存复核。这些候选过滤不会授予权限或改变业务命令。

### 客服工单初始范围

平台用户没有默认租户时，在标准查询栏的“业务范围”字段选择已授权受理组织后，页面才查询对应租户和组织的工单；未选择时由该字段提示选择，不在查询栏上方另设提示块，也不发送缺少范围的列表或详情查询。已有默认租户的用户保留原查询行为。查询字段不替代服务端的数据范围校验。
