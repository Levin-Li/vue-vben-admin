# Levin Framework Base 使用手册

本文面向本项目的管理后台使用者、实施人员和联调开发者，说明系统的访问方式、常用管理流程、核心业务模块和接口联调入口。更细的模块设计可继续参考 `docs/` 下的分模块说明；菜单、租户域名布局与动态路由的完整设计见 `16-自定义菜单与动态路由全链路设计.md`。

## 1. 系统概览

`levin-framework-base` 是 Levin 多租户插件式框架的基础模块，提供租户、组织、用户、角色、菜单、权限、系统设置、字典、地区、文件、通知、支付、资金账户、内容管理、任务调度、API 安全控制等能力。

系统由两部分组成：

- 后端管理服务：启动模块为 `admin-bootstrap`，本地默认端口为 `8081`。
- 前端管理后台：位于 `frontend/admin/apps/bootstrap-app`，本地开发端口为 `5666`。

默认后端 API 前缀为：

```text
/com.levin.oak.base/V1/api
```

常用访问入口：

| 用途 | 本地地址 |
| --- | --- |
| 管理后台前端 | `http://127.0.0.1:5666/` |
| 后端服务 | `http://127.0.0.1:8081/` |
| Swagger UI | `http://127.0.0.1:8081/api-docs/swagger-ui.html` |
| OpenAPI JSON | `http://127.0.0.1:8081/v3/api-docs` |

## 2. 本地运行准备

### 2.1 环境要求

- JDK：项目规则要求本地使用 JDK 25；根 `pom.xml` 的编译 release 为 17。
- Maven：推荐使用 `/opt/homebrew/bin/mvn`。
- Node.js：前端要求 `>=20.19.0`。
- pnpm：前端包管理器为 `pnpm@10.28.2`。
- 数据库：开发环境使用 PostgreSQL。
- 缓存：项目支持 Redis，开发环境按需启动。

### 2.2 启动依赖服务

开发环境数据库和 Redis 的启动脚本在 `docker-compose` 目录下对应子目录中。进入 PostgreSQL 或 Redis 目录后执行：

```bash
./startup.sh
```

开发环境数据库连接配置见 `admin-bootstrap/src/main/resources/application-dev.yml`，默认连接本机 PostgreSQL 的 `dev` 数据库。实际账号、密码和端口以当前配置文件为准。

### 2.3 启动后端

后端启动模块是 `admin-bootstrap`，默认 Maven profile 是 `env1-dev`，通常不需要额外指定 Spring profile。

推荐先编译后启动：

```bash
/opt/homebrew/bin/mvn -Penv1-dev -pl admin-bootstrap -am package
```

然后按 `后端启动说明.md` 使用编译结果启动。日常联调时应让本项目各子模块的 `target/classes` 位于 classpath 前部，以便本地代码改动优先生效。

启动成功后，可访问：

```text
http://127.0.0.1:8081/api-docs/swagger-ui.html
```

### 2.4 启动前端

进入前端工程：

```bash
cd frontend/admin
pnpm install
pnpm dev:bootstrap-app
```

前端开发服务默认监听 `5666` 端口。开发代理会把 `/api`、`/admin`、`/com.levin.oak.base`、`/v3/api-docs`、`/api-docs` 等请求转发到 `http://127.0.0.1:8081`。

## 3. 登录和基础界面

打开：

```text
http://127.0.0.1:5666/
```

登录页支持：

- 图片验证码
- 短信验证码
- 邮箱验证码
- MFA 验证码

密码登录会先校验账号密码，再按账号和当前租户策略决定是否打开安全验证：已绑定 MFA 的用户输入 Google Authenticator 验证码；其它需要图片验证码的密码登录会在验证码自动填入后显示 5 秒倒计时并自动继续。短信、邮箱验证码登录不改变。实现与运维说明见 `docs/15-密码登录挑战与MFA安全开发指南.md`。

账号、密码以当前环境初始化数据为准。系统存在多租户和域名绑定能力，登录时会结合当前访问域名识别租户站点；平台用户本身不归属于租户，访问租户业务仍须经过明确的租户视角及后端授权。历史 `saas_` 前缀不是平台身份或授权依据。

登录后常用入口包括：

- 左侧菜单：按当前用户权限显示可访问功能。
- 个人中心：查看账号信息、修改密码、上传头像、配置通知。
- 主题/偏好设置：可调整后台显示偏好；租户站点可保存统一后台基础界面配置。
- 消息通知：查看“我的消息”和通知公告。

偏好设置中的“恢复默认设置”只清除偏好相关缓存并立即恢复当前界面默认值，不会退出登录或清除当前认证会话。

## 4. 通用页面操作

管理后台大多数业务页是 CRUD 列表页，通用操作方式一致。

### 4.1 列表和查询

- 使用页面顶部或表格上方的查询条件筛选数据。
- 点击查询后刷新当前列表。
- 支持分页、排序的列会在点击表头后重新加载数据。
- 多租户数据会按当前用户的租户、组织、个人数据范围自动过滤。

### 4.2 新增、编辑、详情和删除

- “新增”用于创建当前模块数据。
- 行内“详情”用于查看完整记录。
- 行内“编辑”用于修改记录。
- “删除”或“批量删除”会根据权限和数据范围校验后执行。

按钮是否显示，取决于后端控制器上的权限注解和当前用户角色权限。看不到按钮时，优先检查角色权限、菜单权限和当前数据归属。

### 4.3 表格工具

通用 CRUD 表格提供：

- 刷新
- 全屏/退出全屏
- 列设置
- 前端导出

列设置支持显示隐藏、列顺序、左右固定和恢复默认。导出时会按当前查询条件和排序条件拉取数据，并可选择导出字段和字段顺序。

## 5. 基础管理模块

### 5.1 租户管理

租户是系统的业务隔离边界。租户相关信息包括名称、标识、Logo、版权、技术支持、前端展示扩展信息等。

常用流程：

1. 创建租户。
2. 配置租户站点或域名。
3. 配置租户系统设置。
4. 创建组织、角色和用户。
5. 为用户分配角色和数据权限。

超级管理员可以管理平台级公共数据。普通租户用户只能操作其权限和数据范围内的数据。

### 5.2 租户站点

租户站点用于把访问域名绑定到租户，并承载站点级展示配置。前端会调用 `tenantSiteInfo` 接口读取当前域名对应的租户站点信息，并合并租户和站点的 `uiExInfo`。

后台基础界面配置使用：

```text
admin-ui-base-setting
```

保存租户站点界面配置后，后续用户访问同一租户站点时会按站点配置显示。

### 5.3 组织、岗位和用户

组织用于维护租户内组织结构，岗位用于描述岗位信息，用户用于登录和业务操作。

建议配置顺序：

1. 先建立组织。
2. 再建立岗位。
3. 创建用户并绑定租户、组织、角色等信息。
4. 按需配置用户数据访问级别和扩展信息。

新增或编辑用户时，密码字段用于设置初始密码或修改密码；编辑时留空通常表示不修改密码，具体行为以页面提示和后端接口为准。

### 5.4 角色和权限

RBAC 是系统权限核心。角色用于聚合权限，用户通过角色获得菜单、接口和业务操作权限。

权限表达式格式为：

```text
模块包名:业务模型名称:业务数据标识:操作名称
```

示例：

```text
com.levin.oak.base:平台数据-平台租户::查看详情
```

支持通配符和多选：

```text
*:平台数据-*
com.levin.oak.base:业务数据-*::查看*|查询列表*
```

权限分配有继承约束：

- 为角色分配权限时，待分配权限必须在当前用户已拥有的权限范围内。
- 为用户分配角色时，当前用户必须能覆盖目标角色权限。
- 非超级管理员不能给自己或他人分配超级管理员、租户管理等超出自身权限的能力。

### 5.5 菜单管理

菜单控制后台左侧导航和页面入口。系统支持公共菜单和租户私有菜单。公共菜单可由租户复用，租户也可以维护自己的私有菜单。

有租户自定义菜单维护权限时，可在“租户自定义菜单”打开“调整菜单”。左侧选择系统菜单，右侧“我的菜单”可编辑名称、图标、启用、显示和替换路径；每行前方固定提供两组竖向按钮，依次为上移/下移和新增/删除，同组按钮紧凑，两组相距 12px。无法继续移动时排序按钮不可用，删除仍需二次确认；右侧宽度不足时横向滚动以访问全部设置。调整后点击“保存”提交；若保存失败，留在弹窗中核对权限、菜单路径和接口错误，不把未保存的本地排列视为已生效。

前端模块内置了基础模块页面映射，菜单路径会映射到对应页面，例如 `/clob/V1/User` 对应用户管理页。菜单与页面不一致时，优先检查菜单路径、前端页面映射和后端控制器资源名。

### 5.6 系统设置和租户系统设置

系统设置用于保存平台级配置，租户系统设置用于保存租户级配置。配置项可用于登录控制、短信、邮件、OAuth、文件存储、API 控制等场景。

系统设置、字典、国际化资源作为公共组件的接入和接口说明见 `docs/11-公共组件使用指南.md`。

建议：

- 平台公共配置放在“系统设置”。
- 租户差异化配置放在“租户系统设置”。
- JSON 类型配置应按页面提供的编辑器或 JSON Schema 填写，避免手写非法 JSON。

### 5.7 字典、地区、地址和国际化

- 数据字典：维护下拉选项、业务分类、状态映射等。
- 国家地区、区域管理：维护地区基础数据。
- 地址管理：维护用户或业务地址数据。
- 国际化资源：维护多语言文案资源。

## 6. 业务能力模块

### 6.1 文件存储和文件资源

文件存储模块支持阿里云、腾讯云、华为云、又拍云、七牛云等 OSS 场景。核心服务为 `BizFileStorageService`，控制器为 `FileStorageController`。

使用流程：

1. 在“服务插件”确认“默认文件存储插件”已启用。
2. 在“服务插件设置”中选择存储供应商，并为公共、租户或域名作用域填写配置。
3. 对于尚未迁移的历史部署，可继续使用 `FileStorage` 系统设置；一旦当前作用域存在有效的服务插件设置，系统优先使用该设置。
4. 在业务页或个人中心选择文件上传。
5. 上传成功后生成文件资源记录。
6. 在“文件资源”中查看、检索和维护上传文件。

服务插件设置会根据所选供应商展示其配置类字段。普通上传统一调用服务端上传接口；只有七牛、阿里云 OSS、腾讯云 COS 支持浏览器直传凭证，其它供应商仍可通过服务端上传正常使用。

### 6.2 短信、邮箱和动态验证码

系统支持短信验证码、邮箱验证码、图片验证码、MFA、人机交互验证码等动态验证方式。短信服务支持主流云厂商通道。插件设计、配置来源和接入方式见 `docs/12-域名与验证码插件设计使用指南.md`。

常见使用场景：

- 登录验证码。
- 注册验证码。
- 敏感操作二次验证。
- API 访问安全控制触发的动态验证码。

如果验证码不可用，优先检查服务插件是否启用、系统设置是否完整、短信/邮箱通道配置是否正确。

### 6.3 第三方 OAuth 登录

OAuth 模块基于第三方登录组件实现，访问后会自动初始化配置项。核心对象包括：

- 社交用户：`SocialUser`
- 控制器：`OAuthController`
- 服务：`BizOauthService`

使用流程：

1. 在系统设置中找到 OAuth 相关配置。
2. 填写第三方平台的 `clientId`、`clientSecret`、回调地址等信息。
3. 启用对应 OAuth 配置。
4. 在登录入口或业务入口发起第三方授权。
5. 授权成功后绑定或创建内部用户。

浏览器发起 `/oauth/transactions` 时，`returnUrl` 必须是与当前请求严格同源的绝对 HTTP(S) 地址：协议、主机和有效端口一致。服务端拒绝相似域名、URL 用户信息、片段及异常格式；省略 `returnUrl` 时仅接受同源 `Referer`，两者都没有时返回当前 OAuth 入口所在站点。部署前必须在最外层代理配置实际允许的 Host、可信转发头和 HTTPS；应用的同源校验不能代替代理 Host 白名单。回跳失败时不创建登录事务或浏览器校验 Cookie。

### 6.4 内容管理 CMS

CMS 模块包含：

- 文章栏目：`ArticleChannel`
- 文章：`Article`

基本流程：

1. 创建文章栏目。
2. 在栏目下创建文章。
3. 维护标题、内容、状态、排序、发布时间等信息。
4. 前端或客户端按业务接口读取文章内容。

### 6.5 支付管理

支付模块采用插件化设计，支持多支付通道和多币种。默认实现包含支付宝和微信官方通道。

核心数据：

- 支付渠道：`PayChannel`
- 支付订单：`PayOrder`

使用流程：

1. 在“支付渠道”中配置支持的支付通道和币种。
2. 业务系统根据币种查询可用通道。
3. 创建支付订单，选择二维码、APP、H5、小程序或公众号等支付方式。
4. 等待支付回调或主动查询支付状态。
5. 需要退款时发起退款。
6. 订阅支付或退款通知处理后续业务。

支付状态变化可通过服务监听器或 Redis/Redisson 主题通知处理。业务接入时优先使用 `BizPayOrderService`，API 调用可参考 `BizPayOrderController`。

### 6.6 用户资金账户

资金模块包含：

- 资金账户：`FundAccount`
- 资金账户流水：`FundAccountLog`
- 资金兑换规则：`FundExchangeRule`

常见流程：

1. 为用户或业务主体创建资金账户。
2. 通过业务操作产生账户流水。
3. 按兑换规则处理不同币种或积分之间的换算。
4. 在资金账户日志中审计交易记录。

### 6.7 通知公告和我的消息

通知公告用于发布系统通知，“我的消息”用于查看当前用户相关消息。通知处理日志可用于排查消息发送、读取和处理结果。

### 6.8 定时任务和调度日志

定时任务模块包含：

- 定时任务：`ScheduledTask`
- 定时任务日志：`ScheduledLog`

使用建议：

1. 在“定时任务”中配置任务名称、执行规则和启停状态。
2. 保存后确认任务状态。
3. 在“定时任务日志”中查看执行结果。
4. 任务异常时结合后端日志和调度日志定位。

### 6.9 域名和 SSL 证书

域名、根域名、租户站点和 SSL 证书管理用于支持多租户站点访问和 HTTPS 配置。SSL 证书申请服务基于 ACME 协议。域名供应商插件、DNS 记录和 DNS-01 配置见 `docs/12-域名与验证码插件设计使用指南.md`。

常见流程：

1. 配置根域名。
2. 配置租户站点域名。
3. 申请或维护 SSL 证书。
4. 生成或更新站点相关配置。

## 7. API 联调

### 7.1 认证相关接口

认证控制器路径位于：

```text
/com.levin.oak.base/V1/api/rbac
```

常用接口：

| 功能 | 接口 |
| --- | --- |
| 获取验证码 | `GET /captcha` |
| 注册 | `POST /register` |
| 登录 | `POST /login` |
| 退出登录 | `GET /logout` |
| 当前用户信息 | `GET/POST /userInfo` |
| 当前租户站点信息 | `GET /tenantSiteInfo` |
| 当前租户信息 | `GET /tenantInfo` |

登录成功后，前端会保存本次 token，并在后续请求中携带认证信息。联调时不要复用历史 token，应该走当前环境的真实登录流程。

### 7.2 业务接口和 CRUD 接口

多数后台 CRUD 资源路径形如：

```text
/com.levin.oak.base/V1/api/<Resource>
```

例如：

- 用户管理：`/com.levin.oak.base/V1/api/User`
- 角色管理：`/com.levin.oak.base/V1/api/Role`
- 菜单管理：`/com.levin.oak.base/V1/api/Menu`
- 租户管理：`/com.levin.oak.base/V1/api/Tenant`
- 文件资源：`/com.levin.oak.base/V1/api/FileRes`

具体方法、参数和响应结构以 Swagger UI 和当前后端源码注解为准。

### 7.3 API 文档

开发环境可通过 Swagger UI 查看接口：

```text
http://127.0.0.1:8081/api-docs/swagger-ui.html
```

如需直接读取 OpenAPI：

```text
http://127.0.0.1:8081/v3/api-docs
```

前端页面开发时，若存在对应 Spring MVC 控制器源码，应以当前控制器源码、注解和业务服务为主，OpenAPI 只作为运行时暴露情况的辅助确认。

## 8. 安全和访问控制

### 8.1 RBAC 权限控制

系统通过 RBAC 控制菜单、按钮、接口和业务操作。后端使用 `@ResAuthorize` 等注解声明权限，前端根据菜单和权限结果展示页面与操作。

排查权限问题时按以下顺序检查：

1. 用户是否登录成功。
2. 用户是否属于正确租户。
3. 用户是否绑定正确角色。
4. 角色是否拥有菜单权限。
5. 角色是否拥有接口或操作权限。
6. 目标数据是否在用户的数据范围内。

### 8.2 数据权限和多租户隔离

多租户对象会按租户隔离，组织和个人数据还会叠加组织、个人范围。业务接口不应只依赖裸 ID，后端请求对象会承载租户、组织、个人上下文，避免越权访问。

使用系统时，如发现“列表为空”或“无权操作”，应先确认当前用户的数据范围，而不是直接判断为数据不存在。

### 8.3 API 访问安全控制

系统可动态控制 API 访问，例如：

- 临时禁用 API。
- 临时开放 API。
- 对特定 API 增加短信、邮箱、MFA、图片验证码等操作验证。
- 按全局、租户或域名维度配置访问规则。

相关页面为“URL 访问控制”，相关配置对象为 `UrlAcl` 和 `DynamicVerifyCodeAcl`。

“URL 访问控制”和“接口流量控制”中的 URL、域名、IP、地区、请求方法、用户类型、用户角色等字符串清单字段使用“通配符清单编辑器”维护。编辑器左侧逐项添加、编辑、复制或删除规则，右侧提供测试匹配和复制 JSON 数组入口；规则过长时，鼠标悬停可查看完整内容。清单规则支持 `*` 和 `?` 通配符，字段说明会标明本字段内是“任一命中”还是“全部命中”。不同字段之间的真实组合关系由后端运行时处理，前端测试只用于校验当前字段的清单规则。

API 动态验证码的目的、前后端协议、弹窗交互、配置方法、实现类和排查方法见 `docs/13-API动态验证码设计使用指南.md`。

### 8.4 数据脱敏

系统支持下行数据脱敏和上行脱敏还原。字段通过 `@DataMasking` 声明展示权限和不脱敏权限。

常见表现：

- 普通用户看到 `******` 等脱敏值。
- 超级管理员或具有指定权限的用户看到原始值。
- 客户端提交脱敏后的 ID 或敏感字段时，服务端可在启用还原能力后恢复原值。

如果敏感字段显示异常，应检查用户权限、字段脱敏注解和数据脱敏开关。

## 9. 常见问题

### 9.1 前端打不开或接口 404

检查：

- 后端是否运行在 `8081`。
- 前端是否运行在 `5666`。
- 前端代理是否指向 `http://127.0.0.1:8081`。
- 请求路径是否带有 `/com.levin.oak.base/V1/api`。

### 9.2 登录失败

检查：

- 验证码是否来自当前会话。
- 账号是否属于当前租户或当前域名。
- 用户是否被禁用、锁定或未分配角色。
- 当前环境是否启用了短信、邮箱或 MFA 等额外验证。

### 9.3 看不到菜单或按钮

检查：

- 用户角色是否正确。
- 角色是否分配了菜单和操作权限。
- 菜单路径是否与前端页面映射一致。
- 当前用户是否具备目标数据范围。

### 9.4 文件上传失败

检查：

- 文件大小是否超过后端限制。默认单文件限制为 `20MB`，请求总大小为 `30MB`。
- “默认文件存储插件”是否启用，且当前作用域是否已选择有效供应商。
- OSS、COS、S3 等存储通道配置是否完整。
- 当前用户是否有上传接口权限。

### 9.5 支付回调未生效

检查：

- 支付渠道配置是否启用。
- 回调地址是否可由支付平台访问。
- 支付订单状态是否已更新。
- 业务系统是否订阅了对应支付或退款通知。
- 后端日志和支付订单日志是否存在异常。

### 9.6 租户站点信息异常

检查：

- 当前访问域名是否绑定租户站点。
- 租户站点是否启用。
- 租户和租户站点的 `uiExInfo` 是否配置正确。
- 前端是否成功调用 `tenantSiteInfo`。
