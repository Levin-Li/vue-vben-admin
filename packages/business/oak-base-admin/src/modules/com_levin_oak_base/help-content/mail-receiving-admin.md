# 邮件收件模块功能与使用手册

## 1. 适用范围与功能

本模块提供两种入站邮件接入方式：应用自身作为**仅收件的 SMTP 服务器**，或者使用 Forward Email 的第三方邮件中转路由。收到的邮件进入统一的 `Inbox` 收件箱。域名服务负责管理域名资产及其 DNS 记录，能协助开通本地 SMTP 收件。主动发送验证码或通知邮件由独立的“默认邮件发送插件”连接外部 SMTP 服务完成。

| 场景 | 使用入口 | 结果 |
| --- | --- | --- |
| 自建入站邮件服务器 | 系统设置“本地SMTP收件配置”与“根域名管理” | 接收已开通域名的邮件并写入收件箱 |
| 域名服务协同 | 根域名管理的检查、开启、同步修复邮件接收操作 | 核对或补齐根域 A、MX 记录 |
| 第三方邮件中转 | “邮件中转路由” | 将受管 alias 同步到 Forward Email，并按其目标投递 |
| 主动发信 | 服务插件设置中的默认邮件发送插件 | 通过另一个 SMTP 服务发送验证码或通知 |

本地 SMTP 入口只接收入站邮件；它没有 SMTP AUTH、外发中继、IMAP、POP3、用户邮箱登录或邮件客户端发件能力。需要用 Outlook、Thunderbird 等客户端登录邮箱或通过本机向互联网发信时，现有功能不能直接充当完整邮件服务。第三方中转路由也不是本地 SMTP 收件器的别名配置。

## 2. 作为入站邮件服务器使用

### 2.1 部署前提

1. 准备公网可达的 IPv4，确认网络和云平台允许外部访问 TCP 25。应用进程在 `127.0.0.1` 监听内部 SMTP 端口，默认 2525；公网 TCP 25 可由 Nginx `stream` 转发。不要把内部端口直接作为开放中继暴露。
2. 为应用准备可写的 Nginx 配置资产目录。默认片段位置为 `../nginx/oak-local-smtp.conf`，可通过 `oak.base.local-smtp.nginx-stream-file` 指定。Nginx 主配置应在 `stream` 上下文包含该片段，不能把它放在 HTTP `conf.d` 下。
3. 在“系统设置 → 邮件接收 → 本地SMTP”找到“本地SMTP收件配置”（键 `LocalSmtpConfig`）。设置“是否开启”、内部“监听端口”和“轮询秒数”并保存。默认端口 2525、轮询 30 秒；轮询执行间隔限制在 15～60 秒。部署项 `oak.base.local-smtp.enabled` 仅决定该设置首次创建时的默认开关值，之后以系统设置为准。
4. 如需降低单封邮件大小，配置 `oak.base.local-smtp.max-message-bytes`；默认 10 MiB。私有原文存储另有 10 MiB 硬上限，提高此配置不会提高存储上限。确认 Nginx、主机防火墙和上游网络均已允许 TCP 25。生产环境的 TLS、证书及反向 DNS/PTR 需要按部署环境单独设计和验证，不能由域名开通动作代替。

服务启动时读取系统设置，启用后在回环地址启动 Apache James SMTP 接收器，并生成 TCP 25 到内部端口的 Nginx `stream` 片段。**生成片段不等于 Nginx 已加载配置**：部署人员需要确认主配置已正确包含该片段、运行 `nginx -t` 并按环境方式 reload。停用服务会删除生成的片段；应同步检查并 reload Nginx，避免旧转发配置继续存在。变更端口后也要核验监听端口与实际 Nginx 转发一致。

### 2.2 邮件怎样进入收件箱

SMTP 在 `RCPT TO` 阶段核对收件域名。只有系统内存在、可用、未过期且已“开启邮件接收”的 Domain 才会被接受；这个域名下的本地部分不要求预先建 alias。收件器解析邮件主题、`text/plain` 和 `text/html` 正文，并按每个实际完整收件地址独立保存 `Inbox`。原始 MIME、普通附件及有有效 `Content-ID` 的内嵌资源保存到私有 `MailBlob`；原文摘要以及 `Message-ID`、`In-Reply-To`、`References` 会保留在收件记录。邮件与其原文、附件引用在同一事务提交，保存失败不留下半条邮件事实。本地 SMTP 不生成 SPF/DKIM/DMARC 认证结果；邮件头也不能证明发件人身份。

归属以已验证的接收入口为事实源：租户 Domain 或验签路由只在本租户按用户、组织、联系租户顺序寻找唯一候选，保留命中对象的组织/个人归属；没有唯一候选时保留入口租户。其他租户的相同联系邮箱不会被选中，也不阻断合法收件。只有平台共享入口无明确租户时，歧义或完全未匹配才保留平台归属。Local 的用户名、用户 ID 或合规手机号本地部分匹配仍限定入口作用域；Forward 采用完整联系邮箱。查询只读取有界归属标量，邮件头不能指定租户。收件箱按接口权限和数据范围查看，普通增删改不能伪造邮件。

SMTP 返回码的主要含义：`250` 表示该次所有已接受收件目标均已持久化，`550` 表示收件域没有开通，`552` 表示原文或 MIME 解码超过资源限制，`451` 表示保存过程暂时失败、发件方可稍后重试。多收件人中前一地址已成功、后一地址保存失败时，整体返回 `451`；重投会复用已提交地址的记录并补齐失败地址。

去重身份包含接收渠道、域名或路由、规范化完整收件地址、消息标识及稳定内容摘要，由非空 `inboundKey` 唯一约束保护。同一 `Message-ID` 但内容不同仍保存为独立邮件；同一消息的不同收件人不会互相覆盖。稳定摘要排除 James 每次接收追加的易变 `Received` 头，原始 MIME SHA-256 单独保留接收证据。缺少消息标识时使用稳定内容摘要，不按主题去重。

默认 MIME 边界为：原文最多 10 MiB、嵌套深度最多 16、MIME 部件最多 100、附件及内嵌资源合计最多 20、单个解码部件最多 5 MiB、全部解码内容合计最多 20 MiB。超限拒绝保存；非超限的格式损坏会保留原文并标记 `ParseStatus=Failed`，不把不完整解析结果当作成功正文或附件。普通 Domain 变更的缓存默认每 60 秒刷新；“开启邮件接收”操作会立即失效对应缓存。

## 3. 与域名服务结合开通

### 3.1 准备域名与 DNS 供应商

在“根域名管理”中登记或申请可用域名，并为该域名绑定可用的域名服务插件。自动管理邮件接收 DNS 需要插件提供 `DnsRecordCrud` 能力、有效凭据以及对目标 DNS zone 的管理权限。供应商接入与配置方式见[域名与验证码插件设计使用指南](?doc=domain-provider-guide)。如果 DNS 由第三方控制且本系统没有可用的写入插件，检查会给出人工配置提示，但当前“开启邮件接收”操作不会仅凭人工配置就把域名标为已开启；需要具备受管 DNS 能力后再开通。

本地收件使用的根域 DNS 基线如下，其中 IP 为系统识别的当前服务器公网 IPv4：

```dns
example.com.  A   <服务器公网IPv4>
example.com.  MX  10 example.com.
```

开通动作只会补齐缺失的根域 A 或 MX，已有正确记录会跳过，已有不一致记录会报冲突并保持原样。它不会替换或删除网站正在使用的 A 记录，也不会配置 AAAA、CNAME、SPF、DKIM 或 DMARC。若根域 A 已指向另一台网站服务器，需先由管理员决定网络和 DNS 架构；不要依赖自动开通覆盖它。

### 3.2 管理端操作步骤

1. 在“根域名管理”选择目标域名，点击“检查邮件接收”。查看返回的公网 IPv4、`missingRecords`、`conflicts` 和 `warnings`。这个操作只读；`ready` 只表示记录检查结果，不能替代全链路实际投递测试。
2. 无冲突且 DNS 供应商可用时，点击“开启邮件接收”。系统只补缺失 A/MX，并重新读取供应商记录及公共 DNS。公共 DNS 尚未传播、读取失败或记录冲突时，不会把 Domain 标为已开启；等待传播或处理冲突后再检查和重试。
3. 开通后，从外部邮件服务向该域名的地址投递测试邮件，再到“收件箱”按收件地址、主题或时间查找。确认邮件实际入库及归属正确。
4. 后续点击“检查邮件接收”可复核状态。已开通域名的 A/MX 被误删时，点击“同步修复邮件接收”仅补回缺失的预期记录。存在冲突时先人工处理，修复操作不会覆盖或删除冲突记录。后台周期检查只报告问题，不自动改写 DNS。

本地收件和 Forward Email 中转都依赖收件域的 MX 指向。为同一域选择接入方式时，应核对现有 MX 与希望使用的接收入口；不要同时把两条路径当作同一封邮件的确定性主入口。

## 4. 查看邮件、发信和第三方中转

在“收件箱”页面查询收件人、发件人、主题、接收时间和处理状态，打开详情查看文本或 HTML 正文。邮件 HTML 属于不可信入站内容，不应作为应用代码、脚本或表单执行。管理端读取需要对应收件箱的查询/详情权限，实际可见记录还受租户、组织及个人数据范围约束。`Received` 表示已接收；解析结果另看 `ParseStatus` 和 `processError`，不表示已经向其他邮箱转发或由人工处理。

原始 MIME 引用为 `rawMimeFileId`，附件及内嵌资源引用为 `attachmentFileIds`。管理 API 在模块 API 前缀下提供 `GET Inbox/blob/download`，参数 `id` 为有权访问的收件记录 ID、`blobId` 为该记录当前引用的私有内容 ID。下载先执行收件箱详情授权，再校验内容归属、引用成员关系和摘要；返回强制附件下载、`application/octet-stream`、`no-store` 和 `nosniff`，不提供公共静态 URL。仅知道内容 ID 不能下载；无权记录、不属于该邮件的引用或内容完整性校验失败会拒绝。下载按钮取决于安装的管理前端版本与授权菜单；后端 API 可用不等于完整浏览器链已经验收。

若业务需要**主动发送**邮件，在“服务插件设置”配置“默认邮件发送插件”的外部 SMTP 主机、端口、用户名、密码或授权码、传输策略和签名。它通过 Simple Java Mail 向已配置的 SMTP 服务提交验证码或通知；本地 Apache James 收件端口不提供对外发件或认证服务，不能直接填作互联网发信通道。凭据只放在受控配置中，不写入文档、页面备注或日志。

若业务需要 Forward Email 的**第三方中转**，在“邮件中转路由”配置域名、别名及 Email/Webhook 投递目标，再使用“测试配置”“预检”“预检DNS”“同步”或“自动配置”等操作。其供应商凭据、DNS 和回调边界见[邮件中转路由使用指南](?doc=mail-relay-admin)。本地 SMTP 无需创建这类逐别名路由；两种入站方式都能在统一收件箱查看其已保存的邮件。Forward Email Webhook 必须提供 `raw` 原始 MIME，不要配置 `?raw=false`；受签名保护的分组多收件人回调会先校验全部地址对应的受管路由，再逐收件人保存。缺少原文或路由/签名不匹配时明确失败，不能用事件 JSON 代替邮件原文。

工作流通知发到邮箱的基础 HTML、正常登录和任务定位配置见[工作流通知邮件使用指南](?doc=workflow-email-guide)。邮件收件事实、个人消息阅读状态和工单处理状态分别保存。客服邮箱、队列、手动转单、固定联系人、追加消息、外发意图及统一通知步骤见[统一消息与邮件工单使用指南](?doc=mail-ticket-guide)，模块事实和验证边界见[实现说明](?doc=mail-ticket-design)。

## 5. 最小验证与故障排查

1. 用 `dig A example.com` 和 `dig MX example.com` 检查公共解析；预期 MX 优先级为 10、目标为本域名，且本域 A 指向当前服务器公网 IPv4。供应商控制台记录正确但公共 DNS 尚未生效时，等待传播后重试。
2. 检查应用内部监听、Nginx `stream` 片段、Nginx 配置加载情况以及外部 TCP 25 连通性。片段生成成功但外部不通时，优先检查 Nginx include/reload、主机防火墙和云平台入站规则。
3. 用**外部**发件服务向已开通域名发送一封小于大小限制的纯文本测试邮件；在收件箱按收件地址与时间查找。测试地址未匹配联系人时，检查可信域名/路由所属租户的记录；平台共享入口才检查平台未归属记录。
4. 收到 `550` 时检查 Domain 是否可用、是否已开启邮件接收及缓存刷新；收到 `552` 时检查邮件体大小；收到 `451` 时检查应用日志、收件箱持久化依赖与存储故障，待恢复后重试。

更细的部署示例见[本地 SMTP 入站收件使用指南](?doc=local-smtp-admin)。

## 6. 当前测试能证明什么

收件验证已包含真实本机 TCP SMTP 会话与隔离 PostgreSQL 17。通过 Apache James 执行 `EHLO`、`MAIL FROM`、多个 `RCPT TO`、`DATA`，每一步投递后直接核对数据库邮件、私有字节及引用。分层运行事实汇总见[统一实现说明](?doc=mail-ticket-design)。

1. 正常多收件人返回 `250`，每位收件人各有一条邮件并保留原文和附件；未知域返回 `550` 且不入库。
2. 原文与解码资源超限返回 `552`；存储故障返回 `451`，失败地址的邮件与私有字节一并回滚。
3. 普通重投、部分收件人成功后的重投及并发同内容重投复用既有事实，不重复保存邮件和附件。
4. 并发和唯一约束使用 PostgreSQL 验证；正文解码、私有下载归属及控制器暴露面另有分层验证。隔离工单链使用实际生成 CRUD/EntityManager，SMTP 验收保留可控配置及故障适配边界；这些都不代表完整生产 HTTP 过滤器链已验收。合法超过32600字符的正文也已由真实 SMTP 确认完整保存。

这些证据说明本机接收协议和数据库保存路径可用，**尚不能证明公网部署已可用**。当前没有已完成的真实公网域名、公共 DNS、Nginx 加载、云网络 TCP 25 和外部邮件服务投递验收；Forward Email 真实供应商回调也需单独联调。部署后必须执行第 5 节，并从外部发件服务实际投递，核对入库、收件归属、附件下载及重投结果。真实环境仍保留未验状态，直到取得目标站点实际外部投递和访问证据。
