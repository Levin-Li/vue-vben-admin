# 工作流平台使用指南

## 模块与前置条件

后端由 `workflow-api`、`workflow-flowable` 与现有实体/生成服务组成；业务模块只依赖
`workflow-api`，不得直接读取 Flowable `ACT_*` 表。管理端运行时入口为
`/com.levin.oak.base/V1/api/workflow-runtime`。

本工程默认配置 `flowable.database-schema-update=true`、`flowable.idm.enabled=false`；若任一项缺失，启动前分别补入 `true`、`false`，并打印一条列明所补默认值的警告。两项布尔值的大小写不影响判断；合法的 `TRUE`、`FaLsE` 等值会在进入 Flowable 引擎前规范为小写，保证实际建表和 IDM 关闭行为一致。EnvironmentPostProcessor 会在配置加载后、Spring 容器和 Flowable 引擎 Bean 创建前检查配置：IDM 显式配置为非 `false` 时拒绝启动；schema update 显式为 `false` 时只打印包含配置键和启用建议的警告，其它非布尔值直接报错，Flowable 引擎随后可能因缺表或版本不匹配而失败。Flowable 自身使用数据源、版本属性和构件内 SQL 创建或升级引擎表；项目保留历史逐句安装器作为离线分析参考，但正常启动不调用它。已有 `ACT_ID_*` 表不由本项目读取或迁移，平台身份仍使用 RBAC。生产自动升级前须确认目标库、可恢复备份，并在隔离副本预演；源仓库的官方脚本参考（资料未收录在线帮助）不随使用方 JAR 分发。

本项目表由当前环境的 JPA 设置初始化，随后按平台范围幂等创建缺失的模块默认菜单/权限；已有同路径菜单配置冲突时启动失败而不覆盖。生产当前 `spring.jpa.hibernate.ddl-auto=none`，新库的平台实体表仍需显式准备，不能把 Flowable 自动建表当作全部平台数据已就绪。最小验证是在隔离 PostgreSQL schema 中启动引擎，核对基础引擎表与版本属性、`ACT_ID_*` 表未新增，再以同一 schema 重启确认数据保持；配置为 `false` 的告警和 IDM 为 `true` 的早拒绝应分别验证。

已有“开发&工具”“个人&中心”平台目录若只保留旧中文内部名、`NULL` 空权限，启动会只读复用其原 ID，不自动重命名或回填。其它目录及叶页面仍按路径、父级、模块、租户、公开范围、页面来源和真实权限严格核验；冲突错误会指出字段名。需要规范化旧菜单数据时，先核对目标库和备份，再走显式菜单迁移。

本次 6.0 只交付 `schemaVersion=3` 的新定义与独立新库。旧 v2 库、定义和活动实例保留原样，不由 6.0 启动、读取或发布路径迁移；连接含旧定义/实例的库应按前置检查失败关闭。日后若要迁移旧库，需另行指定目标、备份和业务处置范围。

客户端二次开发若需要当前 RBAC 主体，使用公共 `RequestRbacContextService<HttpServletRequest>` 从已审计的当前 HTTP 请求获取，并在匿名或缺少授权时失败关闭。6.0 正式生成的客户端 `BaseController` 不再提供 protected `getCurrentRbacUserInfo()`；扩展类不能从请求字段、Header 或旧基类方法恢复身份。客户端生成的工作流 Case、Dispatch、Run、TaskAttachment 接口全禁，其余五类仅允许受原有权限约束的列表读取；实际路由仍须由宿主显式注册，不能把生成控制器当作业务运行 API。私有附件只走受控任务附件接口，不能通过生成 CRUD 或通用文件 URL 读取字节。

## 流程设计与发布

1. 在“开发&工具 → 流程设计”页按中文名称新建流程，选择受控业务对象并创建草稿。平台生成内部流程与用途标识；同一对象有多个业务方案时须明确选择，主键、标题和可选申请人只按目录明确声明的语义角色预填，不按字段名猜测。业务对象不需要固定状态字段，租户组织由服务端确定。缺少对象读取权限、修订或必要语义字段时，资源保持不可发布，由实施者补齐接入。
2. 配置类型化变量、启动条件、同轮次前置用途及结果动作，再编辑节点和连线。当前支持串行、排他条件、成对并行分叉/汇聚、ALL/ANY 多人审批；不支持任意服务任务或脚本节点。
3. 保存 `schemaVersion=3` 的受限 `flowTree`；根级 `nodes/edges` 不是第二份可编辑事实。开始模拟并检查报告中的失败和未覆盖项。模拟失败回到草稿；修改已测试配置会使原报告失效。普通保存、生命周期和发布均调用受控业务接口，不能通过通用 CRUD 改写版本状态或删除历史。旧 v2 定义不能由普通读取或发布接口隐式转换，本次 6.0 不接管旧库。
4. 仅通过模拟的 `Testing` 版本可发布。发布时部署 BPMN，并将旧 Published 版本转为
   Retiring，数据库局部唯一索引保证一个流程定义只有一个可发起版本。

“审批步骤”“发起规则”“完成后处理”使用中文业务字段和受控选项；实施者才能在展开区查看技术键、原始执行轨迹等诊断资料。流程检查与发布仍以服务端校验、模拟覆盖和固定版本摘要为准，界面预填不扩大字段或动作授权。

标准业务资源若出现多个中文业务方案，原 `readonly-1` 保留已发布定义的运行摘要；新流程需要按类别、标题等字段判断时，选择标明“可按业务字段判断”的 `readonly-2` 方案。需要有权审批人员办理其他拥有者的记录时，选择标明“业务条件与授权审批”的 `readonly-3` 方案；办理人仍须同时拥有该资源的正常详情权限、当前全个人读取权限及对应租户组织范围。主键与拥有者只参与平台归属和关键依据，不是普通业务条件。已发布版本不会因目录新增方案而自动切换。

### 发起入口

已授权业务记录页可就地查看资格并发起。个人中心的“发起流程”页面要求已有“发起业务流程”权限；先列当前可访问且已发布的手动流程，再从有正常列表及详情权限的业务资源中分页选择本人有权记录。页面不要求输入业务类型键、裸记录 ID 或契约版本；选定业务方案后，资格和启动请求都固定其契约版本。自动用途不提供手动发起按钮。页面展示的固定类别拒绝原因可用于处理资料或前置流程，但最终提交会再次核对租户、组织、个人、修订、流程条件、轮次和幂等键。无权、撤权、未知资源或无法证明归属的记录不列出且不能靠伪造 ID 发起；结果以 `business/eligibility` 和 `business/start` 的当前服务端响应为准。

集成页面可调用 `GET workflow-runtime/manualStarts` 获取手动流程目录，再以 `GET workflow-runtime/businessRecords` 传入所选业务类型、契约版本、租户和 `pageIndex/pageSize`（每页最多 50）选择记录；关键词最多 128 字。两接口只交付有权目录及记录的最小摘要，不返回任意业务详情字段。无效范围、未知资源、超限分页或权限撤销均拒绝/隐藏，不能把空列表解释为具有发起权。最小验证应以两个当前主体分别访问同一租户下各自拥有和无权的记录，核对列表不越权、伪造 ID 的资格和启动被拒绝，以及合法记录最终只能创建一个用途实例。

### 节点配置契约

每个 `userTask` 必须至少配置固定候选用户、候选组或当前业务契约公开的受控 `approverResolver`。固定候选组使用身份桥接前缀，例如
`role:<角色编码>`、`org:<组织ID>`、`tenant:<租户ID>` 或 `type:<用户类型>`。空审批人不会
自动放宽为所有用户；显式 ESCALATE 配置只在真实主候选不可用时使用指定升级候选。静态 ALL/ANY 使用明确用户列表，不混用候选组；动态 ALL/ANY 从进入节点时解析的完整有效用户集合建立独立席位，至少需要两人，不因后续撤权自动降低阈值。节点可保存 `actions`、可读/可写/必填字段与 `formAction`。表单保存动作、字段类型和当前业务权限必须同时允许写入。`stepUpVerifyTypes` 支持 `Captcha`、`Hmi`、`Sms`、`Email`、`Mfa`。

动态审批节点只保存 `approverResolver: {"key":"request.applicant","parameters":{}}` 这类目录引用，不接收任意表达式、类名或脚本。设计者必须在草稿中明确选择公开该解析器的业务契约版本；当前 `workflow-request@2` 提供申请人样例，已有 `workflow-request@1`、`workflow-expense@1` 不被自动升级。保存、模拟、发布会复核解析器及参数权限；运行时先用当前业务对象和范围解析、校验账号/自审，再冻结本次分配，办理时重验当前资格。解析器返回重复、无效或过量标识会拒绝；空结果按节点配置拒绝或升级。升级任务仍须位于冻结名单并保持当前升级主体资格。模拟只使用契约注册的纯数据样例，不调用真实解析器或业务副作用。

二次验证挑战和校验绑定任务、动作、当前会话用户和表单摘要；验证码、密钥和原始表单内容
不会被写入流程变量或日志。
扩展 `WorkflowRunObserver` 的业务模块须分别实现 `inspectTask` 与 `validateTask`：挑战准备只调用前者，在当前范围内只读核对任务/表单/修订，不取得业务写锁；正式完成仍通过后者按对象→轮次锁定并重读任务。旧实现的默认 `inspectTask` 会回退到 `validateTask` 以保持接口兼容，但若要在有外层事务的二次验证页面避免读写锁竞争，必须覆盖只读钩子，不能仅靠方法名称或只读注释推断无锁。

节点附件走 `workflow-runtime/attachment/upload`，只接受当前可办理任务与当前业务对象均获授权的主体；单文件最多 5 MiB、同任务最多五件。上传只返回私有附件 ID，不返回可公开访问的 URL；刷新待办可经 `attachment/pending` 找回本人当前任务24小时内待提交附件，误传可用 `attachment/deletePending` 撤销以释放配额，二者均重新校验当前任务及业务对象范围。成功办理时将 `attachmentIds` 随动作提交，服务端再次核对同任务、同上传者、同租户组织、未绑定与 24 小时有效期，并在同一事务中与审批意见及引擎推进一起绑定。未绑定上传不进入历史。已绑定附件只能经 `attachment/list` 读取有界最小元数据、经 `attachment/download` 重新验证当前业务范围与流程参与资格后强制下载；不能把旧的 `/fss` URL 或 `FileRes.paths` 当作受保护附件。生产环境须先完成 10.3 所述显式平台表迁移，本地 JPA 建表不代表存量库已就绪。

## 执行与授权

业务模块实现 `WorkflowBusinessAdapter`，注册版本化能力目录、带范围读取及受控业务动作。业务页面通过 `workflow-runtime/business/start` 提交对象引用、用途与幂等键，由编排服务选择定义和建立运行关联；不要从普通业务页面直接调用底层引擎启动接口绕过关联。
当前用户待办、已办、我发起、抄送分别由 `WorkflowTaskService.pageTodo/pageDone/pageStarted/pageCopied` 的受控分页接口读取，完成动作使用 `complete`。四个 HTTP 列表各自接受 `size`（默认 20、最多 50）和 `cursor`，返回 `items/nextCursor/hasMore`；撤权过滤后不返回引擎原始总数，空页有继续游标时仍可翻到后续授权历史。页面刷新从第一页开始；任务到期检查按 25 条一批遍历活动任务，不因前一批已处理而遗漏后续任务。执行时会重新从当前 RBAC 解析用户、角色、组织、租户和类型主体；
流程候选主体不得作为独立身份目录使用。

前端包：

- `@levin/bpm-designer`：定义编辑与低代码流程契约。
- `@levin/bpm-runtime-ui`：任务展示组件与 `WorkflowRuntimeService`，包含待办、已办、
  完成动作的 HTTP 封装。

节点必填表单、二次验证和通知路由均以服务端流程版本配置为事实源；浏览器不得自行放宽
审批动作或授权结果。当前不支持高级表达式：设计 JSON 中包含 `${`、`#{`、Groovy、
SpEL 或 JavaScript 的字段会在转换和发布前被拒绝，而不是由浏览器或 Flowable 直接执行。

### 飞书、企微和钉钉机器人通知

工作流通知路由的渠道可选择 `FeishuWebhook`、`WeComWebhook` 或 `DingTalkWebhook`。机器人 `targetConfig` 只保存受控逻辑目标，例如：

```json
{ "configRef": "tenant:<实际租户ID>:review" }
```

逻辑目标必须属于流程的实际业务租户；平台目标 `platform:<name>` 不能作为租户工作流的默认群回退。当前租户的 `RobotTextMsgSendPlugin` 设置使用 `targets["tenant:<实际租户ID>:review"]`，每项声明对应 `platform`、`urlRef` 及可选 `signingSecretRef`。URL引用为 `env:WORKFLOW_ROBOT_TENANT_<租户ID UTF-8 SHA256大写64位>_<NAME>_URL`，签名秘密采用同作用域的 `_SECRET`；只有部署环境保存真实Webhook与秘密。具体三家配置和平台命名空间示例见三家群机器人Webhook使用指南（资料未收录在线帮助），安全协议边界见三家群机器人Webhook设计说明（资料未收录在线帮助）。不要把真实URL、key/token或secret写入路由、插件设置、前端表单和日志。

通知在工作流消费事务中固定接收人与渠道意图，`Applied` 仅表示可靠入队；实际发送由统一渠道调度完成。同一事件同一群逻辑目标只投递一次。站内渠道进入个人消息中心，不创建用于提醒的公告。邮件采用安全HTML与纯文本替代，办理链接按当前登录与任务/业务权限重新校验，操作说明见[工作流通知邮件使用指南](?doc=workflow-email-guide)。

三家机器人只发送安全文本摘要；生产连接固定经校验的公网IP，保留官方主机的SNI及证书验证，禁止重定向并限制完整执行期限与请求/响应字节。飞书只认数值 `code=0`，企微与钉钉只认数值 `errcode=0`，不能以HTTP成功代替业务确认。明确拒绝、可重试失败及 `Unknown` 分别进入统一审计；结果未知不盲目重发，须由有权人员先核验未受理，再独立重试。

本机协议与隔离数据库验证不能证明真实群发送成功；实际供应商群、签名/关键词/IP安全设置和部署网络仍须在获得授权的专用测试群中验收。当前未完成三家真实群联调。

## 多阶段、重提与办理轮次

同一对象可以配置多个用途。依赖只接受同对象同轮次、最新有效且业务效果 Applied 的前置结果；Rejected、PendingEffects 或旧轮次不能代替 Approved。自动用途必须显式选择事件与受限服务主体，普通字段变化没有业务事件接入时不会自动发起。业务模块需要对象变化唤醒时，先发布新的能力契约版本并在 `eventTypes` 列出稳定事件键；其业务服务应在保存业务修订的同一数据库事务内，以服务端确认的主体和当前对象修订调用 `BizWorkflowRuntimeService.emitEvent`。不得给已发布契约版本直接追加事件类型，也不得把客户端提供的事件主体或修订当成可信事实。当前内建 `workflow-request@1/@2` 未公开对象变化事件；流程结果事件仍由工作流平台自身持久化投递。

业务面板展示资格和安全的阻断原因，发起时服务端再次校验。运行记录分别展示执行状态、结果和业务交付状态；看到引擎结束不代表业务已写入。结果交付恢复使用独立 `business/retry` 权限，并恢复原交付而不是重新发起。

`business/roundState` 使用明确 `contractVersion` 只读返回当前真实 `revision`、`currentRoundId`、`active`、`reasons` 和 `resubmittableRunIds`。新轮次通过 `business/newRound` 提交 `contractVersion`、`expectedRevision`、`expectedRoundId`、`idempotencyKey` 与业务引用；仅无活动或待交付实例时允许，历史保留且旧轮次前置不再放行。

拒绝、撤回或终止后的再次提交使用独立 `business/resubmit`，引用当前轮次最新且效果已应用的失败尝试，重新评估当前发布版本与全部条件。普通 `business/start` 不能手动绕过事件模式。宿主必须提供独立权限和明确确认操作；网络失败应保留幂等键，不把技术重试转成新业务尝试。接口实现和浏览器验证仍以当前交付批次证据为准。

重提命令在新轮次命令字段之外包含 `purposeKey` 和 `sourceRunId`。来源采用历史响应的 `runId`，不使用引擎 `instanceId`，且必须出现在 `resubmittableRunIds` 中；这个只读许可不替代提交时的重验。服务端以完整命令摘要绑定幂等键，技术重放即使遇到后续修订或新轮次也只返回原结果，同键不同参数拒绝。新轮次返回新轮次字符串，重提返回实例响应。对应独立写权限为 `WorkflowRuntime:业务数据-工作流运行时::开启业务流程新轮次` 和 `WorkflowRuntime:业务数据-工作流运行时::重提已结束业务流程`。

## 多节点登录会话

工作流待办、附件和审批动作每次都重新核验当前登录主体。多节点部署时，宿主必须让 Sa-Token 使用同一个受控 Redis 实例、数据库和键前缀；不能把各节点自己的内存会话当成共享身份。当前启动应用通过 `spring.data.redis.*` 提供 Spring Boot 4 的 `RedisTemplate` 连接，默认配置把既有 `spring.redis.host/port/database` 映射到同一连接。仅设置非空的既有 `spring.redis.password` 时，公共模块会在未显式设置新密码的前提下将它传给 Spring Data Redis；显式 `spring.data.redis.password` 优先，若两个客户端分别配置密码须保证连接同一 Redis 时取值一致。无密码环境不写入密码属性，避免无效 AUTH。同一个 PostgreSQL 身份库的应用节点须共享 Redis 命名空间；不同身份库的管理/客户端应用须分配不同 Redis 数据库或经验证完全隔离的键前缀，避免令牌和插件目录缓存跨库混用。当前客户端默认使用 DB3、测试 DB5、生产 DB6；管理端对应默认 DB0、测试 DB4，部署覆盖时仍须核对实际地址、凭据和隔离数据库。Redis 不可用或认证存储未就绪时应停止登录能力，不能回退为各节点独立的内存会话。请求进入业务控制器前若租户、URL 访问控制规则或签名随机串、客户端应用认证、CPU 限流配置及 MVC 二次规则读取所需的安全存储失败，过滤器或拦截器返回脱敏 HTTP 503/业务码 503 且不执行业务；恢复后重新读取当前授权和规则。生产监控应将连续 503 视为安全依赖故障，不以 404 或空规则掩盖。

### 生产数据库与跨源配置

管理端和客户端以 `prod` profile 启动时，部署环境分别注入 `PROD_DB_URL`、`PROD_DB_USERNAME` 和 `PROD_DB_PASSWORD`；URL 指向本应用经确认的独立 PostgreSQL 目标，密码从受控密钥存储注入，不写入镜像、配置仓库、请求或日志。任一变量缺失或空白时应用启动失败，不使用包内默认 localhost 数据库。两个应用连接不同身份库时，还要按上节隔离 Redis 命名空间。

管理页面与 API 经同一可信代理域名访问时，无需设置 `app.cors.allowed-origins`，默认拒绝跨源读取。确需跨源浏览器访问时，以逗号分隔的**精确 HTTPS Origin** 配置该属性，例如 `https://console.example.test`；不得使用通配、`null`、路径或 HTTP 生产来源。允许来源仅限 GET/HEAD/POST/PUT/PATCH/DELETE；动态验证码的 `DVC-<令牌>` 请求头只对该精确来源的预检回显。未知来源预检和实际跨源请求均拒绝，配置无效则启动失败。CORS 不代替 Cookie 的 Secure/HttpOnly/SameSite、状态变更的 CSRF 防护或代理 Host/TLS 校验。

最小验证应在目标代理上分别发送同源请求、已配置 Origin 预检与实际请求、未知 Origin 及 `null` Origin 请求，检查允许来源的响应头与拒绝业务码，并确认未提交任何状态变更；再以缺少一项生产数据库变量的隔离启动验证失败关闭。源码级和本机回环结果不能替代生产代理、浏览器与数据库现场验收。

最小验证：在节点 A 通过正式挑战登录，同一令牌访问 A 与 B 的 `rbac/userInfo` 均应返回相同主体；在 B 退出后，同一令牌访问两节点均应被拒绝。可在具名隔离库与两个本机测试进程上运行 `scripts/workflow-session-cross-node-e2e.mjs`；脚本不记录令牌。此验证不能替代跨租户数据范围与权限撤销矩阵。

## 最小接入验证

从有权限的原业务页创建对象，在设计器绑定公开字段、保存、模拟并发布，换合法审批用户办理，核对业务结果与三种状态。再建立依赖用途，验证前置运行中/拒绝不解锁、Applied 才能发起；验证跨组织访问、撤权、非法表单、重复提交及业务动作失败均不产生越权副作用。完整验收必须覆盖真实数据库和浏览器，包构建通过不能替代上述步骤。

本批集成的在线模拟仅解释注册期冻结的纯数据 fixture，不在线调用真实适配器的 `load/execute/validate`。只读校验器使用声明式 `rule`，不执行任意 Java 回调；这是有预算的结构规则解释，不是任意代码的强制中断。模拟报告证明配置与 fixture 的一致性，真实业务动作仍通过独立授权的 HTTP/数据库验收验证。该扩展的完整集成验收以本批实际记录为准。

## 实例流程图与真实轨迹

待办、已办、我发起的流程及成功处理动作的响应提供 `processDiagramNodes`、
`processDiagramEdges` 和 `timeline`。节点及连线来自该实例固定的定义版本，后续发布版本
不会替换历史图。节点状态为 `active`（当前活动）、`completed`（已经过）、
`pending`（尚未到达）、`cancelled`（已取消或退回）、`skipped`（实例结束时未经过）。
前端必须按连线的 `source`、`target` 绘图，不能按节点数组顺序补造串行箭头。

轨迹使用实际引擎起止时间、活动记录和平台动作记录，时间为 ISO8601 UTC；退回后的
同一节点会保留多次进入记录，转办不会标记节点完成，会签中某个任务完成也不代表整个
节点完成。`actor` 仅提供记录中的用户标识，`comment` 仅提供显式审批意见；不返回原始
业务表单、校验摘要、验证码、候选名单或分支条件。超过 1000 项时返回最近 1000 项并设置
`timelineTruncated=true`，界面必须提示截断，原始历史不会被删除。

这些信息沿既有任务参与者、发起人和业务对象范围校验返回，没有新增接受裸实例 ID 的图
或轨迹查询接口。单纯能读取业务对象的历史列表不会自动获得其它流程参与者的引擎轨迹。
业务结果装饰器仍须先重新验证当前对象权限，再保留引擎提供的展示字段。

设计者可通过 `WorkflowDefinitionVersion/simulation-runs` 分页查看当前版本的模拟历史摘要，通过 `simulation-run` 查看覆盖报告和虚拟路径，通过 `delete-simulation-run` 受控软删除单条证据。接口先按当前租户、组织与设计权限验证版本，再校验记录归属；通用模拟 CRUD 删除继续关闭。删除当前通过记录会撤销发布证明，旧记录不能作为回退证明。模拟轨迹只保留有界样本索引、经过的节点/连线和任务键，不含真实业务字段或外部调用。

工作流抄送须由活动实例的真实发起人显式发送。`workflow-runtime/copy-recipients` 只为指定实例和不少于两个字的搜索词返回当前业务可见的接收人，`workflow-runtime/copy` 在同一事务里逐个重验接收人并持久化专属 Flowable 身份关系；发送者只需工作流相应权限，不必拥有系统用户管理列表权限。接收人从 `workflow-runtime/copied` 查看只读实例图、状态与轨迹，不获得办理任务资格。租户/组织、业务访问或 API 权限被撤销后，重新查询不得保留旧可见内容；通知投递与审批候选不会自动形成抄送。

办理页准备二次验证后，图片验证码展示服务端的有界 base64 GIF，人机验证复用公共行为挑战组件；短信、邮箱及 MFA 接收提示并填写对应码。切换任务、动作、验证类型、审批意见或表单字段会废弃旧挑战和输入；提交仍由服务端按任务、动作、表单摘要与业务修订校验，页面不得执行挑战响应中的任意 HTML、脚本或远程题面地址。隔离开发环境的 mock 图片验证码不返回可读图片，不能用它证明真实图片办理交互已完成。

流程申请可同时接入 `workflow-request@1` 与 `@2`。原业务页从当前租户受权能力目录列出契约版本；通用发起资格仅展示一次，每个版本的历史和重提单独使用该尝试冻结的 `businessContractVersion` 与服务端 `roundState`，不能用 @1 的轮次许可代替 @2。切换组织或目录权限变化会清空旧版本面板，写命令仍由服务端再次校验。
