# 性能监控使用指南

## 入口与前置条件

在管理端“运维&审计”分组打开“性能监控”。需要登录，并具备 `com.levin.oak.base` 域下“系统数据-每日访问统计 / 查询排行榜”权限。页面仅读取统计数据，不提供新增、修改或删除操作。

后端管理 API 与客户端 API 均需启用请求采集，且共享计数存储和日统计数据库可用。服务端按当前用户的租户授权范围返回结果，页面不能通过改写参数扩大范围。

页面按“网络访问、OS、Java、数据库”四个标签展示。顶部统计日期对四个标签均生效；切换标签复用已取得的数据，不会再次请求。仅“网络访问”标签提供前端／后端访问入口选择，该选择不用于拆分节点性能数据。

## 查询方式

1. 在页面顶部选择统计日期；日期按北京时间归属，默认显示北京时间当天。页面可见且选择今天时每 5 秒向后端重新查询实时统计；历史日期不自动查询。点击“刷新”可立即重新查询。
2. 在“网络访问”标签选择“后端（管理 API）”或“前端（客户端 API）”。该标签展示整体访问、IP 与用户访问量前 20 名，以及按平均响应时间排序的 URL 前 20 名。
3. “OS”标签查看主机 CPU、物理内存、磁盘容量与利用率；“Java”标签查看进程、JVM 堆、线程池和 GC；“数据库”标签查看连接池与 PostgreSQL 健康指标。

每行的“累计访问次数”为所选日期、入口、租户及该 IP 或用户的访问次数；“最高并发次数”为同一维度当日同时在途请求的峰值。一次已认证请求可同时计入 IP 行和用户行，两个榜单不能相加为总访问量或整体并发。匿名请求只计入 IP 榜。用户维度值是稳定用户 ID。

“当日整体访问”单独展示该租户与入口的累计访问次数和最高并发，不从 IP 或用户榜单相加。慢 URL 榜显示去查询串后的路径、请求次数、平均响应时间和最长响应时间；平均耗时按有效样本计算。路径可能含业务标识，只有获授权人员可查看。

若 IP、用户或 URL 维度达到每天的采集容量上限，或 Redis 等采集环节出现故障，页面会显示“本日维度统计不完整”警告。IP、用户和 URL 的前 20 名可能缺少部分访问或维度值；整体访问独立统计，但 Redis 故障时同样需核对日志，不能仅凭榜单之和判断总体是否完整。

“OS”按节点展示当天有效样本的平均 CPU、物理内存与磁盘使用率；磁盘总量与剩余量取最近有效样本。“Java”展示当日平均 JVM 堆使用率及峰值。“数据库”展示连接池活跃、空闲、等待、上限的最近有效样本，连接池活跃与等待另显示当日平均和峰值。节点指标是全局数据，与前端/后端入口选择无关。不可用指标显示“—”，不当作零。

节点详情还展示当前与当日峰值线程数、可识别的 Spring 线程池（逐池列出 Bean 名及活跃线程、池大小、容量、等待队列）、当日 GC 次数与耗时。Full GC 只有采集器可可靠识别时才显示数值，否则显示未知。数据库健康项展示 PostgreSQL 当前连接数、当日事务提交与回滚、缓存命中率、死锁及临时文件大小；采样不可用时不会把未知量当作零。Java 进程的 CPU、运行时长、当前堆使用字节与上限属于最近快照，与当日平均值分开标注。

## 数据更新与异常

排行和累计值平时保存在 Redis；后端接口请求完成时顺带判断当前上海时间小时是否已成功写入，未写入时将页面所需榜单与概览覆盖到数据库中当天唯一的一条 JSON 日快照，跨天后的首次请求补写前一天最终值。无请求时不运行数据库写入定时任务。当天页面读取尚未同步的 Redis 实时值，并在页面可见时定期更新；历史日期读取已保存的日快照。查询请求本身也会被计入访问量，并可能顺带触发小时快照。无数据时页面显示空状态；无权限或查询失败时显示错误提示。共享存储或持久化故障期间的数据可能不完整，应结合后端日志核查。

最小验证方法：授权用户选择已有流量的日期和入口，核对 IP 榜与用户榜各自按访问次数降序、最多 20 行，URL 榜按平均响应时间降序、最多 20 行；确认整体累计与峰值独立显示，主机指标按节点分行。再选择无流量日期，确认显示空状态。
