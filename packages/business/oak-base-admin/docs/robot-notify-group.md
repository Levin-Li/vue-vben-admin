# 机器人通知群管理页使用指南

## 入口与前置条件

在基础框架的“基础&设置 → 机器人通知群”打开页面。需要当前账号拥有“业务数据-机器人通知群”的查询权限；新增、编辑、删除分别还需对应接口权限。Webhook 地址是发送凭据，前端只向拥有平台角色或租户管理员角色的用户提供维护控件；组织管理员可以按后端数据范围查看共享配置，但不能仅凭组织角色查看或修改明文地址。服务端权限与 `@DataMasking` 是最终边界。

## 配置步骤

1. 选择适用租户与组织。平台公共或组织公共配置的归属由有权管理者按服务端规则设定；租户用户的租户范围由服务端注入，页面不可信任手工传入的其它租户 ID。
2. 填写名称、最多 384 字的业务类型、描述，并决定是否组织共享。未启用的待配置记录可暂不填平台与地址；启用前须选择飞书/企业微信/钉钉平台，并填写最多 768 字的官方 HTTPS Webhook 地址。
3. 保存后在列表按名称、业务类型、平台、归属和启用状态查找。名称和业务类型是后端当前提供的精确查询条件；页面不假造模糊查询参数。

同一 `bizType + orgId + tenantId` 只允许一条记录，平台类型和 Webhook 地址不参与唯一身份。业务发送按这三项字段找最匹配的已启用配置，精确范围优先，适用的公共配置回退。仅在发送时完全没有适用记录，业务服务才自动创建名称为“业务类型-自动创建”的未启用待配置记录并返回未发送结果；已有禁用或未配齐记录不会再创建，供后续补齐字段；调用方发送文本无需指定平台。页面没有直接发送按钮；发送由受信任的业务服务调用。平台或租户管理员编辑地址时以密码控件输入，列表、详情、查询和导出不展示完整 Webhook URL。

## 安全与结果

页面只接受所选平台官方主机的 HTTPS URL；服务端发送层再次检查主机、路径、公网解析和 TLS。当前实体没有单独签名密钥字段，要求飞书或钉钉加签的机器人不能仅靠此 URL 完成发送。保存失败保留输入并展示错误；成功表示配置记录已写入，不代表发送或群成员已阅读。公共记录空租户/组织的唯一语义依赖 PostgreSQL 15+ 的显式 `NULLS NOT DISTINCT` 约束脚本。

最小验证：以有权账号打开页面，新增一条测试配置，确认列表无完整地址；编辑后确认范围和状态正确。以普通查看账号确认地址和维护入口均不可见；另检查前端路由定向测试、类型检查和浏览器控制台。测试中只使用虚构 Webhook，不向真实供应商发送。
