# 客户页面使用指南

组织、负责人与权限配置见[主档多方组织与负责人使用指南](external-org-master-ownership.md)。

## 入口与前置条件

启用 `@levin/oak-base-admin` 后，在后台“客户&伙伴 → 客户”进入 `/clob/V1/Customer`。当前用户需要客户管理权限及对应租户、多方组织或负责人数据范围。法律主体允许建档时暂缺，客户页面不会代为创建法律主体。

## 操作与字段

普通“新增”填写租户内唯一的客户完整名称、客户类型，并只选择商务对接部门和对接人；“新增我的客户”由服务端将当前用户及其组织写入主体方字段，两种普通建档均不创建外部组织或账号。需要同时创建主体、外部组织和首用户时使用独立的“快捷添加”。编辑时各参与方仍按权限管理。

直接客户不提交渠道伙伴 ID；渠道客户须选择有权访问的启用渠道伙伴。法律主体允许后补，已绑定后不可更换；客户类型和渠道关联创建后不可更改。客户有独立 ID，同一法律主体可关联不同客户和合作关系。

联系人姓名、电话、邮箱，以及等级、行业、机密等级、分组、投资关系和有效期均属于客户资料；修改客户联系人不会同步法律主体联系人。客户还可按资料权限维护对方联系人、银行账户、开票和收寄信息，未填写的资料保持为空；原联系人字段继续独立使用。关联法律主体及敏感资料与客户记录权限分别校验，未获相应读写权限时不可查看或提交。

完整名称用于客户合作关系在租户内的唯一识别，并作为列表和候选选择的主名称；简称、行业、投资关系、分组和有效期可按需维护。

保存使用 `/Customer/saveCustomer`，更新使用 `/Customer/updateCustomer`，列表和详情使用 `/Customer/list`、`/Customer/retrieve`。默认删除与批量写入入口不开放。服务端拒绝越权访问、非法引用、不可变关联变更及过期版本，前端只读不能代替服务端校验。

最小验证：创建直接客户和渠道客户，检查独立客户 ID 与自动生成的主体组织；为各方指定跨部门负责人，确认候选不被同方组织限制；切换组织不清除负责人。修改客户联系人后核对法律主体未变。使用无关用户、跨租户引用和过期版本验证拒绝结果。
