# 企业平台配置指导

本模块的服务插件设置和租户插件设置弹窗会从后端供应商目录读取 `onboardingGuidance.markdown`。点击弹窗右上角“配置指南”，在当前弹窗内部右侧覆盖展开 Markdown 手册；原弹窗继续用 `configEditor` 对应的 JSON Schema 编辑配置。指南默认隐藏，未声明 Markdown 的供应商不显示入口。指南中的 `{{callbackUrl}}` 和 `{{inAppCallbackUrl}}` 由当前站点与实际 OAuth API 路径生成，可在指南中复制；平台侧的回调地址仍须自行登记并通过实际授权验证。

## 使用步骤

1. 通过已授权的服务插件配置入口，选择第三方 OAuth 登录插件及具体供应商。
   默认目录名称为英文编码时，配置页以中文显示飞书、企业微信和钉钉；已由管理员改名的供应商保持原名称。供应商可按中文名或编码搜索，编码仍用于接口和回调。
2. 先按指导在开放平台创建企业自建应用，复制应用标识，并让部署管理员保存应用 Secret；表单只填写 clientSecretRef 的 env:NAME 引用。
3. 填写当前租户中无上级且启用的公司根组织 companyRootOrgId，与本公司的组织同步配置一致。企微另填写 Agent ID。
   飞书和企微表单显示各自的 App 内网页回调，钉钉表单显示企业 Corp ID；钉钉不会显示企微 Agent ID 或飞书/企微的网页回调。
4. 从右侧指南复制回调地址，在平台登记并填入 redirectUri。反向代理部署使用员工实际访问的公开域名。
5. 按指导配置应用可用范围及登录用户信息权限；组织同步的部门和成员读取权限按需另行开启。

Markdown 指南只是配置说明，不会替代服务端验证；不能证明部署变量存在或平台已批准权限。公司根、引用值、回调匹配及账号资格由后端在保存或授权、绑定、兑换和同步时复核；后台角色由本系统管理，授权登录不自动授予管理员角色。

## 集成与验证

后端需要返回供应商 code、configEditor 和 onboardingGuidance.markdown；新增供应商只需声明 Markdown 指南，无需改前端供应商编码分支。后端支持的三个企业编码必须与 OAuth 回调编码一致。调用方沿用本模块公开配置页面，不自行拼接授权地址或解析 Secret。

验证应覆盖打开弹窗、展开右侧指南、切换供应商、复制回调与关闭后切换其它页面。真实平台登录及组织同步须使用已授权的企业测试应用；本地表单检查成功不能替代联调。

## App 内网页免登配置

开启 enableInAppLogin 前必须开启基础登录 enable，配置公司根和密钥引用。飞书、企微复制界面单独显示的 `/oauth/inApp/callback/平台编码` 地址至 inAppRedirectUri，并登记平台网页授权回调与可信域名；浏览器 redirectUri 不被替换。钉钉使用 JSAPI 授权码，需填写真实企业 corpId（不是应用 clientId）。生产采用员工实际访问的 HTTPS 站点。

群消息链接只是业务导航，身份由容器授权和后端核验取得。平台应用可用范围、容器支持及站点域名必须有效；未绑定用户先本地登录后主动绑定。已有有效会话不自动切换，失败停止自动重试。

手机号不是基础免登必需项，也不保证返回。飞书另需 contact:user.phone:readonly；企微敏感流程 snsapi_privateinfo 需用户确认、user_ticket/getuserdetail 和手机字段许可；钉钉另需 Contact.User.mobile。三者都不得用手机号自动合并本地账号。

## 回调绑定与兼容边界

飞书、企微的绑定回调 GET 不要求浏览器提供后台 Authorization。返回本地页使用短效一次性中间票据，页面先清理查询参数，再由当前已认证用户 POST 完成绑定；不得把本地 JWT 加到 URL。应用配置指纹变化会拒绝尚未兑换的事务，创建端内事务受共享 Redis 租户配额限制。

飞书端内采用官方 v3 token 协议及 SDK 用户信息读取。SDK 2.8.5 的 v3 token 方法在 JDK 25 存在 HashMap 私有字段反射兼容问题，因此仅该交换方法使用有界的固定官方 HTTP 适配，不引导添加全局 add-opens 参数。
