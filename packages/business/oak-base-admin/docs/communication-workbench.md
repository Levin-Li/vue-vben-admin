# 邮件、个人消息与工单工作台使用指南

## 安装与入口

通过 `@levin/oak-base-admin` 公开入口启用 `createOakBaseAdminModule()`，并使用当前后端授权菜单及页面路由映射。宿主在 `configureAdminApplication` 中注入本包 API 入口导出的 `userMessageService`；框架接入方式见 `@levin/admin-framework` 包内 `docs/personal-message-integration.md`。独立页面不会注册私有邮件文件、通知事件、投递尝试或工单消息的通用 CRUD。

| 页面 | 地址 | 业务分组 |
| --- | --- | --- |
| 我的消息 | `/clob/V1/MyMessages` | 个人&中心 |
| 收件箱 | `/clob/V1/Inbox` | 应用&接入 |
| 支持邮箱受理规则 | `/clob/V1/SupportMailboxRule` | 应用&接入 |
| 工单受理队列 | `/clob/V1/TicketQueue` | 客户&伙伴 |
| 客服工单 | `/clob/V1/Ticket` | 客户&伙伴 |
| 通知投递 | `/clob/V1/NotificationAudit` | 运维&审计 |
| 工作流通知路由 | `/clob/V1/WorkflowNotificationRoute` | 开发&工具 |

菜单、方法权限和服务端支持事件共同决定操作。消息摘要不授予来源访问权；服务端每次读取、下载或写入均重新检查当前身份、租户、组织及业务范围。前端地址或隐藏按钮不能替代这些校验。

## 个人消息与公告来源

消息页使用当前登录身份的服务端分页、未读筛选及未读总数。打开列表、详情或来源不自动标记已读；使用单条或当前页批量已读按钮提交 `{ids:[...]}`，每次最多100条。已读时间由服务器返回，工单、邮件和公告业务状态保持独立。

公告提醒进入 `/clob/V1/MyMessages?noticeId=<公告标识>`，调用 `Notice/myDetail` 读取本人受众快照及当前资格允许的最小展示内容；普通用户不通过管理公告列表或通用详情读取正文。来源失效、无权访问或身份范围变化时，页面清空旧正文并显示不可访问状态。HTML隔离在没有脚本及同源权限的 iframe；文本、Markdown和配置JSON只读展示。

工作流来源使用服务端持久化的 `{kind,id}` 目标，固定进入 `/clob/V1/MyWorkflow?taskId=...` 或 `?instanceId=...`，普通登录保留定位参数。邮件与工单分别进入固定页面的 `?id=...`；不使用摘要中的任意URL，不从业务实例标识猜测工作流任务。

## 队列与支持邮箱配置

先在工单受理队列页选择已授权受理组织，填写同范围唯一的队列编码和名称，选择有效用户或角色作为处理范围。保存和启停使用独立业务命令；编辑或启停必须回传读取时的版本。没有对应操作权限时不显示按钮。

在支持邮箱页选择同一授权组织，配置完整邮箱地址、入站通道和来源。本地SMTP引用已开启收件的域名；Forward Email引用已同步并匹配邮箱的路由。选择已启用队列、可选默认处理人、优先级以及可选受控外发配置引用。外发引用只表示服务端已授权配置，不能填写SMTP主机、口令或任意收件地址。队列搜索按编码查询，主体和入站来源选项由当前范围的服务端接口提供。

新邮箱规则默认停用。修改规则须先停用；启用动作重新核验来源、队列和处理人。停用后邮件仍可进入授权收件箱，但不自动建单。版本冲突、来源无效或范围不符时，刷新后重新核对配置，不通过普通更新覆盖状态或版本。

## 工作流通知渠道与群目标

工作流通知路由使用实际业务资源的查询、新增、更新、删除权限，更新绑定读取时的版本。可按流程标识、定义版本、BPMN节点、事件和优先级配置；事件仅为 `TaskCreated`、`TaskReminder`、`TaskDeadline`、`TaskProcessed`。渠道来自服务端枚举：站内、邮件、飞书 `FeishuWebhook`、企微 `WeComWebhook`、钉钉 `DingTalkWebhook`。

站内与邮件的接收人由工作流引擎和服务端精确受众决定，页面保存空目标对象，不提供任意外部邮箱、角色或用户列表。三家群机器人仅填写与路由实际作用域匹配的逻辑 `configRef`：平台路由使用 `platform:<name>`，租户路由使用 `tenant:<实际租户>:<name>`。引用总长最多128字符；名称须以字母或数字开头，最多64个字母、数字、点、下划线或短横线；平台机器人路由不匹配租户工作流，租户流程必须使用实际租户所属的路由和目标；引用前缀不自动改写，不能输入Webhook URL、token、secret或robotType。

群目标的HTTPS地址与可选加签秘密由服务端部署秘密引用解析；服务插件配置表单消费后端JSON Schema，不能把实际秘密值放进路由、浏览器或消息摘要。路由页面显示固定安全通知模板，不接受自定义HTML或未声明templateCode。匹配条件只保存有限的精确值JSON，不在浏览器执行表达式或脚本。

切换个人渠道与机器人渠道时目标必须明确替换；邮箱/站内目标不能保留旧群引用。服务端拒绝跨作用域配置或未知字段时重新授权读取事实，不能通过请求迁移路由的租户和组织归属。入队、渠道受理及结果不明通过统一投递审计追溯，修改路由不改写已产生的事件或尝试历史。

## 邮件详情与转工单

收件箱支持精确主题查询和服务端分页；固定 `?id=...` 只定位待授权的来源。详情展示纯文本正文和会话头，也可显式查看HTML源文本。原始MIME预览最多128KB，完整内容及关联附件通过携带正常登录鉴权的私有下载请求取得。下载绑定来源收件标识和文件标识，不使用公开上传地址或URL。

转工单前选择授权受理组织以及匹配实际收件地址的启用规则；规则选择支持分页。提交只包含来源邮件和规则标识，负责人、状态、身份和附件关系由服务端决定。成功后进入既有或新建工单详情；失败保持邮件事实，并提示核对范围与受理规则。

## 工单会话、状态动作与邮件回复

工单页只提供授权查询及专用动作，不提供通用新增或任意状态编辑。分派、开始处理、解决、重开、关闭仅在服务端返回相应支持事件且当前方法权限满足时展示。提交回传当前工单版本，服务端完成状态迁移和追加日志。流程日志按时间排序，展示实际操作人、状态迁移与非空说明。

会话按服务端稳定分页显示，截断正文可通过当前工单的专用消息详情读取。来源邮件和私有附件仍独立授权。附件下载绑定工单与不可变来源关系；回复附件只能选择该工单已关联的私有入站附件，本入口不上传任意新附件。

外发前核验现有固定联系人，提供无机密核验记录标识；浏览器不能修改该邮箱。回复只提交纯文本、关联附件及一次明确回复的稳定键，不提交From、To、抄送、SMTP或会话头。首次请求固定回复键和内容，技术重试复用原请求。正文最多十万字符，附件最多二十件。

外发结果区分等待发送、发送中、SMTP已受理、发送前确定失败和结果不明。SMTP受理不证明对方邮箱最终送达。结果不明时不能直接重发；有独立“核验工单邮件未受理”权限且仍符合当前队列处理资格的人员，可明确确认供应商未受理并提供安全证据引用。邮箱未收到不足以证明未受理，确认框不得预先勾选；证据是1至128字符的非秘密记录标识，不是URL、token或原始响应，原因固定为VerifiedUnsent。核验回传当前意图版本，仅把Unknown改为Failed并追加审计，不发送邮件，也不自动重试。页面须刷新外发结果取得新的状态与意图版本；确定发送前失败且总尝试次数未达五次时，才显示另一个显式重试入口。工单版本与外发意图版本不可混用。

## 投递审计与人工核验

通知投递页仅展示安全投递元数据、历史尝试和追加式人工日志，不展示正文、目标凭据或供应商原始错误。按当前授权范围查询或选择可访问组织收缩范围。

未知结果先核验渠道确实未受理，明确勾选确认并填写无机密记录标识；核验本身不会发送通知。之后符合确定失败状态、权限和总次数限制时，才可独立重试。重试原因使用配置已修复或服务已恢复等受控原因，必须回传当前投递版本，不清零历史次数。

## 最小验证与错误处理

使用有效普通用户确认消息与未读数只属于本人，读取公告来源不调用管理正文接口、不自动已读。撤销来源资格后重新打开，必须显示不可访问且不保留旧正文。使用授权处理账号验证队列与邮箱配置、私有邮件下载、重复转工单、状态版本冲突以及回复技术重试。

测试未知投递和未知外发没有直接重发按钮；验证合法动作后列表、详情和日志刷新。接口拒绝范围、状态、身份或版本时保持数据不变，并让用户重新授权读取当前事实。页面可见、构建成功或本地模拟不能证明公共DNS、真实邮箱最终送达与部署现场网络已开通；上线时须按后端模块手册完成对应环境验证。


## 范围选择与二次开发

组织选择器先展示租户分组；点击左侧箭头展开，再选择有权访问的组织。分组本身不可选，初始折叠不表示组织目录加载失败。已有子组织的展开保留服务端组装的树，不额外增加目录权限。

工作流通知路由、工单队列、支持邮箱规则、工单和收件箱的通用 GET 查询及主键请求由 API facade 统一处理范围。非平台主体省略 `tenantId`，由服务端从当前身份注入；平台主体保留明确租户筛选。非空 `orgId` 继续作为标量发送，在调用方没有明确 `orgIdList` 时同时补充单元素 `orgIdList:[orgId]`，沿用现有模型的列表及公共组织查询语义；调用方已有的列表不被覆盖，界面选择记录也不被修改。通用 DELETE 使用相同范围封装。

独立通知审计接口使用自己的 DTO，不追加未知组织字段。Create、Save 和其它 POST 业务命令继续遵循各自 DTO 合同，不能照搬 GET 的字段省略规则；例如队列保存需要明确的租户和组织。路由的逻辑 `configRef` 校验仍读取原界面范围，服务端是最终授权和归属校验方。二次开发应通过服务方法调用，避免直接拼接 API 请求绕开范围封装。


队列处理用户候选沿用上述通用组织查询范围。处理角色使用角色接口正式租户 DTO，不传组织字段，并关闭 `containsPublicData`：队列处理角色必须属于队列租户，平台公共角色不是有效处理角色。候选查询的租户字段省略规则不用于保存、编辑或启停命令；这些命令仍按其 DTO 提交明确归属和读取版本。


支持邮箱默认处理人与工单分派候选也通过统一组织范围查询加载。邮件来源目录使用正式租户 DTO，不发送组织字段：本地 SMTP 只查询已启用、生命周期为 Active 且已开启接收的域名；Forward Email 只查询已启用并已同步的路由。来源可见字段用于排除已知无效记录；私有投递目标被屏蔽时不要求额外读取权限，保存和启用仍由服务端校验真实来源、到期状态、邮箱匹配及 Webhook 目标。当前租户没有满足条件的来源时，候选为空是正常结果，应先按邮件与域名指南配置来源。

平台管理员的通用角色查询可能仍返回平台公共并集。队列角色候选逐项核对正式返回的 `tenantId` 与 `publicRole`：明确公共角色被排除，平台主体还必须精确匹配所选租户；租户主体遇字段被屏蔽时继续依赖正式目录授权与保存复核。这些候选过滤不会授予权限或改变业务命令。
