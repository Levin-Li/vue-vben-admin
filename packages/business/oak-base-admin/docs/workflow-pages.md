# 工作流设计与业务页面接入

## 页面入口与前置条件

基础模块启用后，“基础框架 → 工作流”集中提供“流程设计”“发起流程”“我的流程”“工作流实例管理”“工作流通知路由”和“流程申请样例”。前端只将当前用户已经获准查看的菜单归到此组，页面原URL与路由权限保持；无需上传菜单或修改后端。没有任何可见工作流入口时不显示空分组。通用“通知投递”继续从“运维&审计”进入。

后端须启用工作流能力目录、流程定义与版本、运行时及业务样例控制器，并完成该环境所需的显式数据库准备。页面通过本包 API 目录请求后端，沿用宿主登录会话；申请人由服务端确定，浏览器范围选择须重新授权。新建绑定流程须从授权目录选择业务对象和状态字段；枚举或字典复用选项，普通字符串或整数字段须定义值与名称映射。业务实体无需继承流程父类或实现简单 FSM；既有第三版适配器定义按其固定版本契约运行。

流程运行入口使用 `WorkflowRuntime` 域下的“业务数据-工作流运行时”权限；设计及发布仍使用独立的平台权限。业务结果动作和交付重试还须具备业务适配器规定的权限，页面不自动给账号赋权。重试按钮同时要求 API 权限及服务端返回的授权交付标识。

## 设计并发布

打开“工作流 → 流程设计”，可按名称和业务对象查询、分页查看流程，列表展示全局/租户归属及版本状态。点击“打开设计”后，在接近全屏的大弹窗中选择版本、编辑画布和节点配置、检查及发布；关闭后返回列表，重开同一流程保留尚未保存的编辑，切换流程仍需确认放弃修改。点击“新建流程”，填写流程名称、业务对象、状态字段和映射，创建成功会连续创建首个草稿并打开同一设计弹窗；若草稿创建失败，已建立的定义保留，可打开该定义后重试创建草稿。平台主体默认创建全局定义，租户主体沿服务端当前租户范围创建，归属以服务端返回为准。系统生成稳定内部标识；首次草稿使用该标识作为内部用途，已有发布版本则延续已发布用途。设计器只提供所选业务类型的授权方案：单一方案预填；多个方案必须由用户明确选择，不自动选择最高契约版本。记录编号、名称、申请人和摘要只从服务端明确字段角色预填。用途稳定性及发布资格仍由服务端校验。

设计组件提供业务字段映射、用途前置条件、审批节点、显式连线、结果动作及模拟发布。只能选择能力目录公开的字段和行为，未知能力由服务端拒绝。人员候选沿用现有用户列表、可访问角色和授权组织接口；可用搜索刷新候选，加载失败不将候选扩大为任意用户。

按“选择业务对象、审批步骤、发起规则、完成后处理、检查流程”配置。中文判断字段自动关联内部引用，前置流程及结果操作均从授权目录选择；技术标识和 JSON 留在按需展开的实施者区。保存草稿后点击“执行检查”；报告及发布资格以后端返回为准。变更设计会使原模拟证明失效，需要重新验证。已发布版本不可直接修改，应新建草稿版本。切换定义或版本会提示确认放弃未保存的设计。

设计工作台的“模拟历史”按当前版本分页列出运行记录；“查看报告与轨迹”读取单次真实覆盖和虚拟执行路径。“删除”需要独立方法权限并由服务端软删除，删除当前发布证明后发布按钮不可继续使用，必须重新模拟。只有具备查询历史和报告两项 API 权限时，宿主才加载该区域。

“我的流程”按待办、已办、我发起、抄送四项独立运行时 API 权限加载。发起人在自己仍运行的实例详情里用工作流专用接收人目录搜索并显式发送抄送；接收人可在“抄送”打开只读实例详情。目录至少输入两个字，不能用系统 `User/list` 代替；接收人、租户、组织和业务范围都由后端重新验证。普通发起人需要 `查询流程抄送接收人` 与 `发送流程抄送` 两项方法权限，接收人需要 `查询我收到的流程抄送` 方法权限；撤权会清空本页对应列表和候选。

四个分栏按当前权限独立读取 `size/cursor` 页，默认一次 20 条、上限 50 条；“上一页/下一页”只使用服务端返回的继续游标，不展示未经完整授权计算的全局总数。某页因撤权没有可见记录而仍有下一游标时，可以继续翻页；刷新、切换身份权限或选择另一分栏会清除旧详情与失效响应。

## 运行实例管理

实例列表直接使用公共 `CrudPage`：查询收展、刷新、列设置、全屏和页面展示设置均为标准组件能力。“查看实例”打开专用详情抽屉，展示流程图、轨迹及当前有权执行的动作。列表不提供新增、任意编辑或删除；接口不提供全量读取和授权总数，因此关闭全量导出并保留真实游标的上一页/下一页。

流程定义、运行实例、通知路由以及“我的流程”四个分栏直接使用公共 `CrudPage`，复用查询（接口支持时）、刷新、列设置、全屏、页面展示设置及对应分页；申请样例沿用原标准 CRUD。 设计弹窗、业务绑定新增、通知渠道配置、审批办理及实例详情继续使用专用交互。不会为了样式开放普通删除、任意状态编辑或未授权导出。无总数的运行列表只显示真实游标页；发起流程目录与记录使用标准表格分区、选择操作列和有界页码，不伪造总数或把当前页搜索当作全局查询。

从“工作流 → 工作流实例管理”进入。列表和详情分别要求 `WorkflowManagement:业务数据-工作流实例管理::查询运行实例` 与 `WorkflowManagement:业务数据-工作流实例管理::查看运行实例`，账号还必须具有对应业务对象的当前读取权限。管理者无需成为流程参与者；个人待办、已办、我发起和抄送仍按个人关系授权。

平台主体默认查看全部授权范围，也可用授权组织选择器收窄；租户主体只查询自身当前范围。按关键词、流程定义和执行状态筛选，通过上一页/下一页读取有界游标页；不展示未经业务授权过滤的原始总数。空页仍有下一页时可以继续，切换范围会清空旧列表和详情。

页面将授权组织、关键词、执行状态与流程筛选集中在同一管理区域；设置条件后点击“查询”，点击“刷新”重取当前页。表格下方显示当前页条数与游标翻页按钮。

打开实例可查看关联业务、运行状态、审批结果、业务交付状态、固定版本只读流程图与实际时间线。引擎结束而业务处理尚未成功时，页面继续展示待交付或失败。管理页不提供代他人审批、物理删除历史或任意引擎操作。当前权限被撤销、伪造实例编号或跨范围访问时由服务端拒绝。

## 独立发起流程

从“工作流 → 发起流程”进入，普通租户账号使用当前会话租户；平台管理员先从现有授权组织选择器确定业务租户。页面不允许手工填写业务 ID、表名或技术契约版本。选择手动流程，再从有权读取的业务记录中选择目标，查看服务端返回的用途资格及固定阻断原因，满足条件时点击“发起流程”。自动用途不会出现在手动目录，其资格也不显示手动发起按钮。

目录与业务记录分别按 `pageIndex/pageSize` 分页，每次固定读取 20 条，后端最多 50 条；仅显示页码和上一页/下一页，不估算未授权总数。空页有 `hasMore` 时仍可继续；刷新或权限、租户变化清除旧用途和记录。目录/记录接口复用“发起业务流程”权限，记录还须由后端业务选择器重新验证该账号的正常查询及对象范围权限；资格接口独立要求“查询业务流程资格”。

本页与业务对象上嵌入的 `WorkflowBusinessPanel` 共用 `start` 命令，独立发起页携带所选目录的能力契约版本约束，不提交指定定义版本或模拟证据；业务对象入口不提供该约束时仍由服务端在全部授权契约中匹配。失败保留该对象/用途的幂等键，再点启动重放同一命令；提交期间禁止连点。服务端最终重验范围、当前条件、已发布定义、轮次和并发占位。成功后在“我的流程”查看进度。翻页导致面板卸载或整页刷新后，内存请求键结束，应先查看办理历史；服务端仍保留活动实例和幂等约束。

## 业务发起与办理

“流程申请样例”先通过现有授权组织选择器明确选择本次业务组织。默认空选，不会自动选择第一项；组织节点须携带租户归属。该选择只作为本页请求中的租户/组织选择意图，后端重新校验，不修改全局选择器配置。已有全局范围与本页选择冲突时，服务端明确拒绝，需要统一选择后重试。

选定组织后，可维护标题、类别、金额与资料齐全四个业务字段。申请人由服务器设置，归属必须落在服务器授权范围，办理结果摘要只读；普通创建或更新不会提交流程状态或结果摘要。

创建、列表、编辑和详情使用相同范围请求规则：平台主体（含现有 `platformUser/isPlatformUser` 与管理员身份字段）可以传递明确租户选择，后端仍逐次校验其真实访问范围；普通租户主体须先确认业务引用属于当前会话租户，再省略受保护的 `tenantId` 参数，由后端注入。外租户引用、缺失会话归属或页面选择与引用冲突会明确阻止请求，不通过删除冲突字段继续访问。

同样的范围规则适用于 Oak 宿主工作流连接器的 `eligibility`、`history`、`start`、`roundState`、`newRound`、`resubmit`、`retry`。连接器在每次请求时读取当前真实会话，普通同租户请求省略 `tenantId` 并保留 `orgId`；原业务引用和幂等命令不会被修改，契约、来源运行记录、轮次、修订和请求标识完整保留。公共 `bpm-runtime-ui` 不依赖宿主用户存储，其他宿主须自行遵循后端范围协议。

在记录的“业务流程”中查看各用途的当前发起资格及阻断原因，满足条件时点击“发起流程”。组件每次启动使用请求幂等键，网络失败重试沿用同一键。服务端重新核验资格、范围和并发占位，页面按钮可用不代表最终一定允许启动。

审批人从“我的流程”打开待办，按服务器返回的动作和表单办理。审批结果、执行状态与业务结果交付状态分别展示；业务处理失败不能视为通过。返回样例的“业务流程”，刷新业务结果及办理历史，可查看同一对象不同用途的记录。

报销核对样例使用业务类型 `workflow-expense`、契约 `1`，通过正式业务 API 创建后，在现有“我的流程”办理，不提供独立管理菜单。宿主本地登记 `workflow-expense` 详情键，通过 `/WorkflowExpense/retrieve` 重新授权读取报销事由、申报金额、票据齐全、核定金额、核定说明与处理结果。详情始终只读；核定金额和说明通过服务端声明的节点表单及受控动作提交，不通过普通详情写入。业务引用的租户/组织与其他任务详情使用相同校验规则；授权失败显示错误，不展示上一条任务的内容。

业务更新被拒绝时保留输入，并根据服务端提示处理当前活动流程或办理轮次，不通过清空流程字段绕过保护。对象不可访问、版本冲突、条件不满足或人员资格失效均以后端错误为准。

专用“流程申请样例”页按当前所选租户读取服务端授权业务能力目录，提供 `workflow-request` 契约 `1`、`2` 等实际可用版本；该专用页仍默认优先展示 `1`，可切换到其它授权版本。原业务管理页的通用“业务流程”入口则默认选择当前授权目录中的最新契约，可显式切换其它可用版本；契约选择与流程设计的发布版本分别处理。全局发起资格单独展示一次，不属于所选契约；轮次与历史只挂载当前所选版本的面板，并只展示冻结在该契约版本的记录。两个面板独立查询，单侧加载失败不会清空另一侧；目录加载失败时不猜测默认版本，可点击“刷新契约版本”重试。轮次查询、新轮次和重提入口还分别要求实际 API 方法权限。失败终态且业务结果已应用的最新同轮尝试可点击“重新提交”，命令始终使用该尝试的冻结契约版本，确认后由服务器重新匹配当前发布流程并重验条件；事件用途只显示“由事件触发”，不能用普通手动发起绕过。“开启新办理轮次”先读取当前真实修订，确认后旧前置结果失效且历史保留；存在活动或待交付实例时显示阻断原因。操作成功自动刷新申请结果和历史。

轮次命令响应失败时再次确认会复用完整原命令；取消后“重试原提交”也保持同一幂等键。准备期间取消、切换申请或关闭抽屉，会隔离旧请求的后续界面更新。刷新整个网页会结束组件生命周期并丢弃内存命令，请先检查办理历史再决定后续操作。

## 最小验证与扩展边界

使用有设计权限的账号创建并发布一个绑定样例业务的审批流程。创建一条申请，确认不需要填写状态或申请人。发起后切换到合法审批人办理，再查看原申请结果与历史；重复点击发起、修改活动申请和无权账号访问应由后端按契约处理。

宿主可通过 `@levin/bpm-designer` 和 `@levin/bpm-runtime-ui` 的公开组件扩展自己的业务页面。本包各页面都有独立实现及 `config.ts`，不是依据 OpenAPI 动态生成。新增业务类型仍须后端公开受控能力并接入真实业务授权，不能仅靠增加菜单或前端字段映射获得数据访问权限。

本指南描述接入及操作契约，不构成某个环境已经完成浏览器、数据库或安全验收的证明。

## 流程步骤通知

流程设计器的“审批步骤 → 步骤设置 → 步骤通知”可为自动环节与人工环节配置通知事件、接收人、渠道、标题和 Markdown 正文模板。受支持模板变量与节点事件见`@levin/bpm-designer` 包内的《工作流设计器使用指南》。本宿主使用与“我的消息”一致的安全 Markdown 预览，禁用原始 HTML、危险协议和自动远程图片。短信仅发送文本，编辑界面单独提供纯文本示意。

设计页只声明通知语义；收件人联系方式、供应商与机器人路由由服务端按租户解析。通知配置变更须重新保存、检查、发布，已发布版本保持只读；模拟阶段不发送通知。

## 节点合同文档浏览

“我的流程”的电子合同任务在业务资料区展示合同原文及已签文件；结构化办理表单与文档并存，正文只读。`electronic-contract` 的 `readonly-1` 契约通过固定详情键注册，通用运行组件不依赖合同实体。仅有任务参与资格不足以取得原文，还须具备当前合同查看详情权限与其租户、组织及个人范围。

审批详情先调用认证的 `EContract/use/document-reference`，只取得合同ID、名称、当前 `optimisticLock`、归属、文件名/MIME以及 `hasOriginal/hasSigned`；不调用通用合同详情，不向浏览器交付原文URL、FileRes路径或签名查询参数。存在标志决定是否提供原文/已签文件；在线链接无需本地FileRes。引用尚无文件名或MIME时，界面仍提供分页入口，由后端识别实际文档并生成PNG，不把缺少元数据当成文件不存在。管理页面传入完整合同对象时也支持 `fileUrl` 或 `fileResId` 来源，但组件不把这些定位信息写入DOM或转发给文档接口。

文档内容由服务端从当前已授权业务记录定位。浏览器仅提交合同ID、文件种类、修订及作用域：DOCX通过 `EContract/use/document` 取得受控字节并本地分页；PDF/PPTX通过 `EContract/use/document-page` 返回PNG分页，校验页码、总页数、类型、签名、尺寸和4MiB上限后展示，不依赖PDF插件。PPTX先在服务端转换PDF再分页；预览副本不覆盖原文。分页额外传从1开始的 `page`，不传 `representation`，每页重新校验当前修订与权限。

线上来源支持由业务保存的HTTPS文件直链及带签名查询参数的直链，管理员须在服务端 `workflow.documents.remote.allowed-origins` 配置精确来源；签名参数仅由服务端发送给已授权来源，不进入组件属性或下载URL。链接失效、403/404、未授权来源、HTML登录/分享页、超限或超时明确报错，不回退到旧文档、外部Office查看器或公开地址。需要供应商登录的网页分享地址不能冒充文件直链，须由业务系统提供可受权GET读取的文档链接。本地FileRes绑定继续支持，不能因在线来源新增而跳过本地文件归属检查。

Office及PDF工具仍须由部署方显式配置。宏、外部关系、嵌入HTML等内容不支持；PDF只接受保守子集，含主动内容、外联动作、加密或压缩对象的文件可能被拒绝，不声称所有PDF可用。

验证时使用虚构线上DOCX、PDF、PPTX链接及本地文档分别建立合同；合法审批人须实际看到第1/2页不同正文并提交独立节点表单。再验证签名过期、无权账号及过期修订会明确失败且不展示上一份文档。切页先清空旧图，换合同或修订重置到第一页，关闭详情后清空图片数据，旧响应不能恢复正文；Word不启用文档链接、嵌入网页或远程字体。指南描述操作方法，不宣称某个环境已经通过在线验收。

## 撤回、终止与显式接管

“我的流程”任务或实例详情按服务端 `allowedOperations` 与当前真实API权限显示运行操作；“运行实例管理”独立提供终止/接管。原因必填1至500字，确认后提交固定业务引用、实例/交付标识及随机请求标识；接口失败保留原命令供重试，不静默生成第二次操作。普通重试保持原执行主体，显式接管才使用当前授权主体并记录原因。

撤回只允许真实发起人，终止需要 `workflow.runtime.terminate`，接管需要 `workflow.runtime.recover` 与当前业务及结果动作权限。关键业务依据失效时审批按钮停用并显示服务端阻断原因，合法撤回/终止入口仍可使用；退出不会执行通过业务动作。结果待核验的外部操作不能通过接管强行重发。

个人菜单展示与待办、已办、我发起、抄送各区查询权限分开；任一已授权分栏可使用，无权分栏不请求。菜单本身还须展示授权，业务读取范围与节点办理API也分别授权，不通过给审批人管理角色解决访问不足。升级已有个人菜单时，旧的固定待办前置授权需要管理员通过正式菜单更新接口显式清理，启动不会静默改写。

## 用户原业务页的组织与流程入口

普通业务角色在“用户”页顶部的“用户查询组织”中选择一个当前授权组织，再用登录名或名称查找记录，并点击该行“业务流程”。未选组织时保持本人默认组织。列表、详情和更新共用标准单元素orgIdList，服务端仍逐项校验范围；页面没有启用全局Header豁免，也不要求管理员角色。切换组织会关闭旧记录及流程面板，旧异步响应不能写回。

用户类型、等级显示需要精确只读字典权限 `com.levin.oak.base:通用数据-字典::通过编码查看详情`。业务列表/详情、流程资格/发起和个人菜单仍分别授权；实例管理权限不能替代申请、报销等业务的详情权限。首次接入可用普通角色验证原行发起后，在“我的流程→我发起”找到同一实例，并核对租户、组织与原业务记录一致。

## OA 状态图新增流程与办理

在流程设计列表点新增，依次选择业务对象、状态字段并确认状态映射，保存后进入独立的大弹窗设计，版本、画布、属性、检查和发布都在窗口内，窗口高度内可滚动查看。对象目录由当前账号对实际 CRUD 的读取权限确定，不存在另一个全局“启用业务对象”设置。字段被其它流程占用时不可再选；业务对象或状态字段不能通过普通编辑接口替换。

图中添加已知状态，点击节点配置审批人、会签、表单、进出通知与抄送；点击连线配置事件、条件与目标，可以连接已有状态。检查、配置模拟用例、模拟通过后发布。发布前只占用字段；发布后业务新增使用流程开始状态，普通编辑不能直接变更状态。

从发起流程页面选择已发布用途和已授权业务记录。待办中的同意/拒绝处理审批席位；实例详情中显示当前有权执行的业务事件，动作只提交事件和状态访问标识，不提交目标状态。标准实例列表继续提供查询、列设置与固定版本只读状态图。动态表定义及数据库同步在独立模块管理，工作流通过提供者接口接入。

## 任务式流程设计

新建流程保存业务对象和必选状态字段后，进入第五版任务图大弹窗，初始为开始→结束。点击＋添加人工办理、自动处理、条件分路或同时办理；并行模板自动维护配对汇合。已有绑定定义的“新建任务流程版本”会明确创建空白任务图，原固定版本保持原样。具体操作与字段权限见设计器包的[工作流设计器使用指南](../../bpm-designer/docs/工作流设计器使用指南.md)。我的流程中的保存动作按实际saveTask API权限与服务端canSave显示，保存不会完成任务。

## 标准列表的最小验证

进入“工作流”分组，分别打开流程设计、通知路由、实例管理和我的流程。检查刷新、列设置和全屏工具，调整查询后分页；有实际授权的行继续通过“打开设计”“查看实例”或“查看／办理”进入专用界面。我的流程切换待办、已办、我发起、抄送时只加载该分栏授权接口，列偏好与游标分别保存；撤权后清空对应列表。发起流程先选择流程，再选择授权记录、查看资格。列表没有数据时使用空态提示，不用手工业务ID补查。
