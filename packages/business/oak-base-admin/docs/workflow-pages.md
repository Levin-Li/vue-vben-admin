# 工作流设计与业务页面接入

## 页面入口与前置条件

基础模块启用后，“开发&工具”分组提供“流程设计”和“流程申请样例”，“个人&中心”分组提供“我的流程”。实际菜单及动作仍由当前登录用户的后端授权决定；路由上传沿用本包的完整页面映射。

后端须启用工作流能力目录、流程定义与版本、运行时及业务样例控制器，并完成该环境所需的显式数据库准备。页面通过本包 API 目录请求后端，沿用宿主登录会话；申请人由服务端确定，浏览器范围选择须重新授权。业务对象无需状态字段、流程父类或简单 FSM。

流程运行入口使用 `WorkflowRuntime` 域下的“业务数据-工作流运行时”权限；设计及发布仍使用独立的平台权限。业务结果动作和交付重试还须具备业务适配器规定的权限，页面不自动给账号赋权。重试按钮同时要求 API 权限及服务端返回的授权交付标识。

## 设计并发布

打开“流程设计”，创建流程名称、稳定标识和已注册业务类型。保存稳定定义后新建草稿版本，在版本设计中填写用途标识并保存设计正文；用途不保存在稳定定义上。该流程已有发布版本时，新草稿默认延续已发布用途，首次发布后的用途稳定性仍由服务端校验。

设计组件提供业务字段映射、用途前置条件、审批节点、显式连线、结果动作及模拟发布。只能选择能力目录公开的字段和行为，未知能力由服务端拒绝。人员候选沿用现有用户列表、可访问角色和授权组织接口；可用搜索刷新候选，加载失败不将候选扩大为任意用户。

保存草稿后开始自动模拟；报告及发布资格以后端返回为准。变更设计会使原模拟证明失效，需要重新验证。已发布版本不可直接修改，应新建草稿版本。切换定义或版本会提示确认放弃未保存的设计。

设计工作台的“模拟历史”按当前版本分页列出运行记录；“查看报告与轨迹”读取单次真实覆盖和虚拟执行路径。“删除”需要独立方法权限并由服务端软删除，删除当前发布证明后发布按钮不可继续使用，必须重新模拟。只有具备查询历史和报告两项 API 权限时，宿主才加载该区域。

“我的流程”按待办、已办、我发起、抄送四项独立运行时 API 权限加载。发起人在自己仍运行的实例详情里用工作流专用接收人目录搜索并显式发送抄送；接收人可在“抄送”打开只读实例详情。目录至少输入两个字，不能用系统 `User/list` 代替；接收人、租户、组织和业务范围都由后端重新验证。普通发起人需要 `查询流程抄送接收人` 与 `发送流程抄送` 两项方法权限，接收人需要 `查询我收到的流程抄送` 方法权限；撤权会清空本页对应列表和候选。

## 业务发起与办理

“流程申请样例”先通过现有授权组织选择器明确选择本次业务组织。默认空选，不会自动选择第一项；组织节点须携带租户归属。该选择只作为本页请求中的租户/组织选择意图，后端重新校验，不修改全局选择器配置。已有全局范围与本页选择冲突时，服务端明确拒绝，需要统一选择后重试。

选定组织后，可维护标题、类别、金额与资料齐全四个业务字段。申请人由服务器设置，归属必须落在服务器授权范围，办理结果摘要只读；普通创建或更新不会提交流程状态或结果摘要。

创建、列表、编辑和详情使用相同范围请求规则：超级管理员或 SaaS 管理员可以传递明确租户选择；普通租户主体须先确认业务引用属于当前会话租户，再省略受保护的 `tenantId` 参数，由后端注入。外租户引用、缺失会话归属或页面选择与引用冲突会明确阻止请求，不通过删除冲突字段继续访问。

同样的范围规则适用于 Oak 宿主工作流连接器的 `eligibility`、`history`、`start`、`roundState`、`newRound`、`resubmit`、`retry`。连接器在每次请求时读取当前真实会话，普通同租户请求省略 `tenantId` 并保留 `orgId`；原业务引用和幂等命令不会被修改，契约、来源运行记录、轮次、修订和请求标识完整保留。公共 `bpm-runtime-ui` 不依赖宿主用户存储，其他宿主须自行遵循后端范围协议。

在记录的“业务流程”中查看各用途的当前发起资格及阻断原因，满足条件时点击“发起流程”。组件每次启动使用请求幂等键，网络失败重试沿用同一键。服务端重新核验资格、范围和并发占位，页面按钮可用不代表最终一定允许启动。

审批人从“我的流程”打开待办，按服务器返回的动作和表单办理。审批结果、执行状态与业务结果交付状态分别展示；业务处理失败不能视为通过。返回样例的“业务流程”，刷新业务结果及办理历史，可查看同一对象不同用途的记录。

报销核对样例使用业务类型 `workflow-expense`、契约 `1`，通过正式业务 API 创建后，在现有“我的流程”办理，不提供独立管理菜单。宿主本地登记 `workflow-expense` 详情键，通过 `/WorkflowExpense/retrieve` 重新授权读取报销事由、申报金额、票据齐全、核定金额、核定说明与处理结果。详情始终只读；核定金额和说明通过服务端声明的节点表单及受控动作提交，不通过普通详情写入。业务引用的租户/组织与其他任务详情使用相同校验规则；授权失败显示错误，不展示上一条任务的内容。

业务更新被拒绝时保留输入，并根据服务端提示处理当前活动流程或办理轮次，不通过清空流程字段绕过保护。对象不可访问、版本冲突、条件不满足或人员资格失效均以后端错误为准。

申请页按当前所选租户读取服务端授权业务能力目录，提供 `workflow-request` 契约 `1`、`2` 等实际可用版本；默认优先展示 `1`，可切换到其它授权版本。全局发起资格单独展示一次，不属于所选契约；轮次与历史只挂载当前所选版本的面板，并只展示冻结在该契约版本的记录。两个面板独立查询，单侧加载失败不会清空另一侧；目录加载失败时不猜测默认版本，可点击“刷新契约版本”重试。轮次查询、新轮次和重提入口还分别要求实际 API 方法权限。失败终态且业务结果已应用的最新同轮尝试可点击“重新提交”，命令始终使用该尝试的冻结契约版本，确认后由服务器重新匹配当前发布流程并重验条件；事件用途只显示“由事件触发”，不能用普通手动发起绕过。“开启新办理轮次”先读取当前真实修订，确认后旧前置结果失效且历史保留；存在活动或待交付实例时显示阻断原因。操作成功自动刷新申请结果和历史。

轮次命令响应失败时再次确认会复用完整原命令；取消后“重试原提交”也保持同一幂等键。准备期间取消、切换申请或关闭抽屉，会隔离旧请求的后续界面更新。刷新整个网页会结束组件生命周期并丢弃内存命令，请先检查办理历史再决定后续操作。

## 最小验证与扩展边界

使用有设计权限的账号创建并发布一个绑定样例业务的审批流程。创建一条申请，确认不需要填写状态或申请人。发起后切换到合法审批人办理，再查看原申请结果与历史；重复点击发起、修改活动申请和无权账号访问应由后端按契约处理。

宿主可通过 `@levin/bpm-designer` 和 `@levin/bpm-runtime-ui` 的公开组件扩展自己的业务页面。本包三个页面各有独立实现及 `config.ts`，不是依据 OpenAPI 动态生成。新增业务类型仍须后端公开受控能力并接入真实业务授权，不能仅靠增加菜单或前端字段映射获得数据访问权限。

本指南描述接入及操作契约，不构成某个环境已经完成浏览器、数据库或安全验收的证明。
