# 主档多方组织与负责人使用指南

## 入口与前置条件

在后台“客户&伙伴”分组进入“法律主体”“客户”“供应伙伴”或“渠道伙伴”。操作需要对应资源动作权限、租户范围及参与方数据范围；能打开记录不代表能修改全部资料或重新分配负责人。升级须同步部署后端的新字段契约并显式完成历史数据迁移，不能只升级前端包。

## 法律主体

法律主体分别配置“主体方组织”“主体方负责人”“商务对接部门”“商务对接人”，对应 `subjectOrgId`、`subjectUserId`、`businessOrgId`、`businessUserId`。两个组织各一个，负责人各一名；负责人不要求属于同方组织。负责人从独立用户候选中选择，切换组织不会自动清空或改写负责人。

## 客户与合作伙伴

客户、供应伙伴和渠道伙伴统一有主体方、商务、售前、售后、财务五方。各方分别有一个组织字段和一个负责人字段，例如 `businessOrgId`、`businessUserId`；其他前缀为 `subject`、`presales`、`aftersales`、`finance`。这些字段表示独立参与关系，负责人候选不绑定同方组织。编辑已有记录时，普通用户只能查看参与方分派；服务端确认的管理员可调整职能组织和负责人，主体组织仍不可换绑。

普通“新增”客户或伙伴只选择商务对接部门和对接人；“新增我的”由服务端写入当前用户的主体组织和主体方用户。两种普通建档均不创建外部组织或管理员账号。需要一站式创建法律主体、外部组织、首用户及合作关系时使用“快捷添加”，该入口的内部父级只用于新外部节点位置。伙伴完整名称在同一租户内唯一。

法律主体关联允许创建时留空，之后补全；已关联的主体不可更换。客户联系人姓名、电话、邮箱独立维护，不修改法律主体联系人。渠道客户需要选择当前有权访问的渠道伙伴。认证状态只通过专用认证动作变更。

## 权限与返回语义

普通用户通过任一获授权参与组织或负责人条件命中记录；有全部组织权限时不再按这些参与方筛选。服务端仍独立校验租户、机密等级、接口动作及字段分组权限。客户端不提交逻辑组注入字段、旧 `orgId` 或旧 `ownerId` 来决定可见范围。

详情按中文业务字段展示参与方与状态摘要，关联对象、校验哈希、数据版本和动作清单不作为重复字段展示。仅平台用户可见的租户字段不会为普通租户用户预先读取全局租户列表。

认证动作只提交记录 ID、租户、乐观锁及动作参数，由后端重新计算有效多方范围。保存失败保留输入并显示错误；跨租户、无权分配引用、无原目标访问权、乐观锁冲突或缺少有效内部父级时不能视为成功。

## 最小验证

在测试租户创建法律主体，分别配置两个组织及来自其他部门的负责人；确认负责人不因组织不同被前端排除。创建客户和两类伙伴后，确认主体组织由服务端生成且编辑时不可更换，五方组织和负责人分别回显。切换销售组织，确认已选销售负责人不被自动清除。以不同参与方用户核对列表、详情和认证动作，并验证无关用户及非法租户被拒绝。

历史页面展示设置若保存旧 `orgId`、`orgName`、`ownerId`，需要管理员按新字段重新配置；页面读取不自动改写历史设置。迁移和测试执行记录由源仓库管理，不随发布包交付。
