# 快捷添加客户与伙伴设计

## 目标与范围

客户、供应伙伴和渠道伙伴各有现成的管理列表，但一次开户涉及法律主体、外部组织、管理员用户和业务主档。快捷添加把必要输入收在同一个弹窗，目标身份由所在页面固定，后端在一个事务内建立关联。普通新增、资料编辑及认证审核入口保持独立。

## 输入与交互决策

三个页面复用同一弹窗。管理员输入主体名称后，页面等待约 0.8 秒再向已配置的企查查插件搜索候选；只有选择候选才查询一次详情，避免为每条候选发起可能计费的详情请求。查询无结果、未授权或不可用时，仍可人工填写主体名称与统一社会信用代码。来源提示只说明录入方式，不等于法律主体已经认证。

主体名称与简称在桌面同一行，小屏改为单列。主体类型只提供法人、个体户和非法人组织；自然人不使用此 18 位统一社会信用代码快捷入口。管理员手机号必填，姓名、用户名和密码可留空：姓名默认为“管理员”，用户名由后端生成唯一的“管理员_”前缀登录名并在成功后提示，空密码账号使用已有短信验证码登录能力。客户固定为直接客户；供应伙伴和渠道伙伴各需选择自己的业务子类型。

## 数据与权限边界

页面不提交租户、父组织、角色、负责人或现有外部组织 ID。对应业务控制器固定目标身份；后端以当前认证用户的租户和内部组织作为可信归属，依次创建或复用法律主体、创建外部组织、管理员用户和业务主档。同代码主体仅在名称与类型一致、且尚无同类关系时可复用；复用时不覆盖原主体方和认证资料。

快捷添加动作权限决定按钮是否可见，服务端仍独立授权。三类管理员分别使用平台级的 `R_CUSTOMER_ADMIN`、`R_SUPPLIER_PARTNER_ADMIN`、`R_CHANNEL_PARTNER_ADMIN`；角色定义不绑定租户，用户的有效范围仍限当前租户与自身组织。外部查询与本地开户分成两次操作，查询费用或失败不参加开户数据库事务。

## 取舍

首版候选搜索固定使用企查查，页面明确提示可能计费；未配置时保留人工路径。用户名自动生成时返回实际登录名，避免操作人需要从数据库猜测。开户不自动复用已有用户，也不自动审核法律主体或伙伴。
