# 结算单使用指南

## 入口与前提

在“支付&交易”分组进入“结算单”。账号需要结算单查询及对应业务动作权限，并拥有本单据与合作伙伴关系的数据范围。只查询单据不代表有权查看银行账户、开票资料、单据、业务内容或日志。

页面和业务 API 使用 `/SettlementOrder` 路径；旧 `/SettlementStatement` 入口不再提供。已有付款凭证继续使用原 `SettlementStatementPaymentProof` 业务类型标识以兼容历史资源。

## 创建与修改

选择合作伙伴，填写结算时间、正数金额和币种（默认 CNY）。结算时间包含开始时刻，不包含结束时刻。结算内容使用非空 JSON 对象，例如 `{"orders":[{"id":"订单引用"}],"description":"月度对账"}`。页面不采集本方、对方、付款方或收款方法律主体 ID。查询区对结算开始时间和结束时间分别提供范围选择，并提交对应的开始/结束边界。

创建后合作关系和归属不可普通修改。只有待确认状态允许修改时间与业务内容；编辑原内容需要独立结算资料读取权限及“结算业务内容”字段组授权，读取失败不会以空对象覆盖。金额不能通过普通编辑调整。

结算内容在创建和编辑表单中占整行，使用 JSON 编辑器维护完整的非空对象。当前实体未指定固定 JSON Schema，因此页面不预设订单、对账或说明等属性，也不增加包装字段。编辑已有单据先调用受授权财务详情读取原内容；无权、读取失败或切换单据期间不会展示旧内容，也不会用空对象覆盖。

## 流程操作

确认后可登记实际已完成开票的发票编号或直接进入待打款。获退票权限的操作人可在尚无打款且存在有效发票时说明原因并退回发票。获调额权限的操作人可通过“协商调整金额”填写新金额与原因，新金额不得低于已打款累计，原始金额保留。按钮按当前服务端支持事件、状态、金额约束及 API 权限显示；服务端最终按操作权限、数据范围和状态校验。

登记每笔打款时填写金额、实际打款时间并上传流水凭证。上传先写入统一文件存储，再登记不公开、不共享的文件资源，提交的凭证是文件资源 ID。上传成功本身不影响结算金额。上传需要单文件上传与文件资源新增权限。首次登记请求后表单固定金额、时间、凭证及幂等键，失败重试保持同一请求；结果不明确时先核对单据，不另建重复付款。累计足额后使用“确认收款”完成整单；无打款时才可废弃。

## 财务资料

“查看结算资料”调用独立 `readFinancialDetails` 接口，仅提交结算单 ID；租户、组织和数据范围由服务端按当前会话校验。接口分别展示当前账号获授权的收款账户、付款方开票资料、发票单据、付款单据、业务内容和操作日志。JSON 资料先展示摘要，点击“查看 JSON”在只读查看器中查看全文；没有返回的组不会显示，也不从旧数据补值。普通列表、详情和导出不包含这些敏感 JSON 资料。日志按发生时间正序展示操作人与实际前后状态。

本轮新建单据暂不自动读取或写入 `payerInvoiceInfo`；开票登记按接口权限、单据范围和发票引用完成，不以该快照存在为前提。历史单据中已有的开票资料仍按财务详情字段组权限控制读取。

## 错误与最小验证

版本冲突、非法状态、超额打款、权限不足或数据范围不符会由服务端拒绝；表单保留输入，刷新核对后重新操作。用一张新单依次验证创建、待确认编辑、确认、直接待打款、两次分笔打款与整单收款；用另一张单验证开票、退回、重新开票。无财务资料权限的账号应无法读取任何敏感组，只授权一个字段组的账号应只看见该组。

实体 Java 类名已改为 `SettlementOrder`，物理表映射保留原 `SettlementStatement` 标识；本次不执行表重命名或历史数据迁移。接入方需将旧 API 路径和请求类型更新到新名称。
