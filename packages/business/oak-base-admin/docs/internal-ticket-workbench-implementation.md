# 系统内工单工作台实现与扩展

启用 `createOakBaseAdminModule()` 后，个人中心的 `/clob/V1/MyTickets` 和 `/clob/V1/MyHandlingTickets` 使用同一工作台组件。标准 CRUD 帮助入口由本模块注册；页面上下文只传路径和标题，截图在本地生成并预览，失败时仍可提交。使用前应同步菜单和对应后端方法权限。

前端通过 `ticketService` 调用工单业务接口，不通过生成的消息或私有文件 CRUD。服务端分别核验参与者、发起或受理组织、小组资格和版本，发送回复后返回服务端状态；截图由私有接口按工单和消息关系重新授权。切换组织、工单和登录身份会清理不再适用的会话，刷新失败也清空旧内容。消息内容按文本展示。

系统标签由 `ticket-tags` 字典提供，自定义标签仅属于工单。轮询周期为 7 秒；超时提醒和已解决自动关闭由后端配置和调度器决定，配置项及操作步骤见 [使用指南](communication-workbench.md)。部署时由后端维护人员执行后端发布的数据库迁移；安装前端包本身不会迁移数据库。跨租户工单不在当前能力范围内。

扩展页面应复用服务端授权和固定的通知定位接口，不能仅凭通知中的工单标识直接展示正文，也不能把截图转换为公开文件地址。最小验证包括不同组织双方建单与回复、内部备注隔离、独立未读、组织资格撤销、截图授权、版本冲突和定时流程。登录态或数据范围变化时应清除旧内容。
