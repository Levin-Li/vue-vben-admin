# 法律主体与合作伙伴页面接入指南

> 当前参与组织、负责人及访问边界见[主档多方组织与负责人使用指南](external-org-master-ownership.md)。法律主体使用主体方、维护方；客户与伙伴使用主体方、销售、售前、售后、财务五方。旧 `orgId`、`ownerId` 不再作为主档归属字段。

## 入口与前置条件

启用 `@levin/oak-base-admin` 后，使用后台授权菜单中的“法律主体”和“合作伙伴”页面。法律主体页面维护主体身份、证照、开票资料及主体认证；合作伙伴页面维护内部组织与主体之间的一条合作关系。页面所需 API 为本模块后端的 `/LegalSubject`、`/Partner` 资源；实际可见操作由控制器权限及当前用户的租户、组织数据范围决定。

## 日常操作

1. 在法律主体页面创建或查找已有主体。主体资料修改和“提交认证、认证通过、认证拒绝、撤销认证”均在该页面完成。需要主体作为结算收款方时，在表单勾选“收款银行账户”并填写开户行、账号名称和账号；它与“开票信息”中的银行字段分别维护，依各自资料权限显示和提交。未勾选的资料组不会随普通编辑提交，受限字段仍由服务端授权控制，账户完整性摘要由服务端生成。
2. 在合作伙伴页面创建渠道或供应链关系，搜索并选择有权访问的已有法律主体，填写业务名称和伙伴类型，按需选择新外部组织的内部父级并配置五方组织和负责人。一个主体可以建立多条不同组织或身份的合作关系；每条关系有独立 Partner ID。客户资料请在独立的[客户页面使用指南](customer-page.md)所述页面维护。
3. 编辑合作关系时可维护运营资料及获授权的职能组织、负责人。主体组织只读；已关联法律主体和伙伴类型不可在普通编辑中更换；要变更合作身份，应按业务规则处置原关系。主体名称和证照需回法律主体页面维护。
4. 开票授权按名称选择当前人有权办理的法律主体，提交法律主体 ID 与服务商编码。“开票申请”新增表单从当前人可用的有效授权中选择“公司 · 服务商”，提交授权 ID；无需额外建立供应伙伴关系。购买方开票抬头填写在 `buyerInfo.name`，销售方抬头取授权主体的 `subjectName`；票面明细逐项填写并计算金额，申请号由服务端生成。开具成功后的票据作为 PDF 文档链接保存在申请中。旧外部订单若已有供应伙伴关系，可在业务接口中继续提交可选 `partnerId`，服务端会校验其法律主体与所选授权一致。候选和记录列表均由服务端分页及权限过滤。

选择器只加载当前操作者可访问的主体和关系；服务端会再次校验关联范围。缺少主体权限、跨租户或无权组织、重复合作身份、非法类别组合及修改既有 `legalSubjectId` 均会被拒绝。前端隐藏或过滤不能代替服务端授权。

## 二次开发边界

Partner 表单的请求字段以业务控制器 `savePartner/updatePartner` 使用的 `SavePartnerReq` 为准，不得重新把法定主体资料加入该请求。法律主体认证只调用 `/LegalSubject` 的专用状态事件接口，不得通过普通 CRUD 更新认证状态。扩展开票选择器时，授权 ID 表示实际开票通道，法律主体 ID 表示法定销方，Partner ID 只表示可选的外部合作关系；不可把三者混用。所选授权无效、跨租户、无权访问或与可选合作关系的法律主体不一致时，后端拒绝开票。

最小验证：同一测试主体分别建立渠道和供应链关系，确认主体 ID 相同、Partner ID 不同；编辑一条关系不应修改主体资料或另一条关系。给两个有权公司分别建立有效开票授权，从发票新增表单逐一选择公司及服务商，填写购买方和一条明细后核对销方快照、金额和授权 ID；无供应链关系的自有公司也应能提交。尝试选择其他公司或租户的授权应被拒绝。

平台用户在客户表单中选择租户后，渠道客户的渠道伙伴候选按该租户的全部已授权组织加载，选择器支持按 ID 搜索、分页和已有值回显；切换租户会清除旧选择。加载失败可重试，候选范围或操作权限不满足时服务端会拒绝请求；提交客户时仍由后端复核渠道关系。
