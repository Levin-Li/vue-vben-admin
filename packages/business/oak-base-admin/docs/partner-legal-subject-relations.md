# 法律主体与合作伙伴页面接入指南

> 当前组织与个人归属操作见[外部组织主档管理页面使用指南](external-org-master-ownership.md)。业务主档选择自身外部组织节点，不再设置个人所有者；下文旧的“管理组织”“个人所有者”步骤不适用于新版本。

## 入口与前置条件

启用 `@levin/oak-base-admin` 后，使用后台授权菜单中的“法律主体”和“合作伙伴”页面。法律主体页面维护主体身份、证照、开票资料及主体认证；合作伙伴页面维护内部组织与主体之间的一条合作关系。页面所需 API 为本模块后端的 `/LegalSubject`、`/Partner` 资源；实际可见操作由控制器权限及当前用户的租户、组织数据范围决定。

## 日常操作

1. 在法律主体页面创建或查找已有主体。主体资料修改和“提交认证、认证通过、认证拒绝、撤销认证”均在该页面完成。
2. 在合作伙伴页面创建渠道或供应链关系，搜索并选择有权访问的已有法律主体，再选管理组织、合作类别和子类别。一个主体可以建立多条不同组织或身份的合作关系；每条关系有独立 Partner ID。客户资料请在独立的[客户页面使用指南](customer-page.md)所述页面维护。
3. 编辑合作关系时只修改启用状态和运营资料。法律主体关联、管理组织、个人所有者、类别及子类别在普通编辑中不可改；要变更合作身份，应停用旧关系并创建新关系。主体名称和证照需回法律主体页面维护。
4. 电子发票和电子发票授权先按名称搜索有权访问的法律主体，再选择该主体下适用的供应链合作关系。候选项显示管理组织和子类别，提交值仍是 Partner ID；搜索和关系列表都由服务端分页及权限过滤。

选择器只加载当前操作者可访问的主体和关系；服务端会再次校验关联范围。缺少主体权限、跨租户或无权组织、重复合作身份、非法类别组合及修改既有 `legalSubjectId` 均会被拒绝。前端隐藏或过滤不能代替服务端授权。

## 二次开发边界

Partner 表单的请求字段以业务控制器 `savePartner/updatePartner` 使用的 `SavePartnerReq` 为准，不得重新把法定主体资料加入该请求。法律主体认证只调用 `/LegalSubject` 的专用状态事件接口，不得通过普通 CRUD 更新认证状态。扩展发票或供应商选择器时，保留 Partner ID 的业务语义，并按当前租户、组织及适用合作类别筛选；读取法定资料应经后端主体关联和权限校验。

最小验证：同一测试主体分别建立渠道和供应链关系，确认主体 ID 相同、Partner ID 不同；编辑一条关系不应修改主体资料或另一条关系。认证动作在主体页面完成后，两条关系展示一致结果；发票只选择适用的供应链关系。
