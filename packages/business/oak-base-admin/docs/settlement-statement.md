# 结算单使用指南

## 入口与前提

在“支付&交易”分组进入“结算单”。账号需要结算单查询及对应业务动作权限，并拥有本单据与合作伙伴关系的数据范围。只查询单据不代表有权查看银行账户、开票资料、单据、业务内容或日志。

## 创建与修改

选择合作伙伴、本方与对方法律主体，确认实际付款方与收款方，填写结算时间、正数金额和币种（默认 CNY）。结算时间包含开始时刻，不包含结束时刻。结算内容使用非空 JSON 对象，例如 `{"orders":[{"id":"订单引用"}],"description":"月度对账"}`。法律主体选择只列出当前账号可访问的主体。

供应商关系默认本方付款、供应商收款；渠道关系应明确选择双方角色。创建后角色、合作关系和归属不可普通修改。只有待确认状态允许修改时间与业务内容；编辑原内容需要独立结算资料读取权限及“结算业务内容”字段组授权，读取失败不会以空对象覆盖。金额不能通过普通编辑调整。

## 流程操作

确认后可登记实际已完成开票的发票编号或直接进入待打款。付款方在尚无打款且存在有效发票时可以说明原因退回发票。收款方可通过“协商调整金额”填写新金额与原因，新金额不得低于已打款累计，原始金额保留。按钮按当前服务端支持事件、状态、金额约束及 API 权限显示；付款方或收款方身份由服务端最终核验。

登记每笔打款时填写金额、实际打款时间并上传流水凭证。上传先写入统一文件存储，再登记不公开、不共享的文件资源，提交的凭证是文件资源 ID。上传成功本身不影响结算金额。上传需要单文件上传与文件资源新增权限。首次登记请求后表单固定金额、时间、凭证及幂等键，失败重试保持同一请求；结果不明确时先核对单据，不另建重复付款。累计足额后使用“确认收款”完成整单；无打款时才可废弃。

## 财务资料

“查看结算资料”调用独立 `readFinancialDetails` 接口，分别展示当前账号获授权的收款账户、付款方开票资料、发票单据、付款单据、业务内容和操作日志。没有返回的组不会显示，也不从旧数据补值。普通列表、详情和导出不包含这些敏感 JSON 资料。日志按发生时间正序展示操作人与实际前后状态。

## 错误与最小验证

版本冲突、非法状态、超额打款、错误主体或数据范围会由服务端拒绝；表单保留输入，刷新核对后重新操作。用一张新单依次验证创建、待确认编辑、确认、直接待打款、两次分笔打款与整单收款；用另一张单验证开票、退回、重新开票。无财务资料权限的账号应无法读取任何敏感组，只授权一个字段组的账号应只看见该组。

本次不提供旧数据库迁移 SQL；不应将缺少相应表结构的旧库视为可直接升级环境。
