# 界面设置管理

`@levin/oak-base-admin` 的“界面设置管理”页面用于维护由服务端保存、按范围解析的界面配置。页面路径为：

```text
/clob/V1/UiSetting
```

它对应基础 API `UiSetting`，使用 `uiSettingService`，并受“平台数据-界面设置”资源权限控制。项目接入时必须从公开 API 导入服务，而不是直接拼接 URL：

```ts
import { uiSettingService } from '@levin/oak-base-admin/modules/com_levin_oak_base/api/index';
```

## 配置范围与匹配

一条界面设置可以带租户、领域、组织类别、组织类型、用户类别和用户类型等上下文条件。运行时以当前服务端确认的主体与站点上下文匹配最具体设置；未命中时使用更通用设置或应用默认值。

不要把技术字段、主键或服务端注入字段伪造成用户输入。页面仅展示和提交服务端允许编辑的条件与配置值。

## 配置值与历史

界面设置值使用独立 JSON 编辑入口，适用于结构化配置。每次修改应通过页面提供的保存与历史能力完成：

- 值编辑不要求把整条记录重新录入；页面会按当前设置记录序列化配置内容。
- 历史记录按 `com.levin.oak.base.entities.UiSetting` 业务类型保存，用于查看和恢复此前版本。
- 恢复操作不会绕过原有资源权限；非超管仍受界面、接口和数据范围限制。

## 租户站点基础界面配置

租户站点可在 `uiExInfo.admin-ui-base-setting` 中下发后台基础界面配置。前端读取其中的 `setting` 与 `preferServerSetting`：

- `setting` 是服务端提供的基础界面设置值。
- `preferServerSetting` 为真时，运行时优先采用服务端设置。
- 登录后若调用 `tenantSiteInfo`，项目应按接口返回值更新当前界面，不能只确认请求成功而忽略返回配置。

未返回有效 `admin-ui-base-setting` 时，前端默认明确使用浅色主题，不会因框架默认值、浏览器系统偏好或历史本地状态自动进入黑夜模式。服务端明确下发有效主题设置时，仍按 `preferServerSetting` 的既有规则应用。

账号切换或会话失效进入登录页时，框架会立即清除上一账号的动态路由、菜单、权限码和访问检查状态；挑战登录完成后再按新账号权限重新生成访问路由。项目不应通过刷新页面来修复新账号可访问页面仍被旧账号权限拒绝的问题。

界面设置是展示与交互配置，不替代后端权限、数据范围或字段写入校验。涉及动态脚本或表达式的配置仍只能由超级管理员保存和执行。
