# 角色与用户数据权限分配

在角色管理或用户管理列表中点击“数据权限分配”。弹窗按领域、租户、组织分为三个标签。每个候选项只有一个“未设置 / 允许 / 禁止”三档开关：未设置不单独写规则，允许写入允许范围，禁止写入明确禁止范围。三档互斥，同一项不会同时允许和禁止。

角色与用户列表的“数据权限分配”操作以绿色、红色小角标分别显示允许和禁止规则合计；用户某侧继承角色时，列表从有权读取的关联角色规则计算该侧去重数量，悬停会标明包含角色继承；弹窗三个标签右上侧也分别显示当前类别的允许和禁止数量，单侧为 0 时不显示。角色列表的“资源权限分配”操作以三个小角标分别显示菜单权限、操作权限、数据字段权限数量；悬停角标可查看类别和数量。

“未设置”表示该项未定义：保存时它不出现在允许列表或明确禁止列表。若之前已经配置了该项，保存会提交移除该项后的列表；用户某侧字段原本为 `null` 时继续保持 `null` 继承，不把它变成显式空列表。

租户清单中的“用户默认租户”固定预设随登录身份解释；名称为“默认租户”的实际租户按具体租户 ID 区分，两者可分别设置。打开或保存弹窗前须有对应的角色／用户详情与更新接口权限；接口字段策略无法匹配当前模块已注册路由时会拒绝加载或保存，不会绕过校验。

固定预设与动态候选共用一个选项框，中间以分隔线区分；各标签原有固定选项保持上方布局与操作，名称旁保留含义描述。动态候选直接显示，不需点击“更多候选项”。选项较多时整个框滚动，搜索框保留；租户候选超过一页时点击“加载更多租户”。组织标签下方使用公共 `UserOrgSelector` 展示搜索与普通组织树；已配置允许或禁止的组织节点会自动展开祖先路径，搜索框在宽屏约占选项框四分之一；每个动态组织节点右侧依次是三档访问开关和四种常用子组织匹配模式的下拉选择，固定项“全部组织”和“用户默认组织”也提供同样的匹配模式下拉框，“无组织”没有下拉框。未设置档清空并禁用匹配模式选择；切到允许或禁止时先采用“自身及全部下级”，随后可以调整。权限分配领域候选直接读取当前操作者的全部授权领域，不依赖全局领域选择器的 UI Setting。

用户每类范围有一个“自定义”开关。未开启时允许和禁止字段都继承有效角色配置，候选项不可编辑；开启后可编辑，空选择也是明确的自定义空范围。关闭自定义会将两个字段都设为 `null` 并清空本类规则。存量配置若只对其中一侧自定义，未修改的一侧继续保持 `null` 继承。角色没有继承开关。

“全部”也是固定候选项，用同一个三档开关选择允许或禁止后，其它候选暂时收起；切回未设置可在保存前恢复原按项草稿。组织的“全部组织”映射全部根组织并按所选模式匹配子组织；仅选“自身及全部下级”时才收起其它组织候选。“无组织”使用独立选项；“用户默认组织”的底层值仍是 `_DEFAULT_`。简单模式不显示特殊规则列表；切到高级模式可查看并按权限编辑存量规则。动态组织节点切换常用匹配模式时，已选的允许或禁止随之切换到新规则；切回未设置会清除该节点的普通匹配规则与模式选择。所有选择只映射原有六个范围字段，不修改后端结构或授权计算。

动态组织候选切到允许或禁止时采用“自身及全部下级”作为起始模式，可通过该行下拉框切换常用匹配模式。高级模式保留原有允许与禁止双列表、预设规则含义说明、单侧继承以及添加、编辑、删除入口，不限制切换用户；含 Groovy 的组织范围对非超级管理员只读。页面候选受当前操作者权限限制，保存时服务端再次校验，越权或乐观锁冲突会按接口错误反馈。

弹窗底部右侧固定显示“保存”和“保存并关闭”，候选框滚动时仍可操作。最小验证：把同一领域从未设置切到允许，再切到禁止，确认只有禁止列表包含该规则；切回未设置，确认两边都不包含。将全部组织切到禁止，确认公共组织树收起，保存载荷只新增全部根组织的禁止规则，无组织保持原设置。对测试用户可验证关闭自定义后两个字段都继承角色配置。
