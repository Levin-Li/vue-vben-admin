# 全局选择器 Header 与授权契约

本说明面向使用 `@levin/admin-framework` 的项目。全局选择器提供的是**请求上下文**，不是授权能力；最终允许范围始终由后端根据当前登录主体计算。

## Header 格式

| 维度 | 单选 | 多选 |
| --- | --- | --- |
| 平台领域 | `X-Oak-Domain-Id` | 不支持 |
| 组织 | `X-Oak-Org-Id` | `X-Oak-Org-Id-List` |
| 拥有者 | `X-Oak-Owner-Id` | `X-Oak-Owner-Id-List` |

组织和拥有者多选值为去重且非空的逗号分隔 ID，例如 `org-a,org-b`。单选与多选 Header 在同一维度互斥；清空或未选择时不发送该维度 Header。

请求客户端不会再修改 `orgId`、`orgIdList`、`ownerId` 参数或请求体。因此，业务接口的显式查询条件保持原样；后端若声明具名范围变量，显式参数优先于 Header，空值才可回退 Header。

## 接入要求

- 项目使用框架提供的请求客户端，不要手工复制 Header 注入逻辑。
- 后端必须逐项校验 Header 候选，不能以 Header 值本身授予跨租户、跨组织或越机密级别访问。
- 多选列表出现空元素、重复元素或任一越权候选时，后端应拒绝整次请求。
- 业务页面若需要读取当前选中状态，使用公共导出，不要导入包内 `src` 路径；具体状态 API 见 `global-user-org-context.md`。

## 请求专用范围

候选查询需要使用目标租户及其已授权组织时，可在请求配置中传入 `__globalUserOrgContext: { tenantId, orgIds }`；`orgIds` 为字符串数组，即使只有一个值也使用 `X-Oak-Org-Id-List`。可选 `ownerIds` 同样使用列表头。显式范围不会继承顶部租户、组织或用户，领域上下文继续按当前全局领域发送。组织及用户 ID 不得包含逗号或空白，不得重复；服务端仍必须核实租户和逐项授权，不得把客户端范围作为授权依据。调用方需要完整组织集合时还应由服务端验证集合完整性。

`__skipGlobalUserOrgContext: true` 优先于显式范围，跳过顶部及显式租户、组织、用户头，领域头仍保留。调用方直接传入的上下文 Header 会先被清除，不区分大小写；只有通过明确配置生成的范围参与请求。旧规则对象 `isOverride` / `isRequired` 不改变 Header 行为。

## 刷新行为

有效选择、切换或清空会让框架重新加载菜单与当前活动页。业务组件应把选择器状态视为只读上下文，不应通过本地写入伪造选择或自行放宽后端范围。

## 编辑请求的原记录租户定位

编辑表单不展示或不提交租户输入时，公共 CRUD 仍将原记录的 `tenantId` 作为技术定位参数传给更新接口；这不允许修改记录归属，也不把 `tenantId` 加入强制更新字段。普通更新、API 更新回调、自定义更新路径、独立 JSON 编辑及行内启用操作使用同一规则。若最终载荷已显式携带租户则保留原值；原记录没有有效租户时不从当前用户、全局选择器或其它记录推断。实际目标和租户访问范围仍由后端验证。
