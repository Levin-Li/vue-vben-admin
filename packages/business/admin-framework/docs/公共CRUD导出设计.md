# 公共 CRUD 完整分页导出设计

## 目标与边界

公共 CRUD 导出面向不同业务列表服务。列表服务可能接受每页 2000 条，也可能裁剪页大小；前端必须在不修改当前页状态的前提下读取全部匹配记录。字段选择、展示值转换、50,000 条上限和权限检查均沿用公共组件既有规则。导入仍使用现有 `batchCreate` 与字段映射流程。

## 分页决策

导出开始时冻结当前激活 `ListTable` 的查询与排序，从第 1 页顺序请求。返回条数小于请求的 2000 可能只是后端裁剪页大小，不能独立证明已经到末页。响应提供有效总数时，在累计读取达到总数后结束；总数缺失或不可用时继续请求到空页。后续页与前一页的稳定记录 ID 完全重复，视为页码未推进，拒绝生成误导性的文件。每页读取后仍检查权限代际，累计超过 50,000 条则停止。

这一策略优先保证完整性，可能比使用短页判断多发起一次只读请求。它不改变后端 API，也不提供跨多个 HTTP 请求的数据库快照；高频变动列表需要由业务方另行设计快照语义。

## 数据与权限

导出文件只包含用户选定且允许读取的列。列表数据与导出数据经过同一字段组读取策略；导出过程中权限状态变化时立即停止。导入是独立写操作，必须有 `batchCreate` 方法和权限，文件映射不能授予字段或目标数据访问权。
