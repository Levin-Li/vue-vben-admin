# 前端菜单与动态路由设计

本文定义管理后台中“授权菜单 → 自定义展示菜单 → Vue Router → 侧边菜单”的完整契约，并说明租户、域名和标签栏状态对最终导航的影响。

## 1. 目标与边界

- 后端是菜单权限和租户范围的最终来源；前端不自行扩大可访问菜单。
- 自定义菜单只调整展示结构、名称、顺序和启用状态，不修改真实 `Menu.parentId`、接口权限或菜单资源标识。
- 前端路由只为后端最终下发的菜单路径注册页面；未下发的业务路径不得因本地页面映射存在而自动可访问。
- 分组可以只有子菜单，也可以同时拥有自身页面。后者必须既能展开子菜单，也能在允许的交互条件下进入自身页面。

## 2. 关键术语

| 名称 | 含义 |
| --- | --- |
| 系统菜单 | 后端 `Menu` 记录及其资源权限，是授权判断依据。 |
| 自定义菜单布局 | `TenantCustomMenu.itemList` 保存的展示树；节点以 `path` 关联系统菜单或已注册前端页面。 |
| 租户公共布局 | `TenantCustomMenu.domain` 为空的布局。 |
| 域名专属布局 | `TenantCustomMenu.domain` 与当前租户站点域名相同的布局。 |
| 平台用户 | 没有归属租户的用户，使用 `isPlatformUser()` 判断。 |
| 分组自身页面 | 一个含有 `children` 的菜单节点，同时配置了可解析的页面路径。 |

## 3. 后端：授权菜单与自定义布局

入口是 `RbacResServiceImpl#getAuthorizedMenuList`。

### 3.1 平台用户与租户用户

- 平台用户不应用租户自定义菜单布局，直接返回其已有授权系统菜单。
- 租户用户使用当前域名解析出的租户上下文读取布局；无法解析时才退回用户租户。
- 旧 `isSaasUser()` 仅作兼容，不应用于新的用户身份判断；统一使用 `isPlatformUser()` / `isTenantUser()`。

### 3.2 布局选择

`TenantCustomMenu` 实现 `MultiTenantPublicObject`，并声明：

```java
@SelfOverridableObject(overrideColumnNames = {E_TenantCustomMenu.domain})
```

默认生成服务的 `loadCacheList(tenantId, predicate)` 负责租户与公共数据的覆盖合并。授权菜单的候选条件为：

```text
layout.enable = true
AND layout.itemList 非空
AND (layout.domain = 当前域名 OR layout.domain 为空)
```

选择顺序：

1. 当前域名精确匹配的布局优先；
2. 同一优先级保持默认服务既有排序；
3. 没有域名专属有效布局时使用租户公共布局；
4. 没有有效布局时回退授权系统菜单。

### 3.3 布局节点下发

- `item.enable = false` 时，该节点及其整个子树不下发。
- 布局节点能关联到授权系统菜单时，保留系统菜单的页面、图标、权限和操作元数据，再叠加布局标签和子树。
- 已解析系统菜单的子节点若暂时缺少后端菜单源记录，保留为受控布局子节点，使已保存的“父菜单 → 子菜单”结构不因菜单同步滞后而丢失。
- 根级节点或纯虚拟分组下的未知路径不下发，避免自定义 JSON 扩大导航访问范围。

后端不负责前端组件选择；它输出的是已授权、已裁剪的 `MenuInfo` 树。

## 4. 前端：从菜单树生成路由

入口链路：

```text
authorizedMenuList
  → buildMenuRoutes
  → generateRoutesByBackend
  → generateAccessible
  → generateMenus
  → LayoutMenu
```

### 4.1 页面映射

每个后台页面映射同时维护：

- 后端菜单路径，例如 `/clob/V1/Nation`；
- `viewPath`，例如 `/system/com_levin_oak_base/nation/index.vue`；
- `sourceFilePath`，用于菜单同步与源码定位；
- `resource`，用于路径无法精确命中时的资源名兜底。

`LocalPage` 路径优先使用该映射加载 Vue 页面。一个未在当前菜单树中的已注册页面会注册为无权限页，不会因为本地有页面文件而直接开放。

### 4.1.1 应用入口、模块首页与路由上传

应用入口、模块首页、CRUD 子页面和“上传前端路由”是相邻但职责不同的层次：

```text
Bootstrap preferences.defaultHomePath
  → 模块根路径，例如 /clob/V1/index
  → 模块 routes.ts 的默认首页子路由（path: ''）
  → 模块 views/home/index.vue

模块 routes.ts（非 CRUD 页面） + admin-crud.ts（CRUD 子页面）
  → module.ts 组装为最终模块 routes
  → 上传前端路由
  → backendRouteMappings 提供 sourceFilePath 与 viewPath
  → 后端菜单
  → 登录后 buildMenuRoutes 重新加载同一 Vue 页面
```

各层职责如下：

| 位置 | 职责 | 不应承担的职责 |
| --- | --- | --- |
| 入口应用的 `preferences.defaultHomePath` | 决定访问 `/` 时默认进入哪个模块路径 | 定义模块页面组件或 CRUD 子页面 |
| 模块 `routes.ts` | 定义非 CRUD 页面，例如模块首页的默认子路由 | 生成实体 CRUD 路由 |
| 模块 `admin-crud.ts` | 生成用户、角色、文章等 CRUD 子页面 | 定义模块首页或其它非 CRUD 页面 |
| 模块 `module.ts` | 将模块首页、CRUD 子页面和其它模块路由组装成最终 `routes` | 直接承载首页业务界面 |
| `backend-route-mappings.ts` | 把后端菜单路径映射到同一个模块 Vue 页面，并为上传提供页面位置 | 替代后端权限判断或生成菜单层级 |
| `views/home/index.vue` | 承载模块首页的实际业务界面 | 决定应用根入口路径 |

模块根路径如果既是菜单分组又有可访问首页，它不是纯目录节点，必须提供完整页面映射。例如后台管理模块首页：

```ts
{
  path: '/clob/V1/index',
  resource: 'AdminHome',
  sourceFilePath: 'modules/com_levin_oak_base/views/home/index.vue',
  viewPath: '/system/com_levin_oak_base/home/index.vue',
}
```

`sourceFilePath` 是“上传前端路由”同步给后端的源码定位信息；`viewPath` 是运行时通过页面注册表加载组件的路径。两者必须指向同一个模块页面。纯分组、重定向和外链没有实际 Vue 页面，不得伪造上述映射。

### 4.1.2 基础框架消费者的模块首页规则

所有使用 `@levin/admin-framework` 的项目都必须遵循本节，不能仅在当前 Bootstrap 示例中约定：

1. 应用入口必须通过 `preferences.app.defaultHomePath` 指向一个明确、可访问的模块首页路径；不得把根路径 `/`、上次访问页或没有页面组件的目录节点当作默认首页。
2. 模块首页是业务模块页面，必须由模块自身固定文件 `routes.ts` 定义，并由固定文件 `module.ts` 组装进最终 `routes`。不得使用其它文件名替代，也不得把模块首页定义在 `admin-crud.ts` 或其它 CRUD 路由生成器中。
3. 模块首页组件、专属工具函数和页面测试必须位于该业务模块固定目录 `views/home/` 内；入口应用的 `_core/home` 只能承担应用级公共首页，不能替代业务模块首页。
4. 模块根菜单同时具有子菜单和首页时，首页必须作为根路由的默认子路由 `path: ''`，并设置 `hideInMenu: true`，避免在侧边栏重复显示首页菜单。
5. 模块首页是可访问本地页面时，必须在所属模块的 `backendRouteMappings` 中提供与实际文件一致的 `path`、`viewPath` 和 `sourceFilePath`，保证“上传前端路由”、后端菜单同步和登录后的动态路由加载同一页面。
6. 纯分组、重定向和外链不是模块首页，不得为了通过菜单同步而伪造页面映射；如果模块根路径没有实际首页，应保持目录节点语义，而不是配置为默认首页。

模块首页的文件落点和文件名必须统一。下表中的 `<app>`、`<package>` 和 `<module>` 仅表示项目名、npm 包目录名和扁平化模块包名三个变量；其余目录层级与文件名必须完全一致，不得改名、移动或合并到其它文件：

| 文件 | 必须负责的内容 | 后台管理模块当前示例 |
| --- | --- | --- |
| `apps/<app>/src/preferences.ts` | 设置 `preferences.app.defaultHomePath`，指定应用根入口的默认模块路径 | `apps/bootstrap-app/src/preferences.ts` → `/clob/V1/index` |
| `apps/<app>/src/modules/list.ts` | 启用业务模块，保证入口应用收集到模块的路由、页面映射和上传映射 | `apps/bootstrap-app/src/modules/list.ts` |
| `packages/business/<package>/src/modules/<module>/routes.ts` | 定义模块首页等非 CRUD 路由；模块首页使用 `path: ''` 和 `hideInMenu: true` | `oak-base-admin/.../com_levin_oak_base/routes.ts` |
| `packages/business/<package>/src/modules/<module>/module.ts` | 将首页路由、`admin-crud.ts` 生成的 CRUD 子路由和其它模块路由组装为最终 `AdminFrontendModule.routes` | `oak-base-admin/.../com_levin_oak_base/module.ts` |
| `packages/business/<package>/src/modules/<module>/admin-crud.ts` | 只生成 CRUD 子页面，例如用户、角色、文章；不定义首页 | `oak-base-admin/.../com_levin_oak_base/admin-crud.ts` |
| `packages/business/<package>/src/modules/<module>/views/home/index.vue` | 承载模块首页实际业务界面 | `oak-base-admin/.../com_levin_oak_base/views/home/index.vue` |
| `packages/business/<package>/src/modules/<module>/views/home/` | 存放首页专属工具函数、子组件与测试 | `oak-base-admin/.../views/home/overview-utils.ts`、`__tests__/overview-utils.test.ts` |
| `packages/business/<package>/src/modules/<module>/page-map.ts` | 将模块 `views/**/*.vue` 注册为可由 `viewPath` 解析的页面映射；新增首页后必须可解析对应 `viewPath` | `oak-base-admin/.../com_levin_oak_base/page-map.ts` |
| `packages/business/<package>/src/modules/<module>/backend-route-mappings.ts` | 定义模块路径、`sourceFilePath`、`viewPath` 和业务 `resource` 的对应关系，供上传和动态菜单加载复用 | `oak-base-admin/.../com_levin_oak_base/backend-route-mappings.ts` |
| `packages/business/admin-framework/src/framework-commons/app/utils/sync-menu-routes.ts` | 框架统一把已启用模块的路由和页面映射组装为“上传前端路由”载荷；业务项目不应复制实现 | 框架公共实现 |

其中模块的 `sourceFilePath` 必须相对于该模块前端源码目录填写，例如 `modules/com_levin_oak_base/views/home/index.vue`；`viewPath` 必须是页面注册表的运行时路径，例如 `/system/com_levin_oak_base/home/index.vue`。两者不能指向入口应用的 `_core/home`、其它模块目录或不存在的文件。

禁止使用 `home-route.ts`、`dashboard.ts`、`router.ts`、`homepage.vue` 等替代名称，也不得把模块首页放在 `pages/`、`components/`、入口应用 `src/pages/_core/home/` 或 CRUD 页面目录中。这样“上传前端路由”的 `sourceFilePath` 才能按统一规则直接定位到 `modules/<module>/views/home/index.vue`，无需按项目猜测文件位置。

代码审查和验收时，应同时检查入口配置、模块路由、首页组件目录、`backendRouteMappings` 以及上传后的后端菜单路径是否形成同一条链路。

### 4.2 三类菜单路由

| 菜单形态 | 路由形态 | 菜单行为 |
| --- | --- | --- |
| 叶子菜单 | 页面组件路由 | 点击直接进入页面。 |
| 纯分组 | `BasicLayout` 或 `RouteView` + 子路由 | 点击只展开/收起。 |
| 分组自身页面 | `RouteView` + `path: ''` 的默认页面子路由 + 其它子路由 | 可展开；在标签栏启用时点击标题进入自身页面。 |

分组自身页面的默认子路由必须使用空路径：

```ts
{
  component: groupPageRoute.component,
  meta: { ...groupPageRoute.meta, hideInMenu: true },
  path: '',
}
```

这样访问父路径时会渲染自身页面，但默认子路由不会额外显示为重复菜单。

### 4.3 顶级分组空白页保护

动态路由由根 `BasicLayout` 承载。顶级分组如果有默认子页面，不能再保留一个嵌套 `BasicLayout`，也不能删除其容器组件。

因此该类分组使用 `RouteView`，并设置：

```ts
meta: {
  preserveComponentWhenChildren: true,
}
```

`generateAccessible` 只会删除普通顶级分组的冗余容器；标记了 `preserveComponentWhenChildren` 的路由保留 `RouteView`。这保证 `/clob/V1/Nation` 能匹配并渲染默认子页面，而不会出现地址栏正确、内容区空白的情况。

## 5. 标签栏与分组点击

分组自身页面的路由标记为：

```ts
meta: {
  navigateOnClick: true,
}
```

布局层在分组展开事件中读取目标动态路由的该标记，再按实时偏好设置决定是否导航：

- `preferences.tabbar.enable === true`：点击分组先展开/收起，再导航到分组自身路径；原页面保留在标签栏中。
- `preferences.tabbar.enable === false`：点击分组只展开/收起，不切换当前内容页，也不会自动跳转到其默认子页面。

普通叶子菜单始终可导航；没有自身页面的分组始终只展开/收起。

## 6. 安全约束

- 后端先依据系统菜单和权限裁剪，再应用布局；布局不能使无权限系统菜单重新出现。
- 前端只把最终展示树中的路径变为可访问路由；未纳入布局的映射页使用无权限兜底组件。
- 缺少系统菜单源的受控回退只允许出现在已解析父菜单之下，防止根级未知路径进入导航。
- 标签栏开关只影响“分组标题是否触发导航”的体验，不影响后端接口权限或叶子菜单访问权限。

## 7. 关键实现位置

- 后端授权与布局树：`services-impl/.../biz/rbac/RbacResServiceImpl.java`
- 布局实体与覆盖键：`entities/.../TenantCustomMenu.java`
- 后端菜单转前端路由：`framework-commons/app/api/core/menu-route.ts`
- 动态路由装配：`packages/effects/access/src/accessible.ts`
- 路由转侧边菜单：`packages/utils/src/helpers/generate-menus.ts`
- 分组点击与展开：`packages/@core/ui-kit/menu-ui/src/components/sub-menu.vue`
- 标签栏开关对菜单的约束：`packages/effects/layouts/src/basic/layout.vue`

## 8. 验证基线

至少覆盖以下场景：

1. 域名专属布局优先于租户公共布局，禁用或空布局不生效；
2. 平台用户不应用租户自定义布局；
3. 布局禁用节点及其子树不下发；
4. 已解析父菜单下的已保存子项不会因菜单源暂缺而丢失；
5. 分组自身页面在顶级和嵌套层级均保留 `RouteView` 与默认子页面；
6. 标签栏启用时，分组点击同时展开并导航；关闭时只展开；
7. 直接访问未下发路径进入无权限页；
8. 重新构建 `access`、`menu-ui`、`layouts`、`admin-framework` 后，开发服务器不出现模块解析错误。
