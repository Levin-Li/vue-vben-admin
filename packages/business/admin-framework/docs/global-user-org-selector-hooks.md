# 全局组织与用户选择器

底层 `UserOrgSelector` 保持通用：只加载候选、保存选中记录并发出事件。调用方通过 hook 或包装层决定候选来源、默认值、显隐、是否允许清空和选中校验。

全局包装层规则：所有选择器默认空选。普通用户实际可操作候选不大于一时隐藏且不注入上下文；候选大于一时展示，选中后不可主动清空。管理员和超级管理员只要服务端启用组织与用户选择器即展示，并可清空。领域选择器候选不大于一时隐藏，当前固定为单选且允许清空，远程 `multiple` 配置不会生效。组织与用户选择器在 `multiple=true` 时支持服务端 `maxSelectCount`：正整数限制最多选择数，缺失或非正值不额外限制。全局上下文只通过请求头传递，不再覆盖查询面板或业务请求参数。

候选采用按需加载：页面初次挂载不会请求组织树、用户候选或平台租户候选。用户首次展开下拉框时才加载当前授权范围，之后重复展开复用已加载结果；配置范围或当前用户身份变化后，下一次展开重新加载。

## 节点类型与请求上下文

公共选择器支持 `tenant`、`org`、`user` 三种节点类型。页面通过唯一配置 `selectableTypes` 声明允许选择的节点类型，例如 `['org']`、`['org', 'user']` 或 `['tenant', 'org', 'user']`；不再使用 `mode`、`allowSelectOrg` 或 `allowSelectUser`。

组织层级保持后端原有父子结构。只有平台用户在运行时把返回记录按 `tenantId` 包装为租户根节点；记录已有 `tenantName` 时直接使用，缺失时才从授权租户候选补齐名称。非平台用户不展示跨租户根节点。

全局选择通过 Header 传递范围：租户为 `X-Oak-Tenant-Id`；组织额外为 `X-Oak-Org-Id`（多选为 `X-Oak-Org-Id-List`）；用户额外为 `X-Oak-Owner-Id`（多选为 `X-Oak-Owner-Id-List`）。选择组织或用户时也必须发送其所属 `X-Oak-Tenant-Id`；后端仍按授权范围校验。
