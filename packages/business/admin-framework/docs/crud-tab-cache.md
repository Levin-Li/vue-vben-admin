# 标准 CRUD 标签缓存接入指南

## 入口与前提

使用 `@levin/admin-framework` 的动态菜单页面，如需切换标签后保留组件状态，应在 `AdminBackendRouteMapping` 中声明 `keepAlive: true`。同时，宿主应用的标签栏及标签缓存偏好必须开启。只有实际的本地页面映射会透传该标记；未声明时保持原有重新挂载行为。

标准 CRUD 页面也可由超级管理员在“展示设置2”中设置“切换标签时保留页面”，然后上传该页面设置。未配置时沿用上述路由声明；开启后，原本未声明缓存的页面也能保留状态；关闭后，即使路由声明了缓存也会在切回时重新挂载。可点“恢复路由默认”撤销页面级覆盖。设置按页面编码及现有适用范围解析，只有当前匹配的设置会作用于当前页面；全局标签缓存偏好关闭时页面设置不生效。

后端菜单转换会把缓存标记传给承载该页面的父级 `RouteView`。缓存只由布局外层按标签键持有，每个标签保留一棵完整页面树；嵌套 `RouteView` 使用该标签自己的路由快照，不再单独缓存叶子页面。失活标签不会跟随其它标签的导航生成新实例，其 `useRoute()` 也保持所属标签的路由。业务模块只需在叶子映射声明一次。

## 行为与边界

缓存沿用标签栏的路由名和完整路径 key。同一标签切走再返回时保留当前组件实例，因此标准 CRUD 的分页、查询条件和排序不会因切换而重置。不同路径的标签独立缓存。关闭标签后重开、点击手动刷新，或租户等全局请求上下文变化时，仍按现有机制失效并重新加载；页面数据的实时性不能只依赖标签缓存。

页面设置上传使用现有界面设置接口。入口仅对超级管理员展示，服务端继续检查登录和保存权限；上传失败时设置不会成为当前页面的新配置。标签缓存只保留前端实例，不改变数据查询、编辑提交和权限校验结果。

`keepAlive` 只影响前端组件生命周期，不授予 API 权限，也不跳过服务端查询及保存校验。需要保持最新数据的页面可在激活时主动刷新，但不要将普通标签切换误作整页刷新。

## 最小验证

在一个声明了 `keepAlive: true` 的标准 CRUD 页面设置查询条件并切到第 2 页，切换至另一个标签后返回：页码和条件应保留，且单纯返回不新增列表请求。再执行标签手动刷新，确认列表重新加载。若未保留，先检查全局标签缓存偏好和最终路由的 `meta.keepAlive`。

对原本未声明缓存的页面，可在“展示设置2”开启页面级配置并上传，再重复上述切换验证；关闭配置后切回页面应重新加载。上传后如未生效，先确认当前页面编码及适用范围命中保存记录，再检查全局标签缓存偏好。
