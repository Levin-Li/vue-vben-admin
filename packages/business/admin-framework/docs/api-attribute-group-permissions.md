# API 属性组授权接入指南

角色管理的资源授权编辑器将 Java 业务实体各接口的属性组汇总在该实体资源类型节点，以区别于操作的标签图标标识“属性组”，并显示可勾选的组名。悬停组名只显示成员属性的中文名称列表，例如“合同金额、税率、结算账号”，不显示字段代码、注解备注或“包含：”前缀；同一实体的组只勾选一次，对该角色已获授权的相关接口生效。操作权限仍单独勾选，取消操作不清除实体组配置；没有操作权限时，组配置本身不能开放字段。动态数据模型字段组仍按原模型动作展示。

`@RbacDataAttrGroup` 可以标注在类、字段或 JavaBean getter 上。类级声明用 `attrList` 指定同组的多个属性；同一资源类型的不同接口使用完全相同的组名时，角色只保存一条组权限，悬停列表汇总各接口成员的 `@Schema.title` 中文名称，包括仅在请求或响应模型中定义的字段。运行时每个接口仍只限制它自己的请求与响应模型中属于该组的字段，不会把一个接口的属性添加到另一个接口。若不希望两个接口共享组授权，须使用不同组名或资源类型。仅去除空格后才相同的不同原始组名视为配置冲突，不自动合并。

页面调用其它实体的独立 API 时，以该请求实际命中的接口操作重新计算属性组，不能借用页面主实体的组授权。当前 API 的请求或响应中嵌入其它实体时，关联实体的受控组不加入当前操作的可分配目录；这些输入被拒绝、输出被省略。需要展示关联实体敏感属性的场景，应使用经过单独授权的目标实体接口，或明确设计该业务接口的跨实体授权边界。

## 后端元数据

沿用现有授权资源树接口和角色 `permissionList` 更新接口。静态实体组聚合在对应的 `ResourceType` 节点；操作节点仍可携带适用组元数据供后端与兼容逻辑使用：

```json
{
  "id": "example:业务数据-合同",
  "name": "合同",
  "nodeType": "ResourceType",
  "attrGroups": [
    {
      "name": "财务信息",
      "entityScope": true,
      "scopeKey": "example:业务数据-合同",
      "permissionExpr": "example:业务数据-合同:DataAttrGroup@摘要:access",
      "attributes": ["合同金额", "税率", "结算账号"],
      "remark": "允许该实体已授权接口输入和输出这些属性"
    }
  ],
  "children": [
    {
      "id": "contract-calculate",
      "name": "合同试算",
      "nodeType": "Action",
      "permissionExpr": "example:业务数据-合同::试算"
    }
  ]
}
```

表达式仅为协议示例。生产表达式必须由后端提供，前端不会根据组名、实体名或 API 路径拼装。静态组权限沿用四段 `domain:type:res:action`，前两段来自接口权限注解；`res` 为稳定的属性组标识，组名在标识和显示前均去除空格。`attributes` 使用适合管理员阅读的属性名称，`remark`、`entityName` 为可选说明。旧接口级组权限只对原接口有效，不自动扩大为实体级。

后端以解析后的 `@ResAuthorize.domain + type` 确定资源类型归属；方法的输入参数和返回类型只用于发现该操作实际涉及哪些组和受控字段。容器内可展开模型，但关联到其他实体时停止归集；例如客户操作不会因关联法律主体而展示法律主体的开票信息组。运行时仍按原有规则检查嵌套敏感字段，不能通过关联字段绕过授权。

## 分配与保存

在实体资源类型节点勾选允许使用的组，并分别勾选需要开放的操作。组可先于操作配置；角色没有对应操作权限时不会获得字段访问权。勾选组仅添加后端提供的完整表达式到现有 `permissionList`；保存与回显的合法集合同时包含操作表达式和组表达式。取消操作时保留实体组选择，后来增加操作时仍须经过服务端转授权检查。

“全选”业务操作不会自动授予所有受控属性组。需要管理员打开入口选择。删除被通配表达式覆盖的操作时，编辑器沿用既有通配权限拆分行为，保留其它已选操作与其组。

## 安全与验证

前端禁用和勾选仅是授权编辑体验。角色授权范围、实际请求检查和 JSON 响应过滤必须由后端执行；无权参数拒绝整次请求，无权响应字段直接省略。字段结构归开发阶段的 API 静态契约所有；已有登录 `userInfo` 响应只提供当前用户有效的操作与组许可，前端在本地合并，不下载字段图。

最小验证：打开角色的资源权限分配，确认同一实体的组只在资源类型节点出现一次，属性组图标不同于操作图标，悬停仅出现中文属性名称；选择操作和组后保存、重开仍勾选；取消操作后组保持选中但无法访问该操作字段。仅有组权限而无操作权限不能调用该操作。授权编辑器沿用原有 API 路径；标准前端登录和业务操作均不调用 `apiDataAttrPolicies` 或 `apiDataAttrPolicySnapshot`。

## 标准 CRUD 的输入与输出

标准 CRUD 按实际接口读取已注册的静态契约，结合当前登录的有效组许可在内存生成策略，不为打开页面、切换标签或逐个接口再发策略查询。创建和编辑只展示、验证并提交允许输入的字段；默认值、复杂对象映射、页面 `transformSubmit` 和专用 JSON 编辑构造完成后，再裁剪最终赋值字段及 `forceUpdateFields`。主键、版本、租户／组织上下文、菜单固定条件及非表单参数先按原值校验，不能被裁剪后继续扩大操作范围；其它明确范围键可用 `dataAttrConditionKeys` 声明。受限更新裁剪后若没有任何业务赋值会拒绝，不发送空更新；新增仍遵守允许服务端默认创建的接口契约。隐藏必填字段不会阻止用户填写其它允许字段。布尔快捷更新和批量导入也检查各自的实际操作，批量新增不继承单条新增的组权限。

查询条件、排序、菜单固定条件和删除标识使用拒绝方式校验。旧查询草稿或保存的排序若包含当前许可不允许的属性，会阻止请求并提示，不会删除条件后执行更宽的查询。列表、详情及导出候选按响应策略过滤，历史导出模板不能恢复受限字段。身份许可未就绪时不开放受控操作；已有编辑草稿保留，保存失败不会自动改写载荷并重试。

标准 API 服务方法通过其 `@ResAuthorize` 操作身份与真实请求目标定位静态声明，包括仅要求登录但仍声明了操作标识的方法。标准 `@CRUD.ListTable` 列表服务使用自身的完整模块请求路径，不必每个页面单独配置。批量导入在点击时读取本地声明与许可；后端禁用的接口不能由页面开放。不能从 `apiService.create` 这个方法名称推断真实 HTTP 路径。若同一操作对应多个处理器，或方法没有可定位的操作声明，应用需提供实际目标：

```ts
const config = {
  apiBase: '/Contract',
  apiService: contractService,
  title: '合同',
  fields: contractFields,
  dataAttrTargets: {
    create: {
      method: 'POST',
      path: '/com.example/V1/api/Contract/submitApplication',
    },
    batchCreate: {
      method: 'POST',
      path: '/com.example/V1/api/Contract/importBatch',
    },
  },
};
```

`path` 是实际完整 API 路径，可以指定 `contentType`；它不承载权限表达式。目标必须与真实请求一致。通用 CRUD 自己发出的固定 HTTP 请求能够直接使用其实际方法和模块路径；动态创建路径和自定义 API 别名不能提前猜测。多个处理器无法唯一定位时阻止操作，并要求显式配置。

## API 开发期静态声明

每个业务模块在自己的 API 目录维护静态契约，开发或构建阶段由后端控制器、请求和响应类型的真实注解导出并校验。契约包含版本、方法、完整路径、操作、分组及请求/响应字段图，不含用户授权结果。发布模块在页面消费前注册它：

```ts
import {
  initializeDataAttrFieldGrants,
  registerDataAttrStaticContract,
} from '@levin/admin-framework';

// apiContract 来自该模块构建生成的版本 1 静态契约。
registerDataAttrStaticContract(apiContract);

// userInfo 来自既有认证响应，不另发字段权限请求。
initializeDataAttrFieldGrants(userInfo.fieldGroupGrants);
```

注册输入为 `{ version: 1, policies: [...] }`；`userInfo.fieldGroupGrants` 为 `{ version: 1, allowed: [{ operation, groupKeys }] }`。静态图不保存 `allowed`，组键必须使用契约给出的稳定键，不能根据显示名称拼装。独立子模块使用同一个注册入口，不硬编码基础模块路径前缀。Oak 的输出为所属 API 目录中的 `data-attr-contract.json`，不生成业务页面。

`@RbacDataAttrGroup` 的类级 `attrList`、字段/getter、继承、嵌套及 JSON 名称映射必须在导出图中保留。不同接口的输入和输出分别声明；页面调用其它实体的 API 时使用那个 API 的契约，不复用主实体字段集合。自定义 Mapper 或路由需要显式提供匹配的导出上下文，避免声明与实际序列化不一致。

### 导出与一致性门禁

本仓库在后端根目录执行以下命令，使用已配置的 JDK/Maven 编译当前 reactor 后运行独立导出器：

```bash
scripts/export-static-data-attr-contract.sh
scripts/export-static-data-attr-contract.sh --check
```

默认输出为 `frontend/admin/packages/business/oak-base-admin/src/modules/com_levin_oak_base/api/data-attr-contract.json`。`--check` 发现文件缺失或定义漂移时失败，不修改已登记契约。后端注解、请求/响应模型、JSON 映射或控制器路径变化后应重新导出，再检查。

下游模块以自己的编译输出及依赖构成 classpath，并明确控制器包及前端 API 输出目录：

```bash
java -cp '<reactor classes及依赖>' \
  com.levin.oak.base.web.dataattr.DataAttrContractExporter \
  --package example.business.controller \
  --output frontend/src/api/data-attr-contract.json \
  --check
```

首次生成时去掉 `--check`。`--package` 可重复指定；存在影响 JSON 字段的命名策略、MixIn 等配置时，加 `--mapper-customizer example.ContractMapper`，该类须实现 `Consumer<ObjectMapper>` 并配置与运行时一致的 Mapper。默认工具不构造控制器、不启动业务容器或数据源；自定义 Mapper 配置类会执行可信开发代码，应只配置 Mapper，不能连接数据库或启动业务。动态路由、专属 MVC 前缀或多 Mapper 场景须用实际映射与转换器导出，不依赖默认扫描猜测。

在前端根目录运行 `pnpm run check:static-field-contract`。此门禁已接入标准发布脚本：存在后端源码时先做后端导出一致性检查，再对实际静态清单执行注册与许可测试；没有后端源码的独立前端仅验证静态结构与注册，不能证明和运行中后端一致，下游必须在自己的后端 CI 保留导出 `--check`。接口数、体积和真实浏览器验证仍须由每次交付记录，不以结构检查代替。

## 缺失声明和拒绝语义

身份已就绪但某接口没有静态声明时，前端不施加字段限制，控制台按会话及接口去重警告；不弹内部策略错误，不补发网络查询。该默认仅解决开发元数据缺失，后端真实授权不变。已声明受控分组却没有对应有效许可时必须拒绝；空许可不等于未声明。非法版本、冲突/歧义声明和身份未就绪不能伪装成“缺失声明”以放行。

## 会话加载、缓存与刷新

标准框架认证流程从既有 `userInfo` 取得有效组许可，并执行会话目录初始化任务。前端不复制后端授权表达式引擎；同一角色同时具备操作与组权限、机密级别及条件授权等结论仍由服务端计算。静态图随代码版本交付，当前许可只在会话内存保存，不保存业务记录。

退出、账号切换或显式强制权限刷新清空旧许可；旧请求即使晚返回，也不能覆盖新会话。普通切页、组件挂载或业务请求被拒绝，不触发字段策略的循环清空和重查。管理员修改授权后，刷新网页或重新登录以更新界面。刷新前的界面可能仍显示旧能力，但每个实际业务接口仍由后端按当前权限校验，因此撤权不能靠旧许可绕过。

自定义宿主同样注册静态契约并安装可信登录响应中的许可，不以本地构造的全允许许可替代认证。标准宿主的旧服务适配只读取本地契约，不得暗中调用字段策略或快照 HTTP 接口。过时的显式 loader/快照注入如仍保留，仅供独立宿主迁移或测试使用，不作为标准认证和 CRUD 加载链路。动态数据模型专属字段来源见[运行时元数据接入指南](runtime-crud-metadata.md)，其显式提供者失败不能当作静态声明缺失。

工作流能力关联目录按登录会话在内存加载一次。角色选项目录在每个页面首次实际需要时加载，登录时不预取；同页相同查询条件的并发调用合并为一次请求；角色关键词继续通过 `containsName` 在服务端搜索，新关键词独立查询并缓存，不同页面可各加载一次。分页和筛选查询参数变化不改变页面缓存键。缺少权限、未启用模块或可选目录加载失败时保持空结果，刷新或重登后重新获取。工作流资格、业务记录、历史和办理命令仍在用户操作时请求，并接受服务端重新授权。UI 设置编辑抽屉只在点击时创建并读取编辑所需的范围选项；页面生效配置仍在渲染时读取，以应用已有列、表单与布局设置。

最小请求验证：从登录到反复切换 CRUD 标签，`apiDataAttrPolicies` 与 `apiDataAttrPolicySnapshot` 请求数均为零。检查已声明无许可的字段拒绝、缺失声明仅控制台一次警告、不同模块同名组隔离以及退出换号不复用旧许可。工作流关联目录不随切页重发；未使用角色选择器的页面没有角色请求，同页反复使用选择器时相同角色查询只请求一次。未打开 UI 设置时不应请求编辑范围选项。使用撤权账号直接提交受控字段，仍须由业务后端拒绝。自定义表单的逐字段交互适配不由标准 CRUD 自动改写，最终安全边界始终是业务后端。
