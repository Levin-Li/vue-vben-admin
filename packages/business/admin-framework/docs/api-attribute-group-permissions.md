# API 属性组授权接入指南

角色管理的资源授权编辑器将 Java 业务实体各接口的属性组汇总在该实体资源类型节点，以区别于操作的标签图标标识“属性组”，并显示可勾选的组名。悬停组名只显示成员属性的中文名称列表，例如“合同金额、税率、结算账号”，不显示字段代码、注解备注或“包含：”前缀；同一实体的组只勾选一次，对该角色已获授权的相关接口生效。操作权限仍单独勾选，取消操作不清除实体组配置；没有操作权限时，组配置本身不能开放字段。动态数据模型字段组仍按原模型动作展示。

`@RbacDataAttrGroup` 可以标注在类、字段或 JavaBean getter 上。类级声明用 `attrList` 指定同组的多个属性；同一资源类型的不同接口使用完全相同的组名时，角色只保存一条组权限，悬停列表汇总各接口成员的 `@Schema.title` 中文名称，包括仅在请求或响应模型中定义的字段。运行时每个接口仍只限制它自己的请求与响应模型中属于该组的字段，不会把一个接口的属性添加到另一个接口。若不希望两个接口共享组授权，须使用不同组名或资源类型。仅去除空格后才相同的不同原始组名视为配置冲突，不自动合并。

页面调用其它实体的独立 API 时，以该请求实际命中的接口操作重新计算属性组，不能借用页面主实体的组授权。当前 API 的请求或响应中嵌入其它实体时，关联实体的受控组不加入当前操作的可分配目录；这些输入被拒绝、输出被省略。需要展示关联实体敏感属性的场景，应使用经过单独授权的目标实体接口，或明确设计该业务接口的跨实体授权边界。

## 后端元数据

沿用现有授权资源树接口和角色 `permissionList` 更新接口。静态实体组聚合在对应的 `ResourceType` 节点；操作节点仍可携带适用组元数据供后端与兼容逻辑使用：

```json
{
  "id": "example:业务数据-合同",
  "name": "合同",
  "nodeType": "ResourceType",
  "attrGroups": [
    {
      "name": "财务信息",
      "entityScope": true,
      "scopeKey": "example:业务数据-合同",
      "permissionExpr": "example:业务数据-合同:DataAttrGroup@摘要:access",
      "attributes": ["合同金额", "税率", "结算账号"],
      "remark": "允许该实体已授权接口输入和输出这些属性"
    }
  ],
  "children": [
    {
      "id": "contract-calculate",
      "name": "合同试算",
      "nodeType": "Action",
      "permissionExpr": "example:业务数据-合同::试算"
    }
  ]
}
```

表达式仅为协议示例。生产表达式必须由后端提供，前端不会根据组名、实体名或 API 路径拼装。静态组权限沿用四段 `domain:type:res:action`，前两段来自接口权限注解；`res` 为稳定的属性组标识，组名在标识和显示前均去除空格。`attributes` 使用适合管理员阅读的属性名称，`remark`、`entityName` 为可选说明。旧接口级组权限只对原接口有效，不自动扩大为实体级。

后端以解析后的 `@ResAuthorize.domain + type` 确定资源类型归属；方法的输入参数和返回类型只用于发现该操作实际涉及哪些组和受控字段。容器内可展开模型，但关联到其他实体时停止归集；例如客户操作不会因关联法律主体而展示法律主体的开票信息组。运行时仍按原有规则检查嵌套敏感字段，不能通过关联字段绕过授权。

## 分配与保存

在实体资源类型节点勾选允许使用的组，并分别勾选需要开放的操作。组可先于操作配置；角色没有对应操作权限时不会获得字段访问权。勾选组仅添加后端提供的完整表达式到现有 `permissionList`；保存与回显的合法集合同时包含操作表达式和组表达式。取消操作时保留实体组选择，后来增加操作时仍须经过服务端转授权检查。

“全选”业务操作不会自动授予所有受控属性组。需要管理员打开入口选择。删除被通配表达式覆盖的操作时，编辑器沿用既有通配权限拆分行为，保留其它已选操作与其组。

## 安全与验证

前端禁用和勾选仅是授权编辑体验。角色授权范围、实际请求检查和 JSON 响应过滤必须由后端执行；无权参数拒绝整次请求，无权响应字段直接省略。授权编辑器不在本地推导后端权限；运行时的 `allowed` 结论仅在当前登录会话内存中缓存，账号、权限变化或后端拒绝后立即失效。

最小验证：打开角色的资源权限分配，确认同一实体的组只在资源类型节点出现一次，属性组图标不同于操作图标，悬停仅出现中文属性名称；选择操作和组后保存、重开仍勾选；取消操作后组保持选中但无法访问该操作字段。仅有组权限而无操作权限不能调用该操作。授权编辑器沿用原有 API 路径；标准 CRUD 及通用请求门禁另通过 `apiDataAttrPolicies` 获取当前会话策略。

## 标准 CRUD 的输入与输出

标准 CRUD 按实际操作加载当前用户的后端策略。创建和编辑只展示、验证并提交允许输入的字段；默认值、复杂对象映射、页面 `transformSubmit` 和专用 JSON 编辑构造完成后，再裁剪最终赋值字段及 `forceUpdateFields`。主键、版本、租户／组织上下文、菜单固定条件及非表单参数先按原值校验，不能被裁剪后继续扩大操作范围；其它明确范围键可用 `dataAttrConditionKeys` 声明。受限更新裁剪后若没有任何业务赋值会拒绝，不发送空更新；新增仍遵守允许服务端默认创建的接口契约。隐藏必填字段不会阻止用户填写其它允许字段。布尔快捷更新和批量导入也检查各自的实际操作，批量新增不继承单条新增的组权限。

查询条件、排序、菜单固定条件和删除标识使用拒绝方式校验。旧查询草稿或保存的排序若包含已撤权属性，会阻止请求并提示，不会删除条件后执行更宽的查询。列表、详情及导出候选按响应策略过滤，历史导出模板不能恢复受限字段。权限变化或策略加载失败时，旧的允许结论立即失效；已有编辑草稿保留，保存失败不会自动改写载荷并重试。

标准 API 服务方法通过其 `@ResAuthorize` 操作身份加载策略，包括仅要求登录但仍声明了操作标识的方法。标准 `@CRUD.ListTable` 列表服务使用自身的完整模块请求路径定位列表策略，不必每个页面单独配置。批量导入策略只在用户点击导入时加载；后端禁用该接口或策略加载失败时不打开导入表单。不能从 `apiService.create` 这个方法名称推断真实 HTTP 路径。若同一操作对应多个处理器，或方法没有可定位的操作声明，应用需提供实际目标：

```ts
const config = {
  apiBase: '/Contract',
  apiService: contractService,
  title: '合同',
  fields: contractFields,
  dataAttrTargets: {
    create: {
      method: 'POST',
      path: '/com.example/V1/api/Contract/submitApplication',
    },
    batchCreate: {
      method: 'POST',
      path: '/com.example/V1/api/Contract/importBatch',
    },
  },
};
```

`path` 是实际完整 API 路径，可以指定 `contentType`；它不承载权限表达式。目标必须与真实请求一致。通用 CRUD 自己发出的固定 HTTP 请求能够直接使用其实际方法和模块路径；动态创建路径和自定义 API 别名不能提前猜测。多个处理器无法唯一定位时阻止操作，并要求显式配置。

标准框架认证流程会连接真实后端策略服务、按登录会话缓存策略，并在登录身份变化、权限刷新或后端拒绝后废弃缓存。自定义宿主应通过公开的 `configureDataAttrPolicyLoader` 接入真实后端 `apiDataAttrPolicies` 服务，响应必须遵守版本化策略图协议；不得在正式应用中返回本地假授权。尚未启用这项能力的旧宿主维持原有 CRUD 行为，仍由后端执行安全限制；一旦启用，加载失败或退出登录后的暂停状态不会退回旧行为。

本轮覆盖标准 CRUD 和公共请求校验。业务自定义表单通过公共网络门禁得到最终拒绝保障；其逐字段交互适配不由标准 CRUD 自动改写。
