# 公共 CRUD 导出开发指南

## 接入公共入口

业务页面使用公共 CRUD 配置声明列表 API 服务或列表路径，并通过控制器 `@CRUD.ListTable` 元数据确定当前列表。列表接口应支持稳定排序与递增 `pageIndex`；接受 `pageSize` 后可以裁剪至自身上限，但须返回对应页的 `items`，最好同时返回可信的 `totals` 和实际 `pageSize`。如果没有有效总数，公共导出会请求到空页。服务端不能忽略页码并反复返回同一批记录；检测到重复稳定 ID 时导出会失败。

页面无需自行实现全量翻页。导出使用打开时的查询、排序和字段组授权，默认只提供表格列；确需增加非表格字段时使用字段配置的 `export: true`，不允许导出时额外暴露查询参数或敏感字段。字段显示转换应与列表一致；复杂值需要明确的稳定文本转换。

## 导入与安全边界

需要导入的页面在 API 服务中提供受权的 `batchCreate`，公共页面才展示导入入口。文件列映射、默认值和前端转换只是录入辅助；后端仍须逐批校验租户、组织、字段权限、业务唯一性和目标状态。公共导入每批最多 2000 条，失败时前面成功批次不会自动撤销。

导出读取也必须由服务端对每页执行租户、组织与字段权限，前端选择列及 50,000 条限制不能替代后端授权或资源上限。需要严格一致快照、长时间大批量或跨表导出的业务，应设计专用受控服务端导出，不复用普通列表分页假定快照。

公共导出现在生成真正的 `.xlsx`，接口字段仍按列表展示文本写入，不可仅改扩展名或 MIME 而保留旧 XML 内容。自定义导出或扩展 `crud-file-export.ts` 时须保持 OOXML 部件关系、ZIP 成员 CRC32 与中央目录一致；工作表单元格为内联字符串，编号和公式样式文本不自动转型。新文件可交给现有公共导入解析器回读；历史 XML `.xls` 即使单元格含逗号也应保持按 XML 解析。不得为此增添第三方依赖或绕过原有字段权限。

## 最小验证

至少验证列表总数 250 且服务端每页裁剪为 100 时读取三页；未知总数时读取到空页；重复页拒绝；筛选、排序及活动 `ListTable` 不串用。保存后检查文件 ZIP、OOXML 部件、表头与记录文本，并以公共导入器回读含中文、前导零、逗号和公式样式文本的 XLSX；再在 macOS Numbers 实际打开文件、确认表头和数据行，不能只用包结构检查代替。还须验证旧 XML `.xls` 的逗号单元格仍可导入。对导入入口用隔离数据验证合法单条、非法字段和越权拒绝。使用步骤见[使用指南](公共CRUD导入导出使用指南.md)。
