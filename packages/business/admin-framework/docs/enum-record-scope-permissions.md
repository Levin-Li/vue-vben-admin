# 枚举记录范围授权接入指南

## 入口与前置条件

角色的资源授权树由 `ResourcePermissionTreeEditor` 展示。在已有资源节点上，只有服务端返回有效 `dataAttrs` 时才显示“数据范围”。旧资源、旧 `modules` 授权格式和 API 属性组的操作授权不变。

此入口控制可访问记录的枚举范围；字段本身是否可提交或返回，继续使用原有属性组授权。前端选项必须由后端提供，不能从字段标题、枚举名称或接口路径自行拼接许可表达式。

## 元数据示例

```ts
{
  id: 'partner',
  name: '合作伙伴',
  nodeType: 'Resource',
  dataAttrs: [{
    entityClass: 'example.Partner',
    entityName: '合作伙伴',
    attribute: 'type',
    name: '客户类型',
    remark: '可访问的合作伙伴类型',
    values: [
      { name: 'Customer', label: '客户', permissionExpr: '服务端返回的完整许可表达式' },
    ],
  }],
  children: [/* 既有操作权限 */],
}
```

`values` 是当前操作者可授予的具体枚举许可。后端仍负责校验转授权限、操作前置条件和完整角色分支，前端勾选不能替代这些检查。

## 分配与保存

1. 在资源节点点击“数据范围”，按字段选择枚举值。字段说明通过悬停展示。
2. 同一字段的多个值表示任选其一，不同字段在同一角色内同时约束记录。跨角色按完整条件分支合并，不能将各字段分别合并后扩大范围。
3. 未勾选表示没有该字段的许可。“全选”只保存当前返回的全部具体枚举许可，不生成通配表达式，后续新增枚举不会被自动授予。
4. 选择范围不会隐式授予查询、修改或删除操作。各操作共享资源下这份范围；残留范围本身不能构成可执行权限。
5. 所选完整 `permissionExpr` 与既有操作、属性组许可一起保存到 `permissionList`。其它存量许可保持原样。
6. 取消完整资源或其父级的授权时，同时清理该资源枚举许可；取消部分操作时保留共享范围。单选许可选择器不展示范围编辑入口。

## 最小验证

无 `dataAttrs` 的资源不应出现入口；多字段应独立回显；全选后保存并重新打开应恢复具体枚举值。重复资源投影中的相同许可应同步回显。取消资源后，操作及枚举范围应一起移除，其它资源许可不变。

前端组件测试覆盖这些交互。数据库过滤、分页总数、更新新值和删除检查由后端负责，需单独进行实际 API 与数据库验证；页面隐藏或勾选状态不能证明后端已经执行数据范围限制。
