# 请求错误提示接入

公共请求客户端优先提示服务端返回的 `msg`、`message` 或 `error`；没有可展示提示时显示“发生服务器异常”。`detailMsg` 可能包含内部堆栈，不用于弹窗。输入校验提示仍由页面自行处理。

页面捕获请求失败且需要保证用户收到提示时，使用公开 API，并传入原始异常：

```ts
import { notifyApiErrorOnce } from '@levin/admin-framework/framework-commons/app/api';

try {
  await saveData();
} catch (error) {
  notifyApiErrorOnce(error);
}
```

公共请求层已经提示该异常时，方法不会再弹出；否则使用服务端提示或统一兜底。响应体为空或不是对象时，请求客户端保留原始请求异常，以便同样识别已提示状态。不要重新包装异常后再调用，否则无法识别原请求是否已提示。显式静默请求由调用方自行决定是否提示；取消操作及本地校验应按各自交互语义处理。

特殊业务需要覆盖后端文案时，在该次接口调用的配置中显式声明；空白文案会回退到后端提示：

```ts
await requestClient.post('/example/save', payload, {
  errorMessageOverride: '当前操作暂不可用，请联系管理员',
});
```

覆盖仅对该次请求生效，并沿用统一去重；其他调用不受影响。此配置适用于使用框架公共请求客户端的接口，独立 `fetch` 或其他请求客户端需要自行接入。

验证时分别模拟服务端返回错误提示和返回空响应，检查前者只展示服务端提示一次，后者只展示“发生服务器异常”一次，并确认表单校验提示仍然可见。
