# 前端组件版本

超级管理员在用户菜单中打开“前端组件版本”，可查看当前页面引用的框架、已启用的基础业务包及框架直接内部公共依赖的包名、版本和打包时间。子项目应用版本、子项目自有模块版本和版本匹配判断不在列表中。

## 数据来源

每个支持此能力的发布包自带 `package-version.mjs`，通过公开的 `./package-version` 入口导出 `packageVersion`（`name`、`version`、`buildTime`）。这些值由本仓库构建与打包流程从当前包自动生成；不手工填写，也不读取私服最新版本。`buildTime` 是包在发布方打包时记录的 ISO 时间，页面按本地时区显示。

框架导入各实际引用包的普通 JavaScript 版本模块。消费方只需正常导入发布包，无须安装版本插件、添加 JSON 元数据处理或注入 Vite 常量。子项目重新构建不会改变已安装包的版本或打包时间。

列表说明的是当前页面构建中框架这条解析链引用的直接内部包；不是服务器 node_modules 的实时扫描，也不是所有传递依赖或其它依赖树重复版本的清单。类型构件也可以在列表中出现，但不表示该包具有运行时代码。

## 本仓库维护

`scripts/sync-framework-package-metadata.mjs` 根据框架依赖声明生成导入清单并初始化缺失的包版本模块。各包的 build/prepack 使用 `--package .` 只更新当前包的版本与打包时间；`--check` 检查生成文件、版本、时间与公开入口。修改包版本后应执行对应包构建，不能用旧版本模块打包。

每个包的 `files` 必须包含版本模块和声明文件，源码 `exports` 和 `publishConfig.exports` 必须同时保留公开入口。首次发布该能力时，需要同步发布提供入口的公共依赖，并按照内部消费者依赖顺序递增版本；旧公共依赖版本没有该入口，不能直接搭配新版框架。本次源代码变更尚不表示这些包已经上传私服。
