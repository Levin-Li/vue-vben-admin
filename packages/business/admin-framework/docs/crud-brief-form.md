# 标准 CRUD 简要表单接入指南

简要表单用于页面开发者明确挑选简单、重要的字段。它与运行时自动提取必填字段的“快捷填写”不同；未声明 `briefFields` 的页面不提供简要视图。组织与用户页面是首个接入实例。

## 首次模式与切换

新增、编辑分别通过界面展示设置选择首次模式：默认 `auto`、简要 `brief`、向导 `wizard`、快捷 `quick` 或普通 `normal`。未指定为默认；默认优先使用有效简要表单；新增其次使用有可填写必填字段的快捷表单，再次是至少三个有效分组的向导，最后使用普通表单。编辑不会自动进入快捷模式，但也展示相同的快捷填写选项；无可填写必填字段时该选项禁用并说明原因。明确选择向导而有效分组不足三个时，回退普通表单并提示。

旧 `quickFill: true` 表示快捷、`false` 保留关闭快捷的选择，缺失表示默认；新 `initialMode` 优先。旧设置关闭快捷且页面存在有效简要字段时，保留原有简要默认行为。首次模式仅决定打开时的视图，手动切换不改写设置。

快捷填写自动集中全部当前有效、可展示且可填写的必填字段；至少一个即可使用，复杂字段保留完整控件。简要表单只在开发者声明的重点字段仍有效时提供，并补入有效必填字段。两种精简视图中的“更多”返回进入前的完整普通或向导布局，保留值、分组、提交选择与向导步骤。

## 配置入口

在页面的 `CrudPageConfig.briefFields.create` 和 `.edit` 分别填写当前表单的字段 `key`。运行时在接口权限、页面展示设置及当前场景过滤后，按原字段顺序显示这些重点字段，并补入可见必填字段。若页面有不可缺少的重点字段，可用 `briefRequiredFields` 声明；任一字段不可用时回退完整表单。字段可用性由既有后端字段权限和 UI 设置决定，不允许借简要模式恢复已排除的字段。

字段可用 `briefLabel` 覆盖简要视图标题，`briefRequired` 仅添加简要视图必填提示，不会把完整表单的可选字段改为全局必填。进入/退出简要视图的临时输入映射可通过 `briefOnEnter`、`briefOnExit` 处理；退出回调抛错时保持当前视图并显示错误。页面只有有权调用真实 API 时才应展示相应业务输入，不能把页面配置当作权限。

## 提交与独立后续操作

页面确需把简要输入映射成其它 API 字段时使用 `finalizeBriefSubmit(payload, formState, editingRecord, canSubmitField)`。该回调在排除不提交字段后运行，必须先用 `canSubmitField` 核对每个目标字段；服务端字段策略和业务校验仍会再次执行。若主记录保存后还要调用独立 API，可用 `afterSave` 回调。返回非空文字表示部分成功，公共表单会关闭并刷新列表，同时显示警告；回调异常也按部分成功处理，不能重试主记录创建。调用者应提供针对已创建记录的恢复入口。

“更多”从简要返回同一弹窗的完整表单并保留表单状态；标题旁的“简要表单”可重新切入。向导每步校验当前参与提交的字段，最终保存仍校验全部提交字段。

## 最小验证

运行 `crud-brief-fill.test.ts`、`crud-quick-fill.test.ts`、`crud-form-wizard.test.ts` 和表单交互测试；打开新增、编辑弹窗，检查模式选择、已有输入保留及最终请求字段。新页面接入时还应验证无权主体和 UI 设置排除字段不会通过映射进入请求。当前实现和真实浏览器验收状态以对应 OpenSpec 任务为准。
