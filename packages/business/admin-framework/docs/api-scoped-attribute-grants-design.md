# 接口级数据授权前端设计

角色资源权限分配沿用已有模块、资源和操作树。每个操作行展示该操作可分配的信息组、受控枚举字段及受控字典字段；没有候选的操作不增加入口。服务端仍是唯一授权事实源，前端不扫描 Java 注解、不根据页面标题或路由拼接权限候选。

同一操作的多个组、字段及允许值序列化为一条 `@` 复合权限；普通四段操作、角色码、旧 `:@value:` 和其它旧权限保持原值。实体存在信息权限候选时，在实体名称同行显示可点击的信息权限入口及绿色数量角标；已有通配授权按原规则编辑，否则只修改已选接口，不能隐式授予其他操作。不同接口的已有许可按并集展示，只有部分接口具备的选项显示半选，未操作时不改原配置。鼠标预览以“信息组：”标明信息组，并逐组列出组成员字段；已选枚举／字典值继续单独展示。前端必须按组来源标识和字段来源键消歧，不能以同名文本合并不同实体的组。

页面只负责候选展示、勾选、回显及格式校验。操作许可、来源身份、字典 code、机密等级、数据范围和角色转授最终由后端重新检查；保存失败须保留当前选择供修正。
