# 公共 CRUD 复杂对象分组使用指南

在页面的 `CrudPageConfig` 中声明 `complexGroups`，并给对应的扁平表单字段配置 `complexGroupKey`。例如，`key: 'legal'` 的对象组通过 `fieldMappings` 将前端 `legalName` 映射到请求对象 `legalInfo.name`。字段原有的 `layoutGroup` 只用于普通业务分组；新增、编辑表单中的对象归属以 `complexGroupKey` 为准。

打开页面的“展示设置 2”，在新增、编辑和详情表单页签中可看到独立的对象分组。对象内字段可调整标题、顺序和显示状态，但“所属分组”固定为该对象；普通字段不能移入对象组。对象组可设置标题、组间顺序、可见条件和初始展开状态。上传设置后，真实表单按同一组配置显示；未上传的草稿不影响运行页面。详情只读展示会根据 `fieldMappings` 展开已声明的嵌套响应对象。

复杂对象仍按页面已有的字段映射生成请求数据。对象组的标题或顺序不会成为请求字段。第一层对象取消勾选时不提交该对象；更深层对象的清除行为须由实际请求契约支持。折叠仅影响显示；字段权限、可见性和校验仍以原有表单规则为准。用户取消勾选时需确认，取消确认保留原状态。

多层对象应给每个对象组配置唯一 `key`，子组通过 `parentKey` 指向父组，并把 `submitKey` 写成从请求根部开始的完整属性路径，例如 `nestedObject.levelTwo.levelThree`。每组的 `fieldMappings` 只写相对于该对象的字段名；一个表单字段只能归属一个对象组。公共 CRUD 按路径合并请求对象、回显各层字段并展开详情；第一层未勾选时省略整支，后续任一层未勾选时将该子对象置为 `null`，不会继续构造其后代。祖先未勾选的字段也不参与必填校验。

最小验证：在“展示设置 2”的新增表单中确认对象字段归属，调整一个对象组标题并上传，重新打开新增表单确认标题一致；再核对对象字段提交映射没有变化。
