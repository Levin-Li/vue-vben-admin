# 前端聚合包使用与迁移指南

## 构件与源码归属

公开构件为 `@vben-core/foundation`、`@vben-core/ui`、`@vben/runtime`、`@vben/common-ui`、`@vben/layouts`、`@levin/admin-framework`、`@levin/oak-base-admin`。三个聚合包的 `src/vendor` 目录直接维护原模块源码；该目录名不表示生成产物。构建不再从旧目录复制源码。

## 下游升级

先取得完整验证后的统一发布版本，再一次性更新所有内部依赖。删除被合并旧包的依赖声明，增加对应聚合包；保留所需的 Vue、路由、Pinia 和组件库 peer 依赖。按上表修改源码、测试 mock、TypeScript `types` 和样式导入，刷新锁文件后执行生产构建。旧包名不提供兼容包装。

普通业务扩展仍优先使用 `@levin/admin-framework` 已公开的扩展接口；包合并不改变权限、租户隔离、数据范围和请求服务边界。构建成功不替代实际权限和页面回归。

## 页面标签缓存

框架可调用 `useTabbarStore().setPageKeepAlive(tabKey, keepAlive, routeDefault)`，在页面设置加载后覆盖当前标签的缓存资格。`tabKey` 由公开的 `getTabKey(route)` 取得；`keepAlive` 为 `true` 或 `false` 时显式覆盖，为 `undefined` 时恢复叶子路由的 `routeDefault`。该动作重算缓存名单，并在同一标签重新加入路由时保留显式覆盖。业务应用优先通过 `@levin/admin-framework` 的“展示设置2”使用此能力；全局标签缓存关闭时仍会重新挂载。

## 验证命令与失败语义

在前端仓库根目录执行 `pnpm build` 检查整个工作区；执行 `pnpm run check:consolidated-package-imports` 检查旧包引用。构建完成后执行 `node scripts/verify-consolidated-consumer.mjs`，打包七个构件并在工作区外安装、构建消费者。它不上传 npm，也不部署应用；失败以非零退出码报告，临时目录保留锁文件和验证证据。

发布前仍须遵循 发布方源码仓库的统一发布流程。尚未完成独立消费者验证的构件不能被宣布为可升级版本。
